# 无人机智能控制系统使用手册

> 文档版本：1.0  
> 更新日期：2026-07-14  
> 默认方案：PX4 SITL + AirSim + ROS 2 Humble + DeepSeek + YOLO + Web 地面站  
> 默认关闭：百炼、Qwen VLM、自动视觉大模型分析  
> 面向对象：演示人员、测试人员、项目组成员和系统操作员

## 1. 这份手册解决什么问题

本手册只关注如何使用系统，包括：

- 从零启动完整项目。
- 判断每个模块是否启动成功。
- 使用独立 Web 地面站。
- 与 DeepSeek 进行流式多轮对话。
- 通过自然语言查询状态和下达任务。
- 使用按钮或对话完成高风险操作确认。
- 查看 RGB、深度点云、YOLO 检测和任务报告。
- 使用 ROS 2 命令进行独立测试。
- 在出现故障时快速定位问题。
- 按安全顺序停止系统。

系统原理、模块设计和接口细节请查看：

## 2. 使用前必须理解的三条链路

### 2.1 飞控链路

```text
PX4 SITL
  -> uXRCE-DDS UDP 8888
Micro XRCE-DDS Agent
  -> ROS 2 DDS
Control / Bridge / Agent
```

PX4 和 DDS Agent 没有连通时，ROS 2 无法获得真实飞行状态，也无法控制飞行器。

### 2.2 传感器链路

```text
Windows AirSim
  -> AirSim RPC
WSL 中的 Bridge
  -> ROS Image / Depth / PointCloud2
Web 8080
  -> 浏览器 5173
```

AirSim 没有启动或 IP 配置错误时，飞控状态可能存在，但相机和点云没有画面。

### 2.3 智能对话链路

```text
浏览器 5173
  -> Agent WebSocket 8090
DeepSeek 流式 API
  -> MCP / Skills / Confirmation Center
ROS Agent
  -> Control / Autonomy / Perception
```

`8090` 不可用时，流式对话、模型切换、会话记忆和 Gateway 确认不可用。界面会尝试回退到 `8080` 的 Legacy ROS Agent。

## 3. 启动前检查

### 3.1 目录检查

默认目录：

```text
/home/waves/aeromind_ws
/home/waves/PX4-Autopilot
```

检查：

```bash
test -d ~/aeromind_ws && echo "ROS 工作空间存在"
test -d ~/PX4-Autopilot && echo "PX4 工程存在"
test -f ~/aeromind_ws/yolov8n.pt && echo "YOLO 模型存在"
```

### 3.2 ROS 环境检查

```bash
source /opt/ros/humble/setup.bash
cd ~/aeromind_ws
source install/setup.bash

ros2 pkg prefix aeromind_bringup
ros2 pkg prefix aeromind_agent_gateway
```

两个命令都应输出安装路径。如果提示 `Package not found`，先执行第 4 节的编译命令。

### 3.3 网络检查

WSL 获取 Windows 宿主机地址：

```bash
ip route | awk '/default/ {print $3}'
```

常见结果类似：

```text
192.168.16.1
```

这个地址可作为 `airsim_ip`。

### 3.4 密钥检查

项目使用环境变量读取密钥。推荐把密钥保存在用户私有配置目录，不要每次启动时重新输入。

创建配置目录：

```bash
mkdir -p ~/.config/drone-console
chmod 700 ~/.config/drone-console
```

编辑配置文件：

```bash
nano ~/.config/drone-console/secrets.env
```

只使用 DeepSeek 时写入：

```bash
export DEEPSEEK_API_KEY="你的 DeepSeek API Key"
```

同时使用千问 VLM 时写入完整配置：

```bash
# DeepSeek 文本模型
export DEEPSEEK_API_KEY="你的 DeepSeek API Key"

# 阿里云百炼/千问
export DASHSCOPE_API_KEY="你的百炼 API Key"

# 项目内部 VLM 变量复用同一把百炼 Key
export AEROMIND_VLM_API_KEY="$DASHSCOPE_API_KEY"
export AEROMIND_VLM_API_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
export AEROMIND_VLM_MODEL="qwen3-vl-plus"
```

`AEROMIND_VLM_API_KEY` 不是第二把密钥。它是项目内部使用的变量名，值来自同一个 `DASHSCOPE_API_KEY`。

限制文件权限：

```bash
chmod 600 ~/.config/drone-console/secrets.env
```

在 `~/.bashrc` 中添加一次自动加载：

```bash
[ -f ~/.config/drone-console/secrets.env ] && \
  source ~/.config/drone-console/secrets.env
```

当前终端立即加载：

```bash
source ~/.bashrc
```

安全检查，只判断变量是否存在，不输出密钥：

```bash
test -n "$DEEPSEEK_API_KEY" && echo "DeepSeek Key 已加载"
test -n "$DASHSCOPE_API_KEY" && echo "百炼 Key 已加载"
test -n "$AEROMIND_VLM_API_KEY" && echo "VLM Key 已加载"
```

不要把真实密钥写入 README、ROS launch、前端代码、浏览器 `localStorage` 或 Git 仓库。

## 5. 完整启动顺序

推荐准备 5 个 WSL 终端和 1 个 Windows AirSim 窗口。

```text
终端 1：Micro XRCE-DDS Agent
终端 2：PX4 SITL
Windows：AirSim 场景
终端 3：ROS 主系统
终端 4：Web ROS 网关 + Agent Gateway
终端 5：独立前端
终端 6：RViz，可选
```

DDS Agent 和 PX4 前后顺序可以互换。推荐先启动 DDS Agent，便于观察 PX4 建立连接。

### 5.1 终端 1：启动 DDS Agent

```bash
micro-xrce-dds-agent udp4 -p 8888
```

如果命令不存在：

```bash
MicroXRCEAgent udp4 -p 8888
```

正常情况下，PX4 启动后会出现客户端建立连接的信息。

### 5.2 终端 2：启动 PX4 AirSim 模式

```bash
cd ~/PX4-Autopilot
make px4_sitl_default none_iris
```

该终端同时是 PX4 Shell，可输入：

```text
commander status
listener vehicle_status
listener vehicle_local_position
```

### 5.3 Windows：启动 AirSim

1. 确认 Windows AirSim 的 `settings.json` 已配置 PX4 和传感器。
2. 启动 AirSim 场景。
3. 等待场景和无人机模型加载完成。
4. 不要在运行过程中重复启动第二个相同 AirSim 实例。

配置示例见 [AirSim 配置示例](AirSim配置示例.json)。

### 5.4 终端 3：启动 ROS 主系统

当前推荐配置为 DeepSeek + YOLO，关闭百炼和 VLM：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

test -n "$DEEPSEEK_API_KEY" && echo "DeepSeek Key 已加载"

ros2 launch aeromind_bringup aeromind_px4.launch.py \
  llm_enabled:=true \
  llm_api_url:=https://api.deepseek.com/v1 \
  llm_model:=deepseek-chat \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  yolo_confidence:=0.35 \
  vlm_enabled:=false \
  auto_analyze_enabled:=false
```

如果自动检测不到 AirSim IP：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  airsim_ip:=192.168.16.1 \
  llm_enabled:=true \
  llm_api_url:=https://api.deepseek.com/v1 \
  llm_model:=deepseek-chat \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  yolo_confidence:=0.35 \
  vlm_enabled:=false \
  auto_analyze_enabled:=false
```

将 `192.168.16.1` 替换为第 3.3 节获得的 Windows 地址。

主系统包括：

- AirSim/PX4 Bridge。
- Perception。
- YOLO detection。
- Planning。
- Autonomy。
- Control。
- Legacy ROS Agent。

#### 5.4.1 可选：开启千问 VLM 按需分析

先按照第 3.4 节持久化 `DASHSCOPE_API_KEY` 和 `AEROMIND_VLM_API_KEY`。

推荐先启用 VLM 服务，但关闭自动定时调用：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  llm_enabled:=true \
  llm_api_url:=https://api.deepseek.com/v1 \
  llm_model:=deepseek-chat \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  yolo_confidence:=0.35 \
  vlm_enabled:=true \
  vlm_api_url:=https://dashscope.aliyuncs.com/compatible-mode/v1 \
  vlm_model:=qwen3-vl-plus \
  auto_analyze_enabled:=false \
  auto_analyze_use_vlm:=false
```

此模式下 YOLO 持续检测，千问 VLM 只在用户主动请求时调用，能减少 API 消耗和费用。

需要自动低频分析时改为：

```bash
auto_analyze_enabled:=true \
auto_analyze_interval_sec:=10.0 \
auto_analyze_use_vlm:=true
```

建议自动分析间隔设置为 `10` 到 `30` 秒。VLM 不适合代替高频 YOLO、深度避障或 PX4 控制。

### 5.5 终端 4：启动 Web 与流式 Agent

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

test -n "$DEEPSEEK_API_KEY" && echo "DeepSeek Key 已加载"

ros2 launch aeromind_bringup aeromind_web.launch.py \
  host:=0.0.0.0 \
  port:=8080 \
  agent_port:=8090 \
  agent_provider:=deepseek \
  agent_model:=deepseek-chat
```

两个后端端口：

| 端口 | 服务 | 用途 |
|---|---|---|
| `8080` | ROS Web Gateway | 遥测、相机、点云、报告、ROS 控制 API |
| `8090` | Agent Gateway | 流式对话、模型、记忆、MCP、确认、Workflow |

### 5.6 终端 5：启动独立前端

```bash
cd ~/aeromind_ws/web/ground_station
python3 -m http.server 5173
```

浏览器打开：

```text
http://localhost:5173
```

如果刚更新过前端，按 `Ctrl+F5` 强制刷新。

### 5.7 终端 6：启动 RViz，可选

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch aeromind_bringup aeromind_vision.launch.py
```

RViz 用于检查原始 RGB、DepthCloud、LiDAR、TF 和自主地图。Web 点云适合控制台展示，RViz 更适合工程调试。

## 7. Web 界面怎么使用

### 7.1 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部状态：ROS、Agent、飞行模式、EKF、服务状态、网关地址      │
├──────────────┬─────────────────────────┬─────────────────────┤
│ 飞行状态/技能 │ 主对话区                │ 任务态势/解析/输出   │
│ 手动控制      │ 流式回复                │ 确认/执行步骤/日志   │
├──────────────┴─────────────────────────┴─────────────────────┤
│ RGB 相机、深度点云、检测结果、报告和截图                     │
└──────────────────────────────────────────────────────────────┘
```

### 7.2 顶部状态栏

重点观察：

| 状态 | 正常表现 | 异常含义 |
|---|---|---|
| ROS 网关 | 已连接 | `8080` 不可达或 Web 节点未启动 |
| Agent | `DEEPSEEK AGENT` | `8090` 不可达或密钥配置错误 |
| Armed | 已解锁/未解锁 | 反映真实飞控状态 |
| Mode | OFFBOARD、AUTO_LOITER 等 | 当前 PX4 模式 |
| EKF | Healthy | 定位估计是否可用 |
| Services | Ready | 控制和感知服务是否就绪 |

### 7.3 ROS 网关地址

本机使用：

```text
http://localhost:8080
```

如果 ROS 网关运行在另一台机器：

```text
http://<ROS_GATEWAY_IP>:8080
```

保存后，前端会自动尝试连接同一主机的 `8090` Agent Gateway。

### 7.4 主对话区

主对话区支持：

- DeepSeek 流式输出。
- 多轮上下文。
- 会话历史恢复。
- 模型与 Provider 信息。
- MCP 工具调用提示。
- 控制任务确认。
- Workflow 执行状态。

正常流式回复时，文字会逐段出现，而不是等待全部完成后一次性显示。

### 7.5 右侧任务区域

右侧区域可滚动，包含：

- 任务态势：当前阶段和执行结果。
- 解析结果：意图、技能、风险和确认状态。
- 执行确认：高风险任务的确认按钮。
- 结构化输出：模型、技能和工具的原始结果。
- 计划步骤：任务拆解过程。
- 工具调用：MCP 和 ROS 调用结果。

部分面板可以拖动底部调整高度。

## 8. 自然语言任务怎么下达

### 8.1 只读任务

只读任务不会改变无人机状态，通常不需要确认。

推荐示例：

```text
检查当前无人机状态
检查前方是否有障碍物
检测画面中是否有人
生成当前任务报告
当前高度和飞行模式是什么
最近一次任务为什么失败
```

### 8.2 控制任务

控制任务会创建结构化确认请求，不会由模型直接执行。

示例：

```text
解锁无人机
起飞到10米
向前飞10米
向左飞20米
悬停
降落
返航
```

### 8.3 复杂任务

示例：

```text
检查状态，如果安全就起飞到10米
起飞到10米，然后向前飞20米，最后悬停
起飞后向左飞20米并检测画面中是否有人
飞一个边长10米的正方形轨迹，完成后降落
飞一个宽10米、深8米的V字形，并在顶点拍照
巡检前方区域，发现人就悬停拍照，否则继续前进20米
```

复杂任务应被拆成 Workflow，并经过一次整体确认。每个步骤仍由白名单动作和确定性模块执行。

当前模块化技能：

- `flight.square`：正方形闭合轨迹。
- `flight.v_shape`：两个相对向量航段组成的 V 字轨迹，可在顶点拍照。
- `inspection.person_branch`：检测到人员时悬停拍照，明确未检测到时继续前进，感知数据不可用时保持悬停。
- `inspection.line_capture`：沿直线航线在起点、终点拍照，可选择原路返回和降落。
- `mission.safe_takeoff_capture`：完成确定性安全检查后起飞并拍照。

Workflow 还支持 `capture_image` Action，以及根据前置步骤成功/失败、检测到/未检测到目标进行条件分支。技能说明位于 Gateway 的 `skill_docs/*/SKILL.md`，同目录 `skill.yaml` 定义参数和步骤，启动时由 Gateway 自动加载并经过动作白名单校验。

Web 左侧分为两组：基础能力来自 `/api/capabilities`，表示真实 ROS 接口；组合技能来自 `/api/skills`，表示可复用 Workflow。Gateway 确认后通过 `/agent/execute_action` 发送结构化动作，不会再把动作翻译成中文交给规则解析器。

### 8.4 推荐表达方式

为了减少歧义，建议明确：

- 动作：起飞、移动、悬停、降落、返航。
- 方向：前、后、左、右、上、下。
- 距离或高度：使用米。
- 条件：如果安全、如果已起飞、如果检测到目标。
- 结束状态：悬停、降落或返航。

例如：

```text
检查飞控和避障状态，如果安全，起飞到8米；到达后向前飞10米并悬停。
```

## 9. 人工确认怎么使用

### 9.1 为什么需要确认

解锁、起飞、移动、悬停、降落、RTL 和组合飞行属于控制动作。模型只能创建请求，Confirmation Center 校验后等待操作员授权。

```text
用户任务
  -> 模型选择 request_* 工具
  -> Gateway 创建 confirmation
  -> 用户确认
  -> ROS Agent 执行
  -> 飞控遥测验证物理完成
```

### 9.2 使用按钮确认

待确认任务会同时出现在：

- 主对话区底部。
- 右侧“执行确认”区域。

点击“确认执行”后才会调用 ROS 控制链路。点击“取消”不会改变飞行状态。

### 9.3 使用对话确认

只有一个待确认请求时，可以直接输入：

```text
确认
确认执行
同意执行
批准执行
```

取消：

```text
取消
取消执行
拒绝执行
```

这些短命令由 Gateway 在进入模型前拦截，不依赖 DeepSeek 是否愿意执行。

### 9.4 多个待确认请求

存在多个待确认请求时，必须指定 ID：

```text
确认 confirm-xxxxxxxxxxxxxxxx
取消 confirm-xxxxxxxxxxxxxxxx
```

这样可以防止确认错任务。

### 9.5 确认过期

确认请求默认约 60 秒过期。过期后不会执行，需要重新发送原任务。

如果模型回复中出现确认 ID，但界面没有确认区域：

1. 确认页面显示 Agent 已连接。
2. 按 `Ctrl+F5` 刷新。
3. 检查 `curl http://localhost:8090/health`。
4. 重启 `aeromind_web.launch.py`。
5. 重新发送任务，旧请求可能已经过期。

## 10. 飞行任务的执行状态

确认以后不代表任务立即完成。界面会经历：

```text
等待确认
  -> 已确认
  -> ROS 服务受理
  -> 飞控执行
  -> 等待遥测验证
  -> completed 或 failed
```

### 10.1 起飞完成条件

系统结合飞控状态和里程计高度判断是否达到目标高度。服务返回成功只是“请求已受理”，不是物理完成。

### 10.2 移动完成条件

Autonomy 接收目标并生成 `/autonomy/trajectory`，Control 执行轨迹，最终由 `/autonomy/status` 的目标到达状态确认。

### 10.3 降落完成条件

无人机接近地面并加锁后，任务才应显示完成。

### 10.4 RTL 完成条件

项目使用 PX4 原生 RTL。返航、降落并加锁后才视为完成。

## 11. 手动控制说明

手动控制区用于短时联调，不适合代替自主任务规划。

常见动作：

- 前进、后退。
- 左移、右移。
- 上升、下降。
- 左转、右转。
- 悬停。

注意：

- 手动按钮发布速度命令，不是目标位置。
- 页面中的起飞高度单位为米。
- 当前坐标和方向受 ROS ENU、PX4 NED、机体系和 AirSim 相机方向影响。
- 第一次测试应低速、低高度、空旷环境。
- 自主轨迹执行期间不要连续发送相反的手动速度命令。

## 12. 相机、点云和目标检测

### 12.1 RGB 相机

RGB 区域显示 `/sensor/camera/rgb/front_center`。

功能：

- 实时画面。
- 点击或放大按钮进入大图。
- 放大、缩小和适配窗口。
- 颜色模式切换。

检查数据：

```bash
ros2 topic hz /sensor/camera/rgb/front_center
ros2 topic echo /sensor/camera/rgb/front_center --once
```

### 12.2 深度点云

Web 使用 Three.js 显示由深度图生成的 3D 点云，支持：

- 鼠标旋转视角。
- 滚轮缩放。
- 重置视角。
- 点大小调节。
- 轴向、高度和距离着色。

点云方向异常时，先用 RViz 对照 TF：

```bash
ros2 run tf2_ros tf2_echo odom camera_front_center_optical
ros2 topic echo /tf_static --once
```

### 12.3 YOLO 检测

当前目标识别默认使用 YOLO，不使用 VLM。

检查 detection：

```bash
ros2 topic hz /perception/detections
ros2 topic echo /perception/detections --once
```

推荐任务：

```text
检测画面中是否有人
检测person
检查前方是否有人
```

YOLO 类别通常使用英文标签，例如 `person`、`car`。Agent 会进行部分中英文别名匹配。

### 12.4 千问 VLM 图像分析

VLM 开启后，可以通过对话请求：

```text
使用视觉模型分析当前相机画面
描述画面中的目标、环境和潜在风险
结合当前画面判断是否适合继续前进
```

也可以直接调用 ROS 服务：

```bash
ros2 service call /perception/analyze_image \
  aeromind_interfaces/srv/AnalyzeImage \
  "{prompt: '描述当前画面中的目标、环境和潜在风险', use_vlm: true}"
```

职责区别：

| 模块 | 主要用途 | 调用频率 |
|---|---|---|
| YOLO | 人、车等固定类别实时检测和检测框 | 高频 |
| 千问 VLM | 场景描述、目标关系、语义风险和自然语言问答 | 按需或低频 |
| Depth/LiDAR | 几何距离和障碍物感知 | 高频 |

千问 VLM 的文字判断不能单独作为起飞或避障的安全依据。

### 12.5 保存图片

通过对话：

```text
保存当前相机图片
```

通过 ROS：

```bash
ros2 service call /perception/capture_image \
  aeromind_interfaces/srv/CaptureImage \
  "{label: front_rgb}"
```

图片通常归档到：

```text
missions/<mission_id>/captures/
```

没有 Mission 上下文时可能保存到公共 captures 目录。

## 16. 常见故障排查

### 16.1 Package not found

现象：

```text
Package 'aeromind_bringup' not found
```

处理：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

仍然失败则重新编译。

### 16.2 PX4 状态没有数据

检查：

```bash
ros2 topic hz /fmu/out/vehicle_status
```

没有数据时：

1. 检查 PX4 是否运行。
2. 检查 DDS Agent 是否监听 UDP 8888。
3. 检查 DDS Agent 是否显示 client connected。
4. 重新启动 DDS Agent 和 PX4。

### 16.3 相机没有画面

```bash
ros2 topic hz /sensor/camera/rgb/front_center
```

无频率：

- 检查 AirSim 是否启动。
- 检查 Bridge 是否崩溃。
- 检查 `airsim_ip`。
- 检查 Windows 防火墙。

有频率但 Web 空白：

- 检查 `curl http://localhost:8080/api/camera`。
- 按 `Ctrl+F5`。
- 查看浏览器 Console。

### 16.4 流式对话不可用

检查：

```bash
curl http://localhost:8090/health
```

确认：

- `DEEPSEEK_API_KEY` 已在启动 Gateway 的同一终端导出。
- `agent_provider:=deepseek`。
- `agent_model:=deepseek-chat`。
- 浏览器能连接 `ws://localhost:8090/ws/agent`。

### 16.5 没有确认按钮

1. 查看 Agent 是否已连接。
2. 查看右侧区域是否向下滚动。
3. 查看主对话区底部是否出现确认条。
4. 发送 `确认执行`。
5. 按 `Ctrl+F5` 更新前端。
6. 重启 Gateway 后重新发起任务。

### 16.6 输入确认后模型说无法确认

新版 Gateway 会在模型前拦截明确确认短语。如果仍发生：

- 当前 Gateway 进程仍是旧版本。
- 没有重新 `source install/setup.bash`。
- 浏览器连接的不是预期 `8090`。

重新编译并重启：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon build --symlink-install --packages-select aeromind_agent_gateway aeromind_web
source install/setup.bash
```

### 16.7 无人机不起飞

检查：

```bash
ros2 topic echo /control/drone_state
ros2 topic echo /sensor/odometry --once
ros2 topic echo /agent/mission_status
```

重点观察：

- 是否已经确认任务。
- PX4 是否解锁。
- 模式是否进入 OFFBOARD 或起飞模式。
- EKF 是否健康。
- 里程计是否持续更新。
- 起飞区域是否被感知安全检查拒绝。

### 16.8 Autonomy 显示 SENSOR_WAIT

表示必要传感器或定位数据超时。检查：

```bash
ros2 topic hz /sensor/odometry
ros2 topic hz /sensor/camera/depth/front_center
ros2 topic echo /autonomy/status
```

不要在定位或深度超时时强行执行自主移动。

### 16.9 YOLO 没有结果

```bash
ros2 node list | grep yolo
ros2 topic hz /perception/detections
```

确认模型路径存在、相机有数据，并检查 YOLO 节点日志。

### 16.10 端口被占用

```bash
ss -lntp | grep -E '5173|8080|8090'
```

可更换端口，但前端默认按 ROS 网关主机推导 Agent 的 `8090`，更换 Agent 端口时还需要配置前端 Agent Gateway 地址。

## 17. 安全停止顺序

### 17.1 正常停止

1. 如果正在飞行，先发送“降落”并确认。
2. 等待飞控状态显示落地和加锁。
3. 取消仍在执行的 Autonomy 目标。
4. 停止 Web/Agent Gateway。
5. 停止 ROS 主系统。
6. 停止 AirSim。
7. 停止 PX4。
8. 停止 DDS Agent。

取消自主目标：

```bash
ros2 topic pub --once /autonomy/cancel std_msgs/msg/Empty "{}"
```

### 17.2 紧急情况

仿真中可立即停止 PX4 或 AirSim进程。真机中必须依赖独立 RC 接管、飞控 failsafe 和急停方案，不能把浏览器或大模型当作唯一安全通道。

## 18. 五分钟演示流程

### 第一步：展示状态和感知

输入：

```text
检查当前状态和前方环境
```

讲解：DeepSeek 调用只读工具，读取飞控、里程计、避障和 YOLO 数据。

### 第二步：展示目标检测

输入：

```text
检测画面中是否有人
```

讲解：语义任务由 Agent 转换为检测查询，实际检测结果来自 YOLO。

### 第三步：展示安全确认

输入：

```text
检查状态，如果安全就起飞到10米
```

出现确认后输入：

```text
确认执行
```

讲解：模型不能绕过 Confirmation Center，确认后才调用 ROS 控制链路。

### 第四步：展示自主移动

输入：

```text
向前飞10米并悬停
```

确认后展示 Autonomy 状态、轨迹和点云。

### 第五步：展示报告和降落

输入：

```text
生成当前任务报告
```

然后：

```text
降落
```

确认并等待物理状态验证完成。

## 19. 真机迁移注意事项

真机架构建议：

```text
地面站电脑
  -> 5173 静态前端
  -> 局域网
伴随计算机
  -> ROS 2 + 8080 + 8090
  -> uXRCE-DDS / MAVLink
PX4 真机飞控
```

必须处理：

- 固定 IP 或可靠设备发现。
- TLS 或受保护局域网。
- 强随机 `AEROMIND_AGENT_TOKEN`。
- 防火墙只开放必要端口。
- RC 独立接管。
- 飞控 geofence、RTL 和失联保护。
- VIO/SLAM 和传感器时间同步。
- 实飞前 ROS Bag 回放和仿真回归。

真机不得照搬 SITL 中绕过硬件检查的 PX4 参数。

## 20. 当前能力边界

当前系统适合：

- PX4/AirSim 仿真演示。
- 自然语言任务编排。
- 流式多轮对话。
- 人工确认控制。
- YOLO 目标检测。
- RGB、深度和点云展示。
- 基础自主规划与避障研究。

当前不能等同于：

- 已完成的复杂未知环境真机自主飞行产品。
- 已认证的安全飞控系统。
- 成熟自动驾驶级动态障碍预测系统。
- 已部署完整 VIO/SLAM 和成熟 ESDF 的量产方案。

大模型负责理解、规划、解释和工具编排；实时控制、安全约束和物理闭环仍由 ROS、Autonomy、Control 和 PX4 负责。
