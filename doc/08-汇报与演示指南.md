# 汇报与演示指南

本文用于向老师、团队或甲方介绍项目。目标是展示真实闭环和工程价值，不把研究原型包装成成熟产品。

## 1. 一句话介绍

本项目是一套基于 ROS 2 和 PX4 的智能无人机任务平台，用户可以通过自然语言描述巡检目标，系统由大模型完成高层理解与任务编排，再由确定性的感知、规划和飞控模块安全执行，并在 Web 地面站实时展示证据和结果。

## 2. 建议汇报结构

### 第 1 页：项目背景

- 传统无人机地面站需要操作员理解模式、坐标和接口。
- 复杂任务涉及感知、规划、控制和报告多个系统。
- 项目目标是用自然语言降低任务表达门槛，同时保留飞控安全边界。

### 第 2 页：项目目标

- 统一接入 PX4、AirSim、相机、深度和 LiDAR。
- 支持自然语言任务、条件分支和多步骤执行。
- 提供人工确认、物理完成验证和任务审计。
- 建立仿真到真机可迁移的软件架构。

### 第 3 页：总体架构

使用 [系统总架构图](架构图/01-系统总架构.png)，重点讲四层分工和“大模型不直接控制电机”。

### 第 4 页：ROS 与数据闭环

使用 [ROS 模块与数据流图](架构图/02-ROS模块与数据流.png)，说明 AirSim 传感器链、PX4 DDS 链和 Web HTTP/WebSocket 链。

### 第 5 页：大模型能力

- 多轮自然语言理解和上下文。
- 根据状态选择 Skills 并生成 Workflow。
- 组合飞行、感知、拍照、报告和返航。
- VLM 开放语义图像理解。
- 失败解释、任务恢复建议和证据化报告。

### 第 6 页：安全执行机制

使用 [智能任务执行闭环图](架构图/03-智能任务执行闭环.png)：结构化校验、风险确认、ROS 执行、遥测验证、异常恢复和安全终止。

### 第 7 页：自主飞行

- 滚动局部地图。
- 动力学重规划。
- Minimum Snap 连续轨迹。
- ROS 2 多航点 Action。
- 轨迹碰撞检查和局部重规划拼接。

明确说明当前是研究原型，成熟 VIO/SLAM、ESDF 和真机验收仍在升级计划中。

### 第 8 页：Web 地面站

展示：飞行状态、主对话、确认卡片、RGB、深度、Three.js 点云、任务态势、技能库和报告。

### 第 9 页：当前成果和证据

- 真实 ROS Topic/Service/Action。
- PX4 模式、高度和里程计变化。
- 截图文件与 Mission 报告。
- 自动化测试结果。
- 固定场景任务录像。

### 第 10 页：不足与路线

用三个阶段概括：先完成 VIO/SLAM 和评测，再升级成熟地图/规划，最后做安全监督与真机部署。

## 3. 五分钟演示脚本

### 0:00～0:40 系统状态

1. 展示 PX4、ROS、Web 已连接。
2. 指出解锁、模式、高度、GPS、EKF 和电压。
3. 展示 RGB、深度和点云来自真实 ROS 数据。

### 0:40～1:30 多模态感知

输入：

```text
仅根据当前画面分析可见物体、障碍、可通行区域和不确定信息。
```

展示 VLM 语义结果，同时用深度/点云解释“语义判断”和“几何测距”的分工。

### 1:30～3:20 复杂任务与确认

输入：

```text
检查飞控和前方区域，如果安全就起飞到 10 米，向前巡检，在指定位置拍照并报告。
```

展示：

1. LLM 将任务拆成 Workflow。
2. 界面显示真实确认卡片。
3. 确认后 ROS 执行，不是模型文本模拟。
4. 飞控状态和任务进度持续反馈。

### 3:20～4:20 自主轨迹

展示多航点轨迹、当前位置、目标、规划状态和局部地图。强调连续轨迹、Action 反馈和局部重规划。

### 4:20～5:00 报告与安全结束

展示截图缩略图和任务报告，最后执行降落或 RTL，确认落地并加锁。

## 5. 应该如何表述大模型价值

推荐说法：

- 大模型把开放自然语言转换成受约束的结构化任务。
- 大模型根据实时状态组合飞行、感知和报告能力。
- VLM 提供开放类别和场景级语义理解。
- 模型决策受到能力白名单、确认中心和飞控状态约束。
- 系统通过物理反馈验证任务，而不是把工具返回当成完成。

避免说法：

- “大模型直接控制无人机电机。”
- “已经实现任意未知环境完全自主避障。”
- “只要写一个 Skill Markdown 就能自动获得新能力。”
- “VLM 可以替代深度、LiDAR 或飞控安全检查。”
- “单元测试通过就代表真机可以安全飞行。”

## 6. 面向甲方的价值

| 价值 | 体现方式 |
|---|---|
| 降低操作门槛 | 用任务语言代替大量底层命令 |
| 提升任务复用 | Skills 和 Workflow 参数化组合 |
| 增强可解释性 | 对话、工具调用、证据、任务步骤和报告 |
| 保留安全边界 | 确认、白名单、状态验证和 PX4 failsafe |
| 支持模块扩展 | ROS 2 接口和插件式 Skill |
| 支持仿真到真机迁移 | Web/Agent、ROS 能力和飞控分层部署 |

## 7. 建议验收指标

- 自然语言意图和参数解析准确率。
- 确认请求生成、过期、取消和幂等正确率。
- 任务成功率与平均完成时间。
- 轨迹跟踪误差和最小障碍距离。
- 传感器超时后的安全响应时间。
- 截图、日志和报告完整率。
- Web 断线重连后的状态恢复一致性。
