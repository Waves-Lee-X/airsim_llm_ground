# 语义世界模型

本模块把 YOLO 的二维检测、深度图、相机内参和 ROS TF 融合为结构化三维对象，为 Agent、态势地图和后续动态避障提供统一的环境事实。

本文说明已实现功能；后续完整工作包和验收计划见 [语义世界模型升级计划](12-语义世界模型升级计划.md)。

当前数据链：

```text
/perception/detections + Depth + CameraInfo + TF
                    ↓ 时间差门控与三维投影
       /world_model/observations
                    ↓ 恒速三维卡尔曼滤波与生命周期
          /world_model/objects
                    ↓
       Agent Gateway / Web / 后续场景图
```

## 1. 当前实现

`semantic_fusion_node` 负责生成当前三维观测，订阅：

- `/perception/detections`：YOLO 类别、置信度和二维检测框。
- `/sensor/camera/rgb/front_center`：提供原始图像尺寸。
- `/sensor/camera/depth/front_center`：在检测框中心区域计算中值深度。
- `/sensor/camera/depth/front_center/camera_info`：将像素反投影到相机坐标系。
- `/tf`：将相机坐标转换到 `odom` 世界坐标系。

融合节点发布 `/world_model/observations`。`object_tracker_node` 再使用恒速三维卡尔曼滤波和同类别距离关联，向 `/world_model/objects` 发布短时稳定 ID、类别、置信度、三维位置、速度、位置协方差、生命周期、数据年龄和证据来源。

生命周期包含 `tentative`、`confirmed` 和 `lost`，默认连续命中 3 次后确认。Detection 与 Depth 的时间差默认不得超过 150 ms；`/world_model/health` 会发布同步差、Depth/CameraInfo/TF 状态、观测数和稳定 Track 数。

三维对象观测默认以 1 Hz 快照写入 `~/.aeromind/world_model.db`，实时 Track 仍按传感器频率更新。SQLite 使用 WAL 模式，默认保留 24 小时且最多保存 20 万行；数据库初始化失败会关闭历史能力，但实时跟踪仍继续运行。

深度或 TF 不可用时，对象仍可作为二维观测发布，但 `position_valid=false`，不应用于三维距离决策。

## 2. 启动与验证

PX4 主 Launch 默认启动语义融合节点；需要 YOLO 提供对象输入：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  yolo_enabled:=true semantic_world_enabled:=true
```

检查数据：

```bash
ros2 topic hz /world_model/objects
ros2 topic echo /world_model/objects --once
ros2 topic echo /world_model/health
ros2 run tf2_ros tf2_echo odom camera_front_center_optical
```

查询当前确认的人：

```bash
ros2 service call /world_model/query aeromind_interfaces/srv/QueryWorldModel \
  "{query_type: current, class_name: person, confirmed_only: true, limit: 20}"
```

查询距离无人机最近的人：

```bash
ros2 service call /world_model/query aeromind_interfaces/srv/QueryWorldModel \
  "{query_type: nearest, class_name: person, confirmed_only: true, limit: 1}"
```

查询指定对象历史：

```bash
ros2 service call /world_model/query aeromind_interfaces/srv/QueryWorldModel \
  "{query_type: history, object_id: person_0001, limit: 50}"
```

Agent 同时注册了只读工具 `query_world_model`，支持 `current`、`nearest`、`history` 和 `health`，不会创建飞行确认或调用控制服务。

Web 态势地图会显示具有有效三维位置的语义对象。Agent 感知摘要会返回 `world_objects` 及证据来源。

## 3. 航线语义关系与事件

`object_tracker_node` 同时订阅 `/autonomy/trajectory`。对于确认状态的 `person` Track，节点会：

1. 将轨迹通过 TF 转换到语义对象所在坐标系。
2. 使用当前位置和恒速预测计算未来 2 秒内到轨迹折线的最小三维距离。
3. 在基础安全半径上加入位置协方差裕度。
4. 连续 3 帧满足侵入条件后发布进入事件，连续 3 帧离开后发布清除事件。

检查接口：

```bash
ros2 topic echo /world_model/relations
ros2 topic echo /world_model/events
```

关系谓词包括 `intersects_path` 和 `near_path`。事件包括：

- `person_entered_path`：人员持续进入规划航线。
- `person_cleared_path`：人员持续离开，或轨迹结束、超时。

事件保存对象 ID、轨迹 ID、最小距离、动态阈值、预测时间、坐标系和证据来源。Web 态势地图会把侵入航线的对象放大并标红。

连续多航点 Action 已消费上述事件。`person_entered_path` 触发 `semantic_person_hold`，控制层保持悬停但保留原始世界坐标航点；`person_cleared_path` 连续稳定达到门限后，自主节点从当前位置重拼接剩余 Minimum Snap 轨迹。Workflow 可通过 `capture_on_semantic_hold: true` 在每次新悬停事件中保存一次现场图像。人员持续占用超过默认 30 秒时，Action 失败并保持悬停，不会盲目恢复。

该闭环只在用户已经确认的 `follow_waypoints` 任务中生效。语义事件不能创建新飞行任务、改变最终目标或绕过确认；几何 ESDF 碰撞检查和传感器超时保护仍然具有独立约束。

若入侵人员在悬停期间丢失跟踪或感知退化，系统将其视为“未知”而不是“已经离开”，不会发布错误清除事件；无法重新确认安全时由悬停超时终止任务。

## 4. 动态目标与局部规划

`autonomy_node` 订阅 `/world_model/objects`，将已确认、三维位置有效且未过期的 `person` Track 转换到当前里程计坐标系。动态预测层使用对象位置、速度、尺寸和位置协方差，在候选轨迹每个采样时刻计算：

```text
预测位置 = 当前位置 + 速度 × 预测时间
禁入半径 = max(对象半径, 默认半径) + sigma × 位置标准差
动态净空 = 无人机轨迹点到预测位置的距离 - 禁入半径
最终净空 = min(ESDF 几何净空, 动态净空)
```

单点运动基元和连续多航点的前视窗口都使用最终净空。动态目标预计横穿直达轨迹时，规划器会优先选择安全的侧向、爬升或降高运动基元；所有候选仍不安全时保持悬停。连续航点发生局部重规划后，仍从当前位置拼接剩余 Minimum Snap 轨迹。

默认参数：

- `autonomy_dynamic_planning_enabled:=true`
- `autonomy_dynamic_object_timeout_sec:=1.5`
- `autonomy_dynamic_object_radius_m:=0.45`
- `autonomy_dynamic_uncertainty_sigma:=2.0`

该预测层不会向 ESDF 写入持久体素，避免移动人员在地图中留下虚假静态障碍。Track 或 TF 过期后动态快照自动失效；已经触发的人员航迹悬停仍由上一节的确定性事件门控处理。

`/autonomy/status` 同步发布 `dynamic_object_id`、`dynamic_clearance_m` 和 `dynamic_ttc_sec`。Web 自主状态卡会显示“动态目标”和“动态净空 / TTC”，Agent 状态证据也包含这些字段。

## 5. 当前边界

- RTAB-Map 模式可使用 `map` 坐标且对象观测已进入 SQLite，但尚未实现定位重启版本和跨会话 ID 合并。
- 目标关联使用类别和三维近邻，尚未接入 ByteTrack/BoT-SORT/ReID，长遮挡和多人交叉仍可能切换 ID。
- 已有三维卡尔曼位置协方差，但尚未传播检测框、深度与 SLAM 定位的完整测量协方差。
- 前视深度只覆盖相机视场，“未观测”不等于“不存在”。
- 语义对象已进入运动基元和连续航点前视窗口的时空净空评分，但当前采用恒速模型与距离代理，尚不是完整碰撞概率、社会运动预测或 MPC。
- 默认只使用置信度不低于 0.45 的确认 Track；低置信度目标的统一限速/悬停策略和世界模型健康门控仍需标定后接入。
- 语义保护目前只覆盖 `follow_waypoints`，普通单点 `move` 尚未迁移到同一 ROS 2 Action 执行模型。
- 自动拍照是可选的 Workflow 留证动作；拍照失败不会让无人机越过语义悬停门控。

## 6. 后续顺序

1. 用固定 Rosbag 统计同步差、TF 成功率、ID Switch 和三维位置误差。
2. 接入 ByteTrack/BoT-SORT，与当前三维近邻关联进行对照。
3. 基于 RTAB-Map `map` 坐标建立 SQLite 对象历史与重定位版本。
4. 扩充 `near/intersects_path` 为语义区域和通用场景关系。
5. 用固定 AirSim 横穿场景统计语义悬停响应时间、误停率和错误恢复次数。
6. 用横穿、同向和迎面三类场景标定动态半径、TTC 与误停率，再评估社会运动预测和 MPC。
