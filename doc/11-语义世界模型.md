# 语义世界模型

本模块把 YOLO 的二维检测、深度图、相机内参和 ROS TF 融合为结构化三维对象，为 Agent、态势地图和后续动态避障提供统一的环境事实。

本文说明已实现功能；后续完整工作包和验收计划见 [语义世界模型升级计划](12-语义世界模型升级计划.md)。

当前数据链：

```text
/perception/detections + Depth + CameraInfo + TF
                    ↓ 时间差门控与三维投影
       /world_model/observations
                    ↓ 恒速三维卡尔曼滤波与生命周期
          /world_model/objects
                    ↓
       Agent Gateway / Web / 后续场景图
```

## 1. 当前实现

`semantic_fusion_node` 负责生成当前三维观测，订阅：

- `/perception/detections`：YOLO 类别、置信度和二维检测框。
- `/sensor/camera/rgb/front_center`：提供原始图像尺寸。
- `/sensor/camera/depth/front_center`：在检测框中心区域计算中值深度。
- `/sensor/camera/depth/front_center/camera_info`：将像素反投影到相机坐标系。
- `/tf`：将相机坐标转换到 `odom` 世界坐标系。

融合节点发布 `/world_model/observations`。`object_tracker_node` 再使用恒速三维卡尔曼滤波和同类别距离关联，向 `/world_model/objects` 发布短时稳定 ID、类别、置信度、三维位置、速度、位置协方差、生命周期、数据年龄和证据来源。

生命周期包含 `tentative`、`confirmed` 和 `lost`，默认连续命中 3 次后确认。Detection 与 Depth 的时间差默认不得超过 150 ms；`/world_model/health` 会发布同步差、Depth/CameraInfo/TF 状态、观测数和稳定 Track 数。

深度或 TF 不可用时，对象仍可作为二维观测发布，但 `position_valid=false`，不应用于三维距离决策。

## 2. 启动与验证

PX4 主 Launch 默认启动语义融合节点；需要 YOLO 提供对象输入：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  yolo_enabled:=true semantic_world_enabled:=true
```

检查数据：

```bash
ros2 topic hz /world_model/objects
ros2 topic echo /world_model/objects --once
ros2 topic echo /world_model/health
ros2 run tf2_ros tf2_echo odom camera_front_center_optical
```

Web 态势地图会显示具有有效三维位置的语义对象。Agent 感知摘要会返回 `world_objects` 及证据来源。

## 3. 当前边界

- RTAB-Map 模式可使用 `map` 坐标，但对象尚未进入 SQLite 持久库，定位重启后 ID 不保留。
- 目标关联使用类别和三维近邻，尚未接入 ByteTrack/BoT-SORT/ReID，长遮挡和多人交叉仍可能切换 ID。
- 已有三维卡尔曼位置协方差，但尚未传播检测框、深度与 SLAM 定位的完整测量协方差。
- 前视深度只覆盖相机视场，“未观测”不等于“不存在”。
- 语义对象已用于 Agent 查询和 Web 展示，尚未作为动态障碍直接绑定到轨迹规划器。

## 4. 后续顺序

1. 用固定 Rosbag 统计同步差、TF 成功率、ID Switch 和三维位置误差。
2. 接入 ByteTrack/BoT-SORT，与当前三维近邻关联进行对照。
3. 基于 RTAB-Map `map` 坐标建立 SQLite 对象历史与重定位版本。
4. 增加语义区域和场景关系，建立可查询场景图。
5. 将动态对象预测位置接入局部重规划，进行时空避障。
6. 增加人员进入航线时悬停、拍照，离开后恢复任务的事件闭环。
