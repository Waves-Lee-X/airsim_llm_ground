# 限制与升级路线

本文集中维护当前不足、技术风险和升级顺序。项目的阶段目标是从“可演示研究原型”逐步发展为“可重复验证的自主无人机系统”，而不是一次性堆叠更多模型和界面功能。

语义世界模型的专项工作包、指标和时间表见 [语义世界模型升级计划](12-语义世界模型升级计划.md)。

## 0. 当前结论（2026-07-22）

项目当前定位为**可演示、可记录、可重复评测的研究原型**，还不是可直接部署到真机复杂环境的成熟自主飞行系统。

当前已经形成的可靠基础包括：

- ROS 2 飞控、感知、自主规划、Agent Gateway、Web/飞书的完整数据与控制链路。
- 高风险动作确认、确认幂等、Mission 单调终态和 Workflow 失败收敛。
- RGB、Depth、PointCloud、YOLO、VLM 的统一健康状态和过期数据清理。
- 连续多航点 Action、Minimum Snap 参考轨迹及局部重规划后的剩余轨迹拼接。
- 固定任务的 JSON/CSV/Markdown 指标报告和 10 次/90% 严格验收门禁。

当前最重要的工作不是继续增加模型或规划算法，而是完成固定场景 10 次真实回归、Rosbag 证据采集和失败复现。真实 VIO/SLAM、成熟 ESDF、全局拓扑规划、Safety Supervisor 和真机分级测试仍属于后续核心工程。

语义世界模型目前只保留低频对象记录、查询和证据关联能力。动态障碍轨迹外推直接参与局部规划的方案已回退，待多目标跟踪、三维定位和固定数据集评测可靠后再重新引入。

## 1. 当前主要不足

### 1.1 真实 VIO/SLAM 尚未部署

当前定位主要来自 PX4/AirSim `/sensor/odometry`。Autonomy 虽然支持切换 `nav_msgs/Odometry` Topic 和协方差门控，但 OpenVINS、VINS-Fusion、ORB-SLAM3、RTAB-Map 等真实定位器尚未完成部署、标定和回归。

影响：真机进入 GPS 拒止或视觉复杂环境时，世界坐标地图和轨迹无法保持可信。

### 1.2 传感器频率和标定不足

可靠 VIO 通常需要高频 IMU、20～30 Hz 图像、准确内参/畸变、相机到 IMU 外参和时间同步。当前仿真相机曾出现约 0.6 Hz 的低频数据，不满足 VIO 条件。

### 1.3 地图后端仍是基础实现

当前滚动体素和距离查询可用于研究原型，但不是 Voxblox、FIESTA、nvblox 等成熟 ESDF 系统。稀疏树木、地面点、动态障碍、遮挡和传感器噪声仍可能导致误触发或漏检。

### 1.4 局部规划仍可能陷入局部最优

角度扇区运动基元与恢复绕行可以处理基础障碍，但复杂树林、U 形障碍和狭窄通道可能反复左右切换或恢复失败。当前还缺少可靠全局引导、拓扑搜索和动态障碍预测。

### 1.5 轨迹跟踪不是 MPC

当前使用连续 Minimum Snap 参考轨迹与限速/加速度平滑跟踪，比离散位置点平滑，但没有显式求解无人机动力学约束、控制量和预测误差。高速、强风和激烈机动的跟踪性能有限。

### 1.6 感知仍以单帧为主

YOLO 提供固定类别检测，VLM 提供低频开放语义解释。当前缺少多目标跟踪、跨帧一致性、语义地图、RGB-Depth 几何绑定和不确定度标准化。

### 1.7 Agent 仍受能力目录约束

LLM 能组合已注册能力，但不能自动获得新的物理执行能力。当前动态规划、技能插件和条件分支已经形成基础，仍需更严格的规划 Schema、能力发现、仿真验证、任务修复和版本治理。

### 1.8 真机安全与工程化不足

尚未完成：

- 独立安全监督节点和硬件急停链。
- 地理围栏、速度/高度/电量统一约束。
- 伴随计算机部署、资源预算和进程守护。
- 网络断连、节点崩溃和传感器降级演练。
- 无桨台架、系留和逐级真机测试。
- 正式权限、审计、密钥管理和安全认证。

### 1.9 模块边界治理完成第一阶段，接口契约仍需固化

空检测、空障碍图的占位发布已经移除，YOLO 成为检测 Topic 的唯一业务发布者；`/perception/health` 已能区分“当前无目标”和“检测器失联/数据过期”。`planning_node` 对未消费障碍图的占位订阅也已删除。

剩余问题是接口契约尚未系统固化：消息版本、QoS、坐标系、单位、时间戳、新鲜度阈值和责任节点仍主要依靠代码约定。自主避障当前真实输入是 Depth/PointCloud 到局部体素地图的链路，不应仅根据某个 Topic 存在就宣称避障已经接通。

## 2. 模块专项改进清单

本节把感知、规划和避障的改进项目转换为可实施、可验收的工作包。优先级中，P0 表示继续功能开发前应先修复，P1 表示真实自主飞行的核心能力，P2 表示性能和智能化升级。

### 2.1 感知模块

| 优先级 | 改进项 | 实施方案 | 验收标准 |
|---|---|---|---|
| P0 | 统一感知 Topic 所有权 | 停止占位节点周期发布空检测和空障碍图；为 YOLO、融合节点和诊断 Topic 分配唯一发布者 | 通过 `ros2 topic info -v` 可确认每个业务输出只有一个责任发布者 |
| P0 | 数据新鲜度和降级状态 | 为 RGB、Depth、CameraInfo、PointCloud、Detection 记录时间戳、频率和超时原因，对 Web/Agent 输出 `OK/STALE/MISSING/ERROR` | 断开任一传感器后，2 秒内显示正确降级状态，不再把历史数据当成当前数据 |
| P0 | 时间同步和坐标校验 | 校验 RGB/Depth/CameraInfo 时间差、内参、深度尺度和 TF，增加启动自检 | 已知距离目标的深度误差和重投影误差在预设阈值内 |
| P1 | RGB-Depth-YOLO 三维融合 | 将二维检测框与深度图绑定，输出目标在相机和 `odom/map` 坐标系中的三维位置、尺寸和不确定度 | 对人、车等目标同时给出类别、置信度、三维位置和数据时间 |
| P1 | 多目标跟踪 | 接入 ByteTrack/DeepSORT 类方法，生成稳定 `track_id`、速度和轨迹 | 目标短时遮挡后仍能保持 ID，并可区分静态与动态障碍 |
| P1 | 感知可测试性 | 建立固定图片、Rosbag 和模拟超时测试，覆盖颜色编码、空帧、错误密钥和 VLM 超时 | 感知节点遇到异常输入不崩溃，自动降级并输出可定位的原因 |
| P2 | 语义世界模型 | 将检测、跟踪、三维位置和 VLM 属性融合为带时间的对象库 | Agent 能查询“最近的人”、“刚才出现的车”并返回传感器证据 |
| P2 | 非阻塞 VLM 管线 | 将 HTTP 调用移出 ROS 订阅回调，增加任务队列、超时、限频、取消和结果缓存 | VLM 超时时不阻塞其他 ROS 回调，不影响飞行状态更新 |

### 2.2 建图与避障模块

| 优先级 | 改进项 | 实施方案 | 验收标准 |
|---|---|---|---|
| P0 | 明确避障真实输入 | 在架构和代码中明确 Depth/PointCloud 到局部地图的链路；删除或重新定义未消费的 `/perception/obstacle_map` | 通过 Topic 图和 Rosbag 回放能证明每个规划障碍点的来源 |
| P0 | 空地图不得默认安全 | 区分“已观测为空”与“没有数据”；Depth/PointCloud 超时或无有效点时进入限速/悬停 | 遮挡相机、停止点云或发送空帧时，系统不会继续向未知区域高速前进 |
| P0 | 地面、自身和噪声过滤 | 引入地面平面过滤、机体排除区、离群点滤波和最小持续观测次数 | 无真实障碍的固定场景不再因地面或噪声反复触发左右绕行 |
| P1 | 成熟占据/ESDF 后端 | 选择 Voxblox、FIESTA 或 nvblox 之一，提供增量更新、未知区域和距离场查询 | 地图更新频率、查询延迟、内存和障碍距离误差有量化报告 |
| P1 | 更完整的环境观测 | 真机优先使用广角/多目深度或 3D LiDAR，明确前视盲区和侧后方未知区 | 绕树、侧向移动和倒退测试中不依赖不可见区域的假设 |
| P1（暂缓） | 动态障碍预测 | 先完成三维目标跟踪和速度误差评测，再将可信速度融入时间化占据；当前不使用语义外推直接控制轨迹 | 行人横穿场景中可提前减速/悬停，且误预测不会造成无障碍场景频繁绕行 |

### 2.3 规划与轨迹模块

| 优先级 | 改进项 | 实施方案 | 验收标准 |
|---|---|---|---|
| P0 | 轨迹连续性和任务终态 | 对重规划前后的位置、速度、加速度进行连续性检查；Action 统一返回成功、取消、阻塞、超时和传感器失效 | 连续多航点不因重新发布而停顿，Web/Workflow 能在有限时间内获得唯一终态 |
| P0 | 碰撞检查加密 | 除轨迹采样点外，按最大空间间隔进行线段/连续轨迹检查，并引入机体包络体 | 不会因 16 个采样点之间的空隙穿过细障碍 |
| P1 | 自适应局部运动基元 | 根据速度、净空、通道宽度和目标方向生成候选轨迹，代替完全固定的角度扇区 | 在宽阔、狭窄和树林场景中能自动选择不同速度和转弯尺度 |
| P1 | 全局/拓扑引导 | 建立粗粒度全局路径或拓扑走廊，局部规划器只负责短时域动力学可行性 | U 形障碍、多排树木和长距离任务不再长时间左右摇摆 |
| P1 | 基于地图的恢复策略 | 从局部可达空间生成恢复点，取代固定“右绕 5 m/左绕 5 m/上升” | 恢复动作在发布前经过可达性和全轨迹安全检查 |
| P2 | 动力学轨迹优化 | 在 Minimum Snap 中统一约束速度、加速度、jerk、航向和距障碍代价 | 轨迹不超出设定动力学约束，并降低停顿次数和跟踪均方根误差 |
| P2 | MPC 对照评测 | 保留当前跟踪器作为基线，在同一轨迹上对比 MPC 的误差、控制平滑度、CPU 占用和抗扰动能力 | 只有在多类场景中稳定改善且满足实时预算时才切换为默认控制器 |

### 2.4 定位、评测与安全支撑

| 优先级 | 改进项 | 实施方案 | 验收标准 |
|---|---|---|---|
| P0 | 可重复 Rosbag 基线 | 录制定位、TF、全部感知输入、地图、轨迹、控制和 Mission 事件 | 同一录包可离线重放感知和规划，并生成可比较的指标 |
| P0 | 诊断与安全门控 | 统一汇总定位质量、传感器新鲜度、地图状态和控制器心跳，输出允许速度和允许任务类型 | 任一关键链路超时后有唯一、可预测的降级行为 |
| P1 | VIO/SLAM 与坐标系回归 | 完成标定、时间同步、漂移、重定位和协方差验证 | 直线、转弯、遮挡和重定位场景均有轨迹误差报告 |
| P1 | 场景测试矩阵 | 建立空场、单障碍、细树干、U 形、狭通道、动态行人和传感器失效场景 | 持续统计成功率、最小障碍距离、耗时、路径长度、停顿次数和轨迹误差 |

## 3. 大模型应继续参与的方向

### 3.1 证据化 Agent

模型回答中的每个关键事实绑定来源和时间：飞控状态、深度统计、检测框、VLM 分析、任务事件。界面明确区分传感器事实、模型推断和操作建议，减少“历史记录被当成当前画面”的问题。

### 3.2 轻量语义状态与证据查询

将检测、深度、点云、位姿和时间关联为带新鲜度的对象记录：类别、位置、置信度和最后观测时间。LLM 查询结构化状态及其证据，而不是把所有原始 ROS 数据塞进 Prompt。当前阶段不让未经可靠跟踪验证的模型速度预测直接改变飞行轨迹。

### 3.3 主动感知

当 VLM 不确定时，模型可以规划安全的观察动作：改变视角、接近但保持距离、重新拍照、多帧确认，再决定继续、悬停或返航。

### 3.4 任务级失败恢复

模型根据结构化失败原因选择受控恢复策略，例如重新观察、换路线、降低任务范围、跳过非关键点或请求人工介入。恢复动作仍必须来自白名单能力。

### 3.5 经验记忆与评测

保存任务条件、场景、轨迹、失败原因和恢复结果，检索相似任务给规划器提供建议。记忆不能自动覆盖当前实时状态，也不能绕过确认机制。

### 3.6 VLA Shadow Mode

VLA 可以作为研究方向，对历史/实时数据输出建议动作，与现有规划器结果对比并评测，但先不实际控制无人机。达到数据量、稳定性和安全指标后，再考虑受限场景的低权限接管。

## 4. 推荐升级顺序

### 阶段 0：冻结基线和建立评测

目标：任何优化都能量化比较。

- 固定 AirSim 场景和任务集。
- 录制 RGB、Depth、PointCloud、Odometry、TF、Trajectory 和状态 Rosbag。
- 建立成功率、最小障碍距离、规划耗时、路径长度和跟踪误差指标。
- 修复所有状态不一致、任务无终态和节点崩溃问题。

验收：同一提交在同一场景可重复得到近似结果。

当前状态：指标工具和终态一致性已完成；固定场景 10 次实测、Rosbag 自动录制和离线回放尚未完成。

### 阶段 1：传感器标定与 VIO/SLAM

- 提高相机和 IMU 频率。
- 完成内参、畸变、外参和时间同步。
- 首选一种定位器完成仿真/录包离线验证，再接实时 Topic。
- 验证漂移、重定位、协方差和坐标系。

验收：静态、直线、转弯和遮挡场景均有量化轨迹结果。

### 阶段 2：成熟地图与语义融合

- 接入 Voxblox/FIESTA/nvblox 等一个成熟后端。
- 建立地面过滤、自身过滤、动态障碍和衰减策略。
- 将 YOLO/VLM 对象绑定三维位置和时间。
- 在 RViz/Web 同时显示原始点云、占据/ESDF 和语义对象。

### 阶段 3：全局引导和局部连续重规划

- 引入 EGO-Planner/Fast-Planner 类局部规划思想或成熟库。
- 保留连续多航点 Action 和局部重规划轨迹拼接。
- 增加拓扑/全局走廊，解决 U 形障碍和复杂树林。
- 对动态障碍加入速度估计和预测占据。

### 阶段 4：控制器升级

- 先完成当前轨迹跟踪误差统计和参数整定。
- 再加入动力学模型、状态约束和控制约束。
- 在仿真中并行比较简单跟踪器与 MPC。
- 只有 MPC 在误差、平滑度和稳定性上显著改善时再启用。

MPC 不用于体现大模型能力，它属于确定性控制优化。大模型可以解释任务、调整高层策略和选择轨迹约束，但不应替代高频 MPC 求解器。

### 阶段 5：认知任务闭环

- 结构化证据总线和语义世界模型。
- 事件驱动多帧 VLM。
- 主动感知 Skill。
- 基于失败类型的 Workflow 自动修复。
- 任务级经验检索和可追溯报告。

### 阶段 6：真机安全与部署

- 伴随计算机资源评估和节点分配。
- systemd/Docker/Launch 生命周期管理。
- 独立 Safety Supervisor、遥控器接管、地理围栏和失联策略。
- 无桨台架、系留、低速、低高度、小范围逐级测试。
- 记录每次飞行的参数、版本、日志和安全事件。

## 5. 真机代码运行在哪里

推荐分层部署：

```text
PX4 飞控板：姿态估计、控制器、混控、电机输出
机载伴随计算机：ROS Bridge、感知、自主规划、控制网关、安全监督
地面站电脑：Web UI、任务管理、日志和可选 LLM Gateway
云端模型：低频 LLM/VLM，可断开且不能成为飞行稳定的必要条件
```

高频、安全关键模块尽量靠近无人机运行；Web、长期记忆和大模型可放在地面站。网络中断时无人机仍必须能悬停、降落或 RTL。

## 6. 优先级建议

| 优先级 | 工作 | 原因 |
|---|---|---|
| P0 | 可重复场景、Rosbag 和指标 | 没有基线就无法判断优化是否有效 |
| P0 | 状态/任务终态一致性 | 直接决定演示和安全可信度 |
| P0 | 感知 Topic 所有权与新鲜度 | 避免空占位消息覆盖真实检测，防止使用过期数据 |
| P0 | 空地图降级和轨迹连续性 | 直接关系碰撞风险、飞行顿挫和任务卡死 |
| P1 | VIO/SLAM 与标定 | 是未知环境自主飞行的基础，但不应在校赛稳定性回归前临时替换定位链路 |
| P1 | RGB-Depth-YOLO 三维融合与跟踪 | 把“看到类别”升级为“知道目标在哪里、如何运动” |
| P1 | 成熟地图与规划器 | 解决树木、窄通道和局部最优 |
| P1 | Safety Supervisor | 真机前必须完成 |
| P1 | 证据化 Agent 和语义地图 | 体现大模型的真实系统价值 |
| P2 | MPC | 在定位和轨迹稳定后再投入 |
| P2 | VLA Shadow Mode | 需要数据和评测基础 |

## 7. 成熟度目标

项目不应只用“功能是否存在”衡量成熟度。推荐用以下门槛：

- 任务成功率和失败原因可统计。
- 每个任务都有明确终态。
- 感知、规划和控制延迟可观测。
- 安全距离和轨迹误差可量化。
- 断网、节点崩溃和传感器超时有确定降级行为。
- 同一任务可以在固定场景重复验证。
- 仿真通过后才进入分级真机测试。

## 8. 建议的近期实施顺序

为避免同时更换感知、地图、规划和控制后无法定位问题，当前按以下顺序执行：

1. **已完成**：清理空检测/空障碍图发布，统一检测 Topic 所有权。
2. **已完成**：增加感知数据新鲜度、频率、超时原因和 Web/Agent 降级显示。
3. **已完成**：Mission 唯一终态、重复确认幂等和 Workflow 失败步骤收敛。
4. **已完成**：固定任务指标脚本与 10 次/90% 严格验收门禁。
5. **当前执行**：固定 AirSim 场景和任务文本，逐次完成 10 轮真实主链测试并形成报告。
6. **下一步**：为每轮任务自动录制 Rosbag，将 Mission ID、参数、日志和传感器时间窗关联归档。
7. **下一步**：建立 Rosbag 离线回放，优先修复地面/自身/噪声误检和空地图降级。
8. **后续**：完成标定、TF 与 RGB-Depth-YOLO 三维融合，再评估真实 VIO/SLAM 和成熟 ESDF。
9. **长期**：加入全局/拓扑引导、Safety Supervisor；定位和轨迹稳定后再对比 MPC。
10. **研究方向**：在证据和评测充分后升级主动感知、Agent 失败恢复及受限的语义动态预测。

### 2026-07-22：Mission 与 Workflow 终态一致性

已完成：

- Gateway Mission 增加单调递增 `revision`，前端忽略迟到的旧版本状态。
- `completed/failed/cancelled/expired` 成为不可逆终态，迟到进度不能把任务写回 `executing`。
- 重复提交同一个确认请求采用幂等响应，不会再次执行飞行动作。
- Workflow 失败时，尚未执行的步骤统一收敛为 `skipped`；取消时，活动步骤为 `cancelled`，其余步骤为 `skipped`。
- 前端收到 Mission 终态后主动清除对应确认弹窗并隐藏 Workflow 控制按钮。
- Gateway 重启中断仍保留 `failed + interrupted`，区分算法失败与进程中断。

下一步：围绕固定主任务建立 10 次连续执行回归和 Rosbag/指标采集，不再仅依赖单元测试判断飞行闭环稳定性。

### 2026-07-22：固定演示主链量化验收

- VLM HTTP 推理从传感器回调组中隔离，感知节点改用三线程执行器，避免一次语义分析阻塞整条 RGB-D、LiDAR 和 YOLO 健康链。
