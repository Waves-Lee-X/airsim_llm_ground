# 系统架构与数据流

本文从初学者视角解释项目各模块为什么存在、数据怎样流动，以及 ROS 2、PX4、AirSim、Web、Agent 和 TF 之间的关系。

## 1. 为什么使用 ROS 2

无人机系统同时包含相机、点云、定位、感知、规划、控制和界面。如果每个模块都直接连接其他模块，接口会迅速失控。ROS 2 提供统一的消息类型、发现机制、进程间通信和调试工具，使每个模块只关心自己的输入和输出。

在本项目中，ROS 2 不是飞控。它是上层机器人软件的通信与组织框架；真正的姿态稳定、电机混控和实时控制由 PX4 完成。

## 2. 四种 ROS 2 通信方式

### 2.1 Topic：连续数据流

发布者持续发布消息，订阅者按需接收，双方不需要相互等待。适合相机、点云、里程计和状态。

```text
airsim_bridge_node 发布 RGB Image
    ↓ /sensor/camera/rgb/front_center
perception_node、web_console_node、yolo_detection_node 分别订阅
```

“节点订阅相机”不是主动读取摄像头硬件，而是告诉 ROS 2：当这个 Topic 有新消息时，把消息交给我的回调函数。

### 2.2 Service：一次请求和一次响应

适合短时命令，例如解锁、起飞、降落、截图。Service 返回“请求是否受理”，不一定代表物理动作已经结束，因此系统还要继续观察飞控状态。

### 2.3 Action：长时间、可反馈、可取消的任务

适合多航点轨迹。`/autonomy/follow_waypoints` 使用 `FollowWaypoints.action`，客户端可以看到进度、取消任务并接收最终结果。

### 2.4 TF：坐标系关系

TF 描述坐标系之间的位置和旋转关系。相机看到的点位于相机坐标系，规划器需要将其转换到 `odom` 世界坐标系，才能和无人机位置、目标点放在同一张地图中。

## 3. 总体数据流

![ROS 模块与数据流](架构图/02-ROS模块与数据流.png)

系统有两条主要输入链和一条任务链：

```text
传感器链：AirSim RPC → aeromind_bridge → ROS Image/Depth/PointCloud2
飞控链：PX4 uORB → uXRCE Client → UDP 8888 → Micro XRCE-DDS Agent → ROS DDS
任务链：Web/飞书 → Agent Gateway → Skills/Workflow → ROS Agent → Autonomy/Control
```

## 4. PX4 与 Micro XRCE-DDS Agent

PX4 内部模块通过 uORB 通信，ROS 2 使用 DDS。PX4 的 uXRCE-DDS Client 把允许导出的 uORB 数据编码后通过 UDP 发出；`micro-xrce-dds-agent udp4 -p 8888` 接收数据并把它加入 ROS 2 DDS 网络。

因此 Micro XRCE-DDS Agent 不是 AirSim 桥，也不是 Web 服务。它专门解决 PX4 与 ROS 2 之间的消息转换和传输。

```text
PX4 uORB
  → PX4 uXRCE-DDS Client
  → UDP 8888
  → Micro XRCE-DDS Agent
  → ROS 2 DDS
  → /fmu/out/* 与 /fmu/in/*
```

## 5. AirSim 数据怎样进入 ROS 2

AirSim 在 Windows 中运行，`airsim_bridge_node` 在 WSL/Ubuntu 中通过 AirSim RPC 连接宿主机 IP。桥接节点主动调用 AirSim API 获取：

- Scene 图像，转换成 `sensor_msgs/Image` RGB Topic。
- DepthPlanar 图像，转换成深度 Image。
- LiDAR 数组，转换成 `sensor_msgs/PointCloud2`。
- 相机内参，发布 `sensor_msgs/CameraInfo`。

AirSim 传感器数据不经过 Micro XRCE-DDS Agent；PX4 飞控数据才经过 UDP 8888。两条链最终都进入 ROS 2，供感知、自主规划和 Web 使用。

## 6. 坐标系与 TF 树

项目对 ROS 侧采用 ENU 世界坐标：

```text
X：东
Y：北
Z：上
```

典型 TF 树：

```text
odom
└── base_link
    ├── camera_front_center_body
    │   └── camera_front_center_optical
    └── lidar
```

- `odom -> base_link`：无人机随时间变化的动态位姿。
- `base_link -> camera_*_body`：相机安装外参。
- `camera_body -> camera_optical`：ROS 光学坐标约定，Z 前、X 右、Y 下。
- `base_link -> lidar`：LiDAR 安装外参。

深度点云方向错误、左右相反或障碍固定在错误位置，通常首先检查 TF、ENU/NED 转换、相机 optical frame 和时间戳。

## 7. ROS 2 包职责

| 包 | 输入 | 输出/职责 |
|---|---|---|
| `aeromind_interfaces` | 无 | 公共 Message、Service、Action |
| `aeromind_bridge` | AirSim RPC、PX4 DDS | 标准传感器 Topic、DroneState、TF |
| `aeromind_perception` | RGB、检测结果 | 截图、VLM 分析、感知摘要 |
| `aeromind_autonomy` | 里程计、深度、点云、目标 | 地图、状态、平滑轨迹、多航点 Action |
| `aeromind_control` | 服务请求、轨迹、PX4 状态 | PX4 命令和 Offboard setpoint |
| `aeromind_agent` | 自然语言任务、系统状态 | 技能调用、Mission 状态和结果 |
| `aeromind_agent_gateway` | Web/飞书会话 | 流式模型调用、确认、Workflow、ROS 工具 |
| `aeromind_web` | ROS Topic/Service | HTTP API、WebSocket、媒体数据 |
| `aeromind_bringup` | Launch 参数 | 组合启动系统节点和 RViz |

## 8. 关键接口

### 8.1 状态与传感器

| Topic | 类型 | 说明 |
|---|---|---|
| `/control/drone_state` | `DroneState` | 解锁、模式、电池、GPS、EKF |
| `/sensor/odometry` | `nav_msgs/Odometry` | ROS ENU 位姿与速度 |
| `/sensor/camera/rgb/front_center` | `sensor_msgs/Image` | 前视 RGB |
| `/sensor/camera/depth/front_center` | `sensor_msgs/Image` | 前视深度 |
| `/sensor/lidar/points` | `sensor_msgs/PointCloud2` | LiDAR 点云 |
| `/perception/detections` | `DetectionArray` | YOLO 检测结果 |

### 8.2 自主飞行

| 接口 | 类型 | 说明 |
|---|---|---|
| `/autonomy/goal` | `PoseStamped` Topic | 单目标输入 |
| `/autonomy/trajectory` | `Trajectory` Topic | 规划器输出的连续轨迹 |
| `/autonomy/status` | `AutonomyStatus` Topic | 状态、策略、距离和结束原因 |
| `/autonomy/cancel` | `std_msgs/Empty` Topic | 取消当前自主任务 |
| `/autonomy/follow_waypoints` | `FollowWaypoints` Action | 连续多航点任务 |
| `/autonomy/esdf_obstacles` | `PointCloud2` Topic | 规划器使用的占据体素 |

### 8.3 控制与感知服务

| Service | 作用 |
|---|---|
| `/control/arm` | 解锁或加锁 |
| `/control/takeoff` | 起飞到目标高度 |
| `/control/land` | 降落 |
| `/control/return_home` | PX4 原生 RTL |
| `/perception/capture_image` | 保存当前 RGB 帧 |
| `/perception/analyze_image` | 规则/检测/VLM 图像分析 |

## 9. 自主规划与控制闭环

```text
里程计 + 深度/点云 + 目标
  → 世界坐标滚动体素地图
  → 动力学候选轨迹与安全距离检查
  → Minimum Snap 平滑轨迹
  → /autonomy/trajectory
  → control_node 连续跟踪
  → PX4 Offboard setpoint
  → 新里程计反馈
```

控制器不是每 2.5 秒才让无人机移动一次。规划器可以低频更新轨迹，而控制器需要高频沿轨迹采样并连续发送 setpoint。局部重规划应从当前轨迹状态平滑拼接剩余航段，避免突然停车和重新起步。

## 10. Agent 执行闭环

模型生成的是受约束的结构化计划。高风险动作通过确认后，ROS 2 才执行实际能力；任务完成由飞控状态、里程计和 Mission 结果验证。详细机制见 [Agent、Skills 与 Workflow](05-Agent、Skills与Workflow.md)。

## 11. ROS 数据怎样到 Web

浏览器不能直接订阅本项目的 ROS Topic。`aeromind_web` 运行在 ROS 环境中：

1. ROS 回调接收 Image、PointCloud2、DroneState 等消息。
2. 网关将消息转换为 JSON、JPEG 或抽样点集。
3. 浏览器通过 HTTP 获取快照，通过 WebSocket 接收实时状态与日志。
4. 浏览器提交控制请求时，网关再调用 ROS Service/Action。

默认端口：

| 端口 | 协议 | 用途 |
|---:|---|---|
| `8888` | UDP | PX4 uXRCE-DDS Client 到 Micro XRCE-DDS Agent |
| `8080` | HTTP/WebSocket over TCP | ROS Web 网关与内置页面 |
| `8090` | HTTP/WebSocket over TCP | Agent Gateway 流式会话 |
| `5173` | HTTP over TCP | 可选独立静态前端 |

Web 方案适合单机、局域网和地面站接入。Zenoh 更适合跨网络、弱网、多机器人或 DDS 难以直接发现的部署，但不是当前仿真系统的必需组件。
