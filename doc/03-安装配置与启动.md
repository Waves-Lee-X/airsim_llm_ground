# 安装配置与启动

本文是项目启动命令的唯一维护入口。默认环境为 Ubuntu 22.04/WSL2、ROS 2 Humble、PX4 SITL 和可选 Windows AirSim。

## 1. 前置条件

- Ubuntu 22.04 或 WSL2 Ubuntu 22.04。
- ROS 2 Humble。
- Python 3.10。
- `colcon`、Git 和常用 ROS 构建工具。
- PX4-Autopilot 源码与 SITL 构建环境。
- Micro XRCE-DDS Agent。
- AirSim Windows 可执行环境，可选。

环境专项配置见 [PX4 与 AirSim 配置说明](PX4与AirSim配置说明.md) 和 [WSL2 代理配置](WSL2代理配置.md)。

## 2. 首次安装

```bash
sudo apt update
sudo apt install -y python3-colcon-common-extensions python3-pip graphviz

cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
```

PX4 首次安装：

```bash
cd ~
git clone https://github.com/PX4/PX4-Autopilot.git --recursive
cd PX4-Autopilot
bash ./Tools/setup/ubuntu.sh
make px4_sitl_default
```

Micro XRCE-DDS Agent 的安装方式取决于本机环境。安装后确认命令存在：

```bash
micro-xrce-dds-agent --help
```

## 3. 每个新终端都要加载环境

```bash
source /opt/ros/humble/setup.bash
source ~/aeromind_ws/install/setup.bash
```

出现 `Package 'aeromind_bringup' not found`，几乎总是因为没有执行第二行，或者工作空间尚未成功构建。

## 4. 构建

全量构建：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

修改接口后，先构建接口和依赖包：

```bash
colcon build --symlink-install --packages-up-to \
  aeromind_interfaces aeromind_autonomy aeromind_control \
  aeromind_agent aeromind_agent_gateway aeromind_web aeromind_bringup
source install/setup.bash
```

## 5. 密钥持久化

推荐把密钥放在仅当前用户可读的环境文件中，而不是写进 Git：

```bash
mkdir -p ~/.config/aeromind
chmod 700 ~/.config/aeromind
touch ~/.config/aeromind/env
chmod 600 ~/.config/aeromind/env
```

编辑 `~/.config/aeromind/env`：

```bash
export DEEPSEEK_API_KEY="你的 DeepSeek Key"
export AEROMIND_LLM_API_KEY="$DEEPSEEK_API_KEY"
export AEROMIND_LLM_API_URL="https://api.deepseek.com/v1"
export AEROMIND_LLM_MODEL="deepseek-chat"
export DASHSCOPE_API_KEY="你的百炼 Key"
export AEROMIND_VLM_API_KEY="$DASHSCOPE_API_KEY"
export AEROMIND_VLM_API_URL="你的百炼兼容模式地址"
export AEROMIND_VLM_MODEL="qwen3-vl-plus"
```

在 `~/.bashrc` 末尾加入：

```bash
test -f ~/.config/aeromind/env && source ~/.config/aeromind/env
```

重新加载并验证：

```bash
source ~/.bashrc
test -n "$DEEPSEEK_API_KEY" && echo "DeepSeek Key 已加载"
test -n "$AEROMIND_LLM_API_URL" && echo "LLM 地址已加载"
test -n "$DASHSCOPE_API_KEY" && echo "百炼 Key 已加载"
test -n "$AEROMIND_VLM_API_KEY" && echo "VLM Key 已加载"
```

不要打印完整 Key，也不要把 `env` 文件放进仓库。

## 6. 推荐完整启动：PX4 + AirSim

### 6.1 终端 1：DDS Agent

```bash
micro-xrce-dds-agent udp4 -p 8888
```

### 6.2 终端 2：PX4 SITL

```bash
cd ~/PX4-Autopilot
make px4_sitl_default none_iris
```

### 6.3 Windows：AirSim

启动使用 PX4 模式配置的 AirSim 环境。参考 [AirSim 配置示例](AirSim配置示例.json)。WSL 中可用以下命令查看 Windows 默认网关：

```bash
ip route show default
```

### 6.4 终端 3：ROS 主系统

参赛演示推荐使用一个 Launch 同时启动 ROS 主系统、Web 和 Agent Gateway：

```bash
cd ~/aeromind_ws
source ~/.config/aeromind/env
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 launch aeromind_bringup aeromind_demo.launch.py \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  vlm_enabled:=true \
  agent_provider:=deepseek \
  agent_model:=deepseek-chat
```

这个入口把开放式任务规划交给 Agent Gateway，Legacy ROS Agent 保留规则兜底与确定性执行服务，但不再重复调用第二次 LLM。外部的 PX4、Micro XRCE-DDS Agent 和 AirSim 仍需先启动。

需要分别调试 ROS 与 Web 时，继续使用下面的独立命令。

不使用云端 LLM、YOLO 和 VLM：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  llm_enabled:=false \
  yolo_enabled:=false \
  vlm_enabled:=false
```

启用 DeepSeek 和 YOLO，不启用 VLM：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  llm_enabled:=true \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  yolo_confidence:=0.35 \
  vlm_enabled:=false
```

同时启用 DeepSeek、YOLO 和 Qwen3-VL-Plus：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  llm_enabled:=true \
  yolo_enabled:=true \
  yolo_model:=/home/waves/aeromind_ws/yolov8n.pt \
  yolo_confidence:=0.35 \
  vlm_enabled:=true \
  auto_analyze_enabled:=false \
  auto_analyze_use_vlm:=false
```

若使用阿里云模型服务的专属兼容地址，应把 `vlm_api_url` 替换为控制台提供的完整 `/compatible-mode/v1` 地址，并保证 Key 属于同一服务与区域。HTTP 401 通常是 Key 未加载、URL 与 Key 不匹配或账号权限不足。

### 6.5 终端 4：Web 与 Agent Gateway

DeepSeek：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch aeromind_bringup aeromind_web.launch.py \
  host:=0.0.0.0 \
  port:=8080 \
  agent_port:=8090 \
  agent_provider:=deepseek \
  agent_model:=deepseek-chat
```

Claude Agent SDK：

```bash
ros2 launch aeromind_bringup aeromind_web.launch.py \
  host:=0.0.0.0 port:=8080 agent_port:=8090 \
  agent_provider:=claude agent_model:=sonnet
```

访问 `http://localhost:8080`。

### 6.6 演示前自动预检

ROS 主系统和 Web/Gateway 启动后，先运行只读预检。该命令不会解锁或控制无人机，也不会输出密钥内容：

```bash
cd ~/aeromind_ws
source ~/.config/aeromind/env
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 run aeromind_bringup aeromind_demo_check \
  --require-yolo \
  --require-vlm
```

检查内容包括：

- LLM/VLM 环境参数是否加载，密钥值始终隐藏。
- Web `8080` 和 Agent Gateway `8090` 是否可访问。
- 飞控状态、里程计、RGB、深度、点云是否已经产生实时数据。
- 解锁、起飞、降落和 Agent ROS 服务是否就绪。
- 关键 ROS Topic 和可选 YOLO Topic 是否存在。

检查通过时退出码为 `0`；存在阻塞项时退出码为 `2`。每次结果自动保存到 `missions/contest/preflight-*.json`，可作为演示环境证据。

连续完成多次任务后生成稳定性报告：

```bash
ros2 run aeromind_bringup aeromind_mission_metrics \
  --since-hours 24 \
  --prefix school-demo-10-runs
```

工具同时读取 `~/.aeromind/agent_gateway.db` 和 `missions/*/mission.json`，在 `missions/contest/` 输出 JSON、CSV 和 Markdown，统计成功率、物理完成率、平均/P95 耗时及失败原因。报告中的成功率只能用于实际已完成的任务，不应把等待确认或执行中的任务算作成功。

### 6.7 独立前端，可选

```bash
cd ~/aeromind_ws/web/ground_station
python3 -m http.server 5173
```

访问 `http://localhost:5173`。关闭浏览器不会停止这个终端进程，使用 `Ctrl+C` 停止。端口占用时：


## 8. 关键 Launch 参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `airsim_ip` | WSL 默认网关 | AirSim Windows 地址 |
| `llm_enabled` | `true` | Legacy ROS Agent 是否启用 LLM 解析 |
| `yolo_enabled` | `false` | 是否启动 YOLO 节点 |
| `vlm_enabled` | `false` | 感知节点是否启用 VLM |
| `autonomy_enabled` | `true` | 是否启动自主规划状态机 |
| `autonomy_trajectory_execution` | `true` | Control 是否执行自主轨迹 |
| `autonomy_velocity_limit` | `1.8` | 自主轨迹速度上限，m/s |
| `autonomy_accel_limit` | `1.0` | 加速度变化上限，m/s² |
| `autonomy_odom_topic` | `/sensor/odometry` | 定位输入 Topic |
| `autonomy_world_cloud_topic` | 空 | 可选世界系注册点云 |
| `autonomy_waypoint_lookahead_sec` | `3.0` | 多航点轨迹碰撞前视时间 |
| `autonomy_waypoint_max_replans` | `12` | 单任务最大局部重规划次数 |

查看完整参数：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py --show-args
```

## 9. 启动后检查

```bash
ros2 node list
ros2 topic hz /sensor/odometry
ros2 topic hz /sensor/camera/rgb/front_center
ros2 topic echo /control/drone_state
ros2 topic echo /autonomy/status
ros2 service list | rg '/control|/perception'
ros2 action list
```

进入操作前至少确认：PX4 DDS 数据存在、里程计持续更新、相机符合预期、控制服务就绪、Web 的 8080/8090 连接正常。

## 10. 减少多个终端

当前可用 Launch 统一启动 ROS 节点，但 PX4、DDS Agent、AirSim 和 ROS 属于不同进程/操作系统，仍需要独立生命周期。后续可使用 `tmux`、systemd user service 或项目启动脚本统一管理。

推荐 `tmux` 窗口分工：

```text
dds | px4 | ros | web | rviz
```

不要把多个长期进程简单放在一条后台命令中；需要保留日志、退出状态和独立重启能力。
