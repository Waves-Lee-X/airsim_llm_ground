# 项目总结、不足与大模型升级方向

> 基线日期：2026-07-15  
> 适用对象：项目负责人、研发团队、合作方、汇报与演示人员  
> 文档目的：说明系统当前真实能力、工程边界、主要不足，以及大模型能力的后续升级顺序。

---

## 1. 项目概述

本项目是一套自然语言驱动的智能无人机任务系统，目标是让操作员通过 Web 地面站或移动端，以对话方式完成状态查询、任务规划、人工确认、感知分析、自主飞行和任务报告。

系统不是让大模型直接控制电机，而是采用分层架构：

```text
大模型层：任务理解、计划生成、工具选择、视觉语义、解释与报告
任务层：Skill、Workflow、确认中心、Mission 状态和执行验证
自主层：定位输入、地图、碰撞检查、局部重规划、平滑轨迹
控制层：PX4 Offboard、原生起降/返航、位置速度加速度控制
安全层：参数校验、权限、人工确认、传感器门控、超时和悬停
```

项目当前已经从“自然语言调用几个 ROS 服务”发展为具有多模型 Agent、多传感器感知、受控任务编排和局部自主飞行闭环的系统原型。

### 1.1 产品定位

- 自然语言驱动的无人机智能任务控制平台。
- 面向科研展示、项目汇报和后续产品化的智能地面站。
- 面向具身智能研究的任务规划、感知理解和自主执行实验平台。
- 面向团队协作的 ROS 2 模块化无人机软件基础。

### 1.2 当前成熟度结论

当前系统属于“功能完整的研究与演示原型”，还不是可直接部署到复杂真实环境的成熟无人机产品。

可以真实展示：

- 自然语言生成受控任务。
- 多轮流式对话和会话历史。
- 人工确认后调用 ROS 2/PX4。
- RGB、深度、点云和 YOLO 感知。
- VLM 开放语义图像分析。
- 多步骤 Workflow 和模块化 Skill。
- ROS 2 Action 连续多航点飞行。
- Minimum Snap 平滑轨迹。
- ESDF 风格碰撞检查和局部绕障重拼接。
- 截图、任务记录和报告。

不能宣称：

- 已达到复杂树林、城市或室内未知环境的稳定自主飞行能力。
- 已完成真实 VIO/SLAM、动态障碍预测和全局路径规划。
- 已通过真机安全认证、可靠性验证或长期无人值守测试。
- 大模型可以越过飞控和安全层直接控制无人机。

## 2. 当前系统架构

```text
┌─────────────────────────────────────────────────────────────────┐
│ Web 地面站 / 飞书                                                │
│ 对话、确认、状态、RGB、深度、点云、任务态势、日志、报告          │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTP + WebSocket / 飞书长连接
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ Agent Gateway                                                    │
│ Claude Agent SDK / DeepSeek / Qwen / 自定义 Provider             │
│ SQLite 会话与记忆 / MCP 工具 / Skill / Workflow / Confirmation   │
└──────────────────────────────┬──────────────────────────────────┘
                               │ ROS 2 Service / Action / Topic
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ ROS 2 任务与能力层                                               │
│ Agent / MissionManager / Perception / Planning / Autonomy        │
└───────────────┬──────────────────────┬──────────────────────────┘
                │                      │
                │ RGB/Depth/LiDAR      │ Goal / FollowWaypoints Action
                ▼                      ▼
┌────────────────────────┐   ┌────────────────────────────────────┐
│ YOLO + VLM 感知         │   │ Local ESDF + Kinodynamic Replan    │
│ 检测、语义、截图与报告  │   │ Minimum Snap + 剩余轨迹重拼接      │
└────────────────────────┘   └────────────────┬───────────────────┘
                                              │ Trajectory
                                              ▼
                                  ┌───────────────────────────────┐
                                  │ Control + PX4                  │
                                  │ Offboard / Arm / Land / RTL    │
                                  └───────────────────────────────┘
```

### 2.1 核心数据流

自然语言控制：

```text
用户输入
  -> Gateway 确定性路由或 LLM
  -> 结构化 Action / Skill / Workflow
  -> Schema、白名单和风险校验
  -> 人工确认
  -> ROS 2 执行
  -> 遥测和 Action 反馈验证
  -> Web 实时显示与任务报告
```

视觉分析：

```text
AirSim/真机相机
  -> ROS Image
  -> YOLO 实时检测
  -> VLM 按需或低频语义分析
  -> Detection / ImageAnalysis
  -> Agent 解释、目标搜索和报告
```

自主飞行：

```text
目标或相对航点
  -> ROS 2 Action
  -> 世界坐标航点
  -> 多段 Minimum Snap
  -> 前视 ESDF 碰撞检查
  -> Kinodynamic 局部绕障
  -> 剩余航点重新拼接
  -> Control 连续轨迹跟踪
  -> PX4 Offboard
```

## 3. 当前已经实现的能力

### 3.1 Web 智能地面站

- 中文企业级深色控制台界面。
- 飞控状态、位置、速度、电池、GPS、EKF 和飞行模式展示。
- RGB 相机、深度图、Three.js 点云和态势信息。
- RGB 图像放大查看和截图缩略图。
- 流式对话、Markdown 排版和历史记录滚动。
- 待确认任务弹窗、确认执行和取消执行。
- Workflow 进度、实时日志、任务报告和截图归档。
- WebSocket 状态推送，前端与 ROS 代码解耦部署。

### 3.2 多模型 Agent

- Claude Agent SDK 原生流式会话。
- DeepSeek、Qwen 等 OpenAI-compatible 模型。
- Provider 和模型切换。
- SQLite 会话、消息、事件、确认和任务持久化。
- Web 与飞书共享身份、任务和会话时间线。
- 滚动历史记忆和可选长期语义摘要。
- 规则兜底与确定性高频命令路由。

### 3.3 Skill、Workflow 与工具调用

系统采用三层能力结构：

```text
基础能力：状态、起飞、降落、RTL、移动、航点、拍照、检测、VLM
Skill：通过 SKILL.md + skill.yaml 描述可复用业务任务
Workflow：大模型动态组合步骤、依赖、条件、等待和失败策略
```

当前支持：

- 动作白名单和 JSON Schema 参数校验。
- 高风险任务统一人工确认。
- 条件分支、步骤依赖、有限循环、等待、暂停和取消。
- 安全检查、目标检测、VLM 分析、拍照和报告步骤。
- 正方形、V 字、巡检和人员条件分支等组合技能。
- MCP 只读工具获取飞控、里程计、检测和自主状态。

### 3.4 感知能力

- RGB、Depth、CameraInfo 和 LiDAR/PointCloud2 桥接。
- YOLO 已知类别实时检测和边界框。
- Qwen3-VL-Plus 等视觉模型的开放场景分析。
- 目标搜索中 YOLO 优先、VLM 语义兜底。
- 图像保存为 PNG，并归档到 Mission 目录。
- VLM 返回场景、物体、风险、建议和不确定信息。

### 3.5 飞行控制

- PX4 解锁、加锁、起飞、降落和原生 RTL。
- Offboard 位置、速度和加速度 setpoint。
- 起飞、降落、RTL 与自主轨迹之间的控制互斥。
- 速度限制、加速度平滑、最低高度和轨迹超时保护。
- 通过飞控、里程计和自主状态验证物理动作完成。

### 3.6 自主飞行与轨迹

- 世界坐标滚动体素地图和 ESDF 风格净空查询。
- 深度射线内部清障、时间衰减和局部地图裁剪。
- TF、相机内参、里程计质量和传感器新鲜度门控。
- 动力学受限的直飞、左右绕行、爬升和下降运动基元。
- ROS 2 `FollowWaypoints` Action，支持反馈、取消和结果。
- 连续多航点七阶 Minimum Snap，中间航点不逐点刹停。
- 稳定轨迹 ID 和心跳，不反复重置控制器时间轴。
- 前视碰撞检测触发局部重规划。
- 保留安全短航段，再向未完成原始航点重建 Minimum Snap 尾段。
- 找不到安全候选、传感器超时或超过次数上限时安全悬停。

### 3.7 当前验证基线

- `aeromind_interfaces`、`aeromind_autonomy`、`aeromind_control`、`aeromind_agent_gateway` 和 `aeromind_bringup` 构建通过。
- 当前相关自动化测试共 129 项通过。
- ROS 2 Action 接口生成和 Launch 参数解析通过。
- 模拟障碍测试可以选择侧绕运动基元并完成剩余轨迹拼接。

自动化测试通过只表示软件逻辑基线正常，不等于真机复杂环境验收通过。

## 4. 当前项目的主要优势

### 4.1 分层边界清晰

大模型不直接输出电机或姿态指令。模型输出必须经过能力白名单、参数校验、人工确认、ROS 状态机和 PX4 控制层，架构方向正确。

### 4.2 已形成端到端闭环

系统不只是聊天演示，已经具备从自然语言到 ROS 调用、物理状态验证、感知结果回传和任务报告的完整链路。

### 4.3 模块化程度较高

感知、自主、控制、Agent、Gateway 和 Web 可以独立开发。团队成员可以通过 Skill 和 ROS 接口扩展任务，而不必修改整个系统。

### 4.4 大模型能力具有可视化证据

流式任务拆解、工具调用、VLM 场景分析、任务报告和多轮上下文都能在界面上直接展示，适合项目演示和解释。

### 4.5 已有安全意识和失败终态

系统明确区分“命令已下发”和“物理动作已完成”，并具有确认、超时、取消、传感器失效、轨迹不安全和悬停保护。

## 5. 当前不足与风险

### 5.1 定位与地图仍是最大基础短板

当前 `/sensor/odometry` 主要来自 PX4/AirSim，没有完成真实 VIO/SLAM 部署。缺少：

- 真实相机和 IMU 时间同步。
- 相机、IMU 和机体系外参标定。
- OpenVINS、VINS-Fusion、ORB-SLAM3 或同类定位系统。
- 回环检测、重定位和长期地图。
- 定位质量退化后的任务级恢复。

没有可靠定位，后续所有三维规划、语义地图和自主巡检都会受到限制。

### 5.2 当前 ESDF 不是成熟地图后端

当前是自研滚动体素和在线距离查询，适合原型验证，但存在：

- CPU 开销随占据点数量增长。
- 地图分辨率、衰减和噪声较敏感。
- 没有成熟增量 ESDF 更新。
- 没有全局地图和已探索区域管理。
- 对细树枝、透明物体、弱纹理和传感器盲区能力有限。

后续应评估 Voxblox、FIESTA、NVBlox 或成熟规划栈。

### 5.3 局部绕障仍可能陷入局部最优

当前连续航点已经能触发局部改道和轨迹重拼接，但它仍是局部反应式规划：

- 只在传感器和局部地图范围内决策。
- 复杂 U 形障碍、狭窄通道和死胡同可能无法脱困。
- 没有全局拓扑路线提供绕障方向。
- 动态障碍物没有速度估计和未来轨迹预测。
- 多次局部重规划可能增加路径长度或产生左右策略切换。

### 5.4 轨迹跟踪还不是 MPC

当前控制器执行位置、速度和加速度参考，并带平滑与限幅，但没有：

- 显式无人机动力学预测。
- 控制量和状态约束优化。
- 风扰、模型误差和延迟补偿。
- 轨迹跟踪误差在线优化。

复杂高速飞行和真机抗扰需要评估 PX4 MPC 调参、外部 MPC 或 NMPC。

### 5.5 VLM 仍以单帧、低频、建议式使用为主

当前 VLM 可以分析单帧 RGB，但：

- 缺少连续视频时序理解。
- 没有直接融合深度、点云、位姿和历史观测。
- 不能可靠给出精确距离和三维坐标。
- 云端调用延迟高，不能参与毫秒级避障。
- 语义建议只作为高层参考，尚未形成稳定的语义闭环。

### 5.6 大模型任务规划仍受能力目录约束

模型可以动态组合动作，但不能凭空获得底层不存在的能力。这是安全上正确的，但目前还存在：

- 能力前置条件和效果描述不够完整。
- 资源、时间、空间和互斥约束表达不足。
- 复杂计划主要依赖模型一次生成，缺少形式化计划修复。
- Skill 数量、覆盖场景和版本治理还不充分。
- 模型生成的计划缺少大规模自动评测。

### 5.7 证据与推断没有完全标准化

界面和报告中可能同时出现：

- 传感器直接测量。
- YOLO 检测结果。
- VLM 视觉推断。
- LLM 根据历史做出的推理。

如果不标明来源、时间和置信度，用户容易把模型推断误认为传感器事实。

### 5.8 工程化和真机安全尚未完成

- 缺少真机硬件在环和大规模场景回归。
- 缺少飞行禁区、地理围栏、速度包线和任务级电量预算。
- 缺少动态人员安全距离和紧急停止独立通道。
- 缺少 ROS 2 DDS 安全、证书、细粒度权限和网络隔离。
- 缺少容器化、一键启动、资源配额和边缘设备性能验收。
- 缺少长期稳定性、故障注入和安全认证材料。

### 5.9 当前成熟度评估

| 能力 | 当前水平 | 说明 |
|---|---|---|
| Web 地面站 | 中高 | 功能丰富，仍需持续做稳定性和大屏适配 |
| 多轮 Agent | 中高 | 流式、历史、确认和多 Provider 已具备 |
| Skill/Workflow | 中 | 可以组合任务，形式化约束和评测不足 |
| RGB/YOLO/VLM | 中 | 演示效果明确，时序和三维融合不足 |
| PX4 控制 | 中 | 基础闭环可用，真机参数和异常测试不足 |
| 局部自主飞行 | 中低 | 已有连续绕障原型，复杂场景能力不足 |
| VIO/SLAM | 低 | 接口已准备，真实系统尚未部署 |
| 动态障碍预测 | 低 | 尚未形成稳定跟踪预测链路 |
| 全局规划 | 低 | 缺少拓扑或全局路径层 |
| 真机产品化 | 低 | 安全、性能、部署和认证尚未完成 |

## 6. 大模型能力后续升级方向

### 6.1 方向一：建立“证据化 Agent”

让每条模型结论都携带来源：

```json
{
  "claim": "前方发现一名人员",
  "source": "yolo",
  "topic": "/perception/detections",
  "stamp": 1784110000.0,
  "confidence": 0.82,
  "frame_id": "camera_front_center"
}
```

升级内容：

- 区分 sensor、detector、VLM、LLM inference 和 mission history。
- 所有状态增加时间戳、新鲜度和坐标系。
- 报告引用原始截图、检测框、深度和任务事件。
- 模型不允许用历史记录替代当前实时状态。

价值：降低幻觉，让合作方能看到“大模型依据什么做出结论”。

### 6.2 方向二：构建多模态语义世界模型

把单帧分析升级为带空间和时间的世界状态：

```text
目标 ID
类别和语义描述
世界坐标与不确定度
速度和运动方向
首次/最近观测时间
关联截图和检测证据
可通行区域与风险标签
```

数据来源：

- YOLO/分割模型提供目标区域。
- Depth/LiDAR 提供三维位置。
- VIO/SLAM 提供世界坐标。
- 多目标跟踪提供速度和轨迹。
- VLM 提供开放类别、属性、关系和场景语义。

价值：模型可以回答“那个人是否仍在前方”“刚才发现的车辆在哪里”“哪条通道更适合巡检”。

### 6.3 方向三：事件驱动的时序 VLM

不应把每一帧都发送到云端模型。推荐：

```text
实时检测/跟踪运行在本地
  -> 新目标、风险变化、任务关键点触发事件
  -> 选择关键帧或短视频片段
  -> VLM 做低频语义判断
  -> 结果写入世界模型
```

可增加：

- 多帧一致性投票。
- 关键帧选择。
- 视频 VLM 或图像序列输入。
- RGB、深度可视化和任务上下文联合 Prompt。
- VLM 结果缓存和相似场景去重。

### 6.4 方向四：层级任务规划与自动修复

把一次性 Workflow 生成升级为层级规划：

```text
用户目标
  -> 任务约束抽取
  -> 高层任务图
  -> Skill/Action 实例化
  -> 确定性可执行性检查
  -> 执行监控
  -> 失败后局部修复计划
```

建议引入：

- Behavior Tree 或更完整的任务状态机。
- 前置条件、效果、互斥资源和超时的形式化描述。
- 计划模拟器，在确认前检查高度、距离、电量和任务时长。
- 只重规划失败子树，不重复已经完成的物理动作。
- 模型提出候选方案，确定性规划器验证后执行。

可支持的新任务：

```text
巡检前方区域；发现人员则保持三米距离悬停拍照，
否则沿道路继续前进二十米；如果能见度不足则返航并生成报告。
```

### 6.5 方向五：让大模型参与自主策略，而不是高频控制

大模型适合在秒级参与：

- 选择继续任务、等待、绕行、换高度或返航。
- 根据语义地图选择巡检区域。
- 判断任务目标是否已经满足。
- 解释阻塞原因并调整任务约束。
- 在多个可行局部路线中加入语义偏好。

大模型不应参与：

- 50～400 Hz 姿态与速度控制。
- 每个轨迹点生成。
- 紧急避障触发。
- 电机和执行器直接控制。

推荐闭环：

```text
底层规划器报告：左绕和上绕都安全
  -> 世界模型提供：上方有电线语义风险
  -> LLM/VLM 建议：优先左绕
  -> Safety Supervisor 验证左绕仍满足几何安全
  -> 底层规划器执行左绕轨迹
```

这样可以真实体现大模型对自主飞行的优化作用，同时不破坏实时性和安全边界。

### 6.6 方向六：技能自动生成与治理

可以让模型根据已有基础能力生成新 Skill 草案，但不能直接上线执行：

```text
自然语言需求
  -> 模型生成 skill.yaml + SKILL.md 草案
  -> Schema 校验
  -> 仿真回放
  -> 单元测试与安全审查
  -> 人工发布版本
```

应补充：

- Skill 版本、作者、依赖和适用机型。
- 输入参数、前置条件、效果和失败恢复。
- 仿真测试用例和验收指标。
- 禁止能力和最大风险等级。
- 技能签名、审核和回滚机制。

### 6.7 方向七：任务级记忆与经验检索

长期记忆不应只保存聊天摘要，还应保存结构化经验：

- 哪类场景曾触发误检。
- 哪组参数在某机型上表现稳定。
- 某任务失败在定位、感知、规划还是控制。
- 某区域历史上有哪些障碍和任务结果。

模型可以检索相似任务，给出参数建议，但历史经验不能覆盖当前实时安全检查。

### 6.8 方向八：VLA 与端到端模型研究

VLA 可以作为后续研究方向，但不建议直接接管现有真机控制。

建议分三步：

1. **Shadow Mode**：模型只预测动作，不执行，与现有规划器对比。
2. **仿真闭环**：只在 AirSim/Gazebo 中执行，并设置独立安全监督器。
3. **受限真机实验**：低速、围栏、小范围、人工急停和确定性控制兜底。

VLA 更适合学习视觉导航策略、目标接近和语义探索，不应替代 PX4 的姿态闭环和紧急保护。

## 7. 推荐升级路线

### 阶段 0：先建立可信评测基线

目标：知道系统是否真的在变好。

- 建立 ROS Bag 和仿真场景集。
- 固定自然语言任务测试集。
- 建立 Agent 计划正确率、工具选择率和确认准确率。
- 建立检测、VLM、轨迹、到达和避障指标。
- 保存每次模型、Prompt、参数、任务和结果版本。

验收指标示例：

| 指标 | 建议目标 |
|---|---:|
| 高风险任务确认覆盖率 | 100% |
| 不存在工具的拒绝率 | 100% |
| 简单任务结构化正确率 | ≥ 98% |
| 复杂 Workflow 可执行率 | ≥ 90% |
| ROS Action 终态覆盖率 | 100% |
| 报告证据可追溯率 | 100% |

### 阶段 1：补齐 VIO/SLAM 和标定

- 选定真实传感器和边缘计算平台。
- 完成相机、IMU 和时间同步。
- 接入 OpenVINS/VINS-Fusion/其他方案。
- 使用数据集和 ROS Bag 验证漂移、重定位和失效检测。
- 将定位质量输入 Safety Supervisor。

这是走向真实未知环境自主飞行的第一优先级。

### 阶段 2：语义世界模型和动态目标跟踪

- YOLO/分割 + 深度三维定位。
- 目标跟踪和速度估计。
- 世界坐标语义对象数据库。
- VLM 事件驱动分析。
- Web 显示语义目标、轨迹和证据。

### 阶段 3：成熟地图与全局/局部规划

- 接入成熟 ESDF 后端。
- 增加全局拓扑或采样规划层。
- 保留当前 kinodynamic + Minimum Snap 作为局部执行接口，或替换为成熟规划器。
- 增加死胡同脱困、动态障碍预测和安全走廊。
- 建立不同障碍场景回归。

### 阶段 4：任务规划、恢复和认知闭环

- 引入 Behavior Tree 或层级任务图。
- 建立任务前置条件、效果和资源模型。
- LLM 根据世界模型生成和修复任务。
- VLM/LLM 参与秒级策略选择。
- 所有建议继续经过确定性安全验证。

### 阶段 5：MPC、真机部署和安全工程

- 根据轨迹误差决定是否接入 MPC/NMPC。
- 完成容器化、一键启动和资源监控。
- 配置地理围栏、电量预算、链路失效和紧急停止。
- 硬件在环、故障注入和长时间稳定性测试。
- 逐步从仿真、半实物过渡到受限真机环境。

### 阶段 6：VLA Shadow Mode

- 采集专家轨迹和多模态任务数据。
- 训练或接入视觉动作模型。
- 只做影子预测和离线评分。
- 达到稳定指标后再进入仿真闭环。

## 8. 推荐团队分工

| 方向 | 主要职责 | 关键产出 |
|---|---|---|
| Agent/LLM | 计划、工具、记忆、评测、证据链 | Planner、Evaluator、Prompt 和测试集 |
| Perception/VLM | 检测、分割、跟踪、VLM、三维语义 | 语义目标和风险事件 |
| VIO/SLAM | 标定、同步、定位、地图 | 稳定 Odometry、TF 和地图 |
| Autonomy | ESDF、全局/局部规划、轨迹 | 安全可达轨迹和恢复策略 |
| Control/PX4 | Offboard、MPC、保护和真机参数 | 稳定轨迹跟踪与飞控安全 |
| Web/Gateway | 交互、确认、状态、报告和可观测性 | 可解释任务控制台 |
| Test/Safety | 场景库、Bag、故障注入和验收 | 回归报告与发布门禁 |

接口必须优先于实现约定，重点统一：

- 坐标系和时间戳。
- 状态新鲜度与置信度。
- Action 反馈和终态。
- 任务、感知和模型证据结构。
- 安全错误码与恢复策略。

## 9. 下一步最值得优先完成的工作

按投入产出比建议依次执行：

1. **建立自动评测与证据链**：避免模型和算法升级只能靠主观观察。
2. **部署真实 VIO/SLAM**：这是未知环境定位、地图和规划的基础。
3. **构建三维语义世界模型**：让 VLM、YOLO、深度、点云和位姿形成统一事实。
4. **增加全局规划和动态目标预测**：解决局部绕障的死胡同与移动障碍问题。
5. **升级层级任务规划与失败修复**：让大模型根据世界状态持续调整任务，而非只在开始时解析语言。
6. **最后评估 MPC 和 VLA**：先用数据证明现有轨迹跟踪或策略层确实需要替换。

近期最适合形成演示成果的组合是：

```text
自然语言巡检任务
  -> LLM 生成带条件的 Workflow
  -> 无人机连续多航点巡检并局部绕障
  -> YOLO + 深度定位人员
  -> VLM 对关键帧做场景和风险分析
  -> 语义世界模型保存目标
  -> Agent 根据证据决定悬停、拍照或继续
  -> 自动生成带截图、坐标和执行记录的报告
```

这个闭环能够比“自然语言转 ROS 命令”更充分地体现大模型在无人机领域的实际价值：模型参与任务理解、开放语义感知、策略选择、失败恢复和知识总结，而实时控制仍保持确定性、安全和可验证。

## 10. 总结

当前项目已经具备智能无人机系统的完整软件骨架，并实现了可演示的自然语言、视觉语义、任务编排、人工确认和自主飞行闭环。其主要价值不是某一个单点算法，而是把大模型、ROS 2、感知、自主规划、PX4 和 Web 控制台放进了同一套受控架构中。

下一阶段不应继续无序增加按钮或零散 Skill，而应围绕三条主线推进：

```text
可信：证据、评测、安全和可追溯
自主：VIO/SLAM、世界模型、全局/局部规划和动态障碍
智能：时序多模态、层级任务规划、失败修复和经验学习
```

只有当大模型能够持续读取可信世界状态、生成可验证计划、根据执行反馈修正策略，并由确定性系统安全落地时，系统才会从“带大模型的无人机控制台”真正升级为“基于大模型的具身智能无人机系统”。
