## 1. 项目概述

本项目是一套面向无人机仿真、自然语言任务编排、感知展示和自主飞行研究的分层系统。系统把 Web、飞书和大模型放在任务层，把 ROS 2 放在模块通信层，把 PX4 放在飞行控制层。

系统目标不是让大模型直接控制电机，而是让大模型完成：

- 理解自然语言任务。
- 读取无人机和环境状态。
- 选择受控技能。
- 拆解多步骤任务。
- 解释风险和执行结果。
- 请求人工确认。

确定性模块负责：

- 参数范围校验。
- 起飞前安全检查。
- Mission 状态机。
- 障碍地图和轨迹生成。
- PX4 Offboard setpoint。
- 飞行状态闭环和故障保护。

核心原则：

```text
大模型提出计划和工具请求
        ↓
安全层校验并等待人工确认
        ↓
ROS Agent 调用白名单服务
        ↓
Autonomy / Control 生成确定性控制
        ↓
PX4 执行并反馈真实状态
```

## 2. 系统分层原理

### 2.1 用户交互层

入口包括：

- Web 地面站。
- 飞书机器人。
- ROS 2 CLI。
- 键盘遥控节点。

Web 负责显示遥测、RGB、深度、点云、目标检测、任务步骤、模型回复和确认按钮。Web 本身不需要理解 DDS，也不直接连接 PX4。

### 2.2 Agent 会话层

`aeromind_agent_gateway` 提供：

- Claude Agent SDK 多轮流式会话。
- DeepSeek、Qwen 等 OpenAI-compatible Runtime。
- 会话和模型切换。
- WebSocket 事件流。
- SQLite 历史和记忆。
- 飞书 Channel Adapter。
- MCP 无人机工具。
- Confirmation Center。
- Workflow 编排。

它面向用户和模型，不直接发布 `/fmu/in/*`。

### 2.3 ROS 任务执行层

`aeromind_agent` 提供 `/agent/execute_task`，负责：

- 自然语言解析或规则回退。
- Skill 选择。
- 起飞前检查。
- ROS 服务调用。
- MissionManager 复合任务。
- `/agent/mission_status` 状态发布。
- 任务截图和报告归档。

Gateway 确认后会调用此 ROS Agent，复用已有安全逻辑。

### 2.4 感知与环境层

`aeromind_bridge` 把 AirSim/PX4 数据转换成 ROS 标准消息：

- `nav_msgs/Odometry`
- `sensor_msgs/Imu`
- `sensor_msgs/Image`
- `sensor_msgs/CameraInfo`
- `sensor_msgs/PointCloud2`
- 自定义 `DroneState`

`aeromind_perception` 负责：

- RGB 缓存。
- 图像保存。
- YOLO 目标检测。
- 图像语义分析。
- 感知摘要和障碍地图基础输出。

### 2.5 自主规划层

`aeromind_autonomy` 当前数据流：

```text
Depth + CameraInfo + TF
        │
        ├── optical frame 点云投影
        ├── 转换到 odom 世界坐标
        └── 射线清障和体素融合
                    ↓
          滚动 ESDF-style 体素地图
                    ↓
          Kinodynamic 运动基元采样
                    ↓
          clearance 连续轨迹检查
                    ↓
          七次单段 Minimum-Snap
                    ↓
             /autonomy/trajectory
```

当前实现是自主飞行基础，不等价于成熟 Voxblox/nvblox、EGO-Planner 或 Fast-Planner。

### 2.6 飞行控制层

`aeromind_control` 支持 AirSim 和 PX4 两种后端：

- PX4 原生 arm/disarm。
- PX4 原生 RTL。
- 起飞和轨迹使用 Offboard setpoint。
- 降落使用 PX4 降落命令。
- 轨迹速度限幅。
- 加速度平滑。
- 最低高度保护。
- 起飞、降落和自主轨迹互斥。

PX4 负责最终姿态、电机和飞行控制闭环。

## 4. ROS 2 通信原理

### 4.1 Topic

Topic 用于连续数据流，发布者不等待订阅者返回。

示例：

```text
/sensor/odometry
/sensor/camera/rgb/front_center
/autonomy/status
/autonomy/trajectory
```

适合遥测、图像、点云、状态和轨迹。

### 4.2 Service

Service 是一次请求和一次响应。

示例：

```text
/control/arm
/control/takeoff
/control/land
/perception/capture_image
/agent/execute_task
```

服务返回成功通常只代表命令被接受。长时间物理动作仍需继续读取状态验证。

### 4.3 DDS 与 QoS

ROS 2 节点通常通过 DDS 发现和传输消息，常见实现使用 UDP。它与 Web 的 8080 端口无关。

PX4 uXRCE-DDS 链路：

```text
PX4 uXRCE client
    ↕ UDP 8888
Micro XRCE-DDS Agent
    ↕ DDS
ROS 2 px4_msgs topic
```

PX4 输出常使用 `BEST_EFFORT` QoS，订阅端必须兼容，否则 topic 存在但没有数据。

### 4.4 Web 协议

| 端口 | 协议 | 作用 |
|---:|---|---|
| 8080 | HTTP/TCP | Web 页面、遥测 API、相机和报告 |
| 8080 | WebSocket/TCP | Web 实时状态推送 |
| 8090 | HTTP/TCP | Agent health、历史、技能和操作员 API |
| 8090 | WebSocket/TCP | Agent 双向流式对话和任务事件 |
| 8888 | UDP | PX4 uXRCE-DDS Agent |

AirSim Bridge 使用 AirSim RPC 与 Windows AirSim 通信；PX4 和 AirSim 之间的 UDP 端口由 AirSim/PX4 配置决定。

## 5. 数据如何到达 Web

以 RGB 图像为例：

```text
AirSim Camera
  → camera_bridge.py
  → sensor_msgs/Image
  → /sensor/camera/rgb/front_center
  → web_console_node 缓存并转换为浏览器数据
  → GET /api/camera 或 WebSocket 状态
  → Canvas 显示
```

以点云为例：

```text
AirSim LiDAR / Depth
  → PointCloud2 或 Depth Image
  → Web ROS 网关降采样
  → /api/pointcloud 或 /api/depthcloud
  → Three.js 3D 点云
```

以无人机状态为例：

```text
PX4 VehicleStatus
  → Bridge/Control 转换
  → /control/drone_state
  → Web 网关和 Agent Gateway 同时订阅
  → Web 遥测 + 大模型状态工具
```

## 6. 自然语言任务执行原理

### 6.1 Legacy ROS Agent

`aeromind_px4.launch.py` 启动 `agent_node`。它可以使用 OpenAI-compatible LLM 解析，也可以在超时或失败后使用规则解析。

```text
用户任务
  → /agent/execute_task
  → intent + skill + args
  → 安全检查
  → pending_confirmation
  → 用户确认
  → ROS 服务/Topic
  → MissionManager
```

### 6.2 Agent Gateway

`aeromind_web.launch.py` 默认同时启动 Agent Gateway。Gateway 提供真正多轮、流式、多 Provider 会话。

模型可用只读 MCP 工具：

```text
get_drone_state
get_perception_summary
get_system_snapshot
list_skills
```

模型可创建控制确认请求：

```text
request_arm
request_disarm
request_takeoff
request_land
request_move
request_return_home
request_hover
request_square_mission
request_workflow
```

这些工具不会立即改变飞控状态。

### 6.3 确认和物理完成验证

```text
模型创建请求
  → Gateway 保存 Confirmation 和 Mission
  → Web/飞书显示确认
  → 用户批准
  → Gateway 调用 ROS Agent
  → ROS Agent 内部安全确认
  → Control/Autonomy 执行
  → Gateway 读取遥测验证
  → completed / failed / cancelled
```

确认前不执行控制。ROS 服务响应不等于无人机已经完成动作。

### 6.4 Workflow

Workflow 支持：

- 最多 20 步。
- 前序依赖。
- `always`、`if_airborne`、`if_not_airborne`、`if_safe` 状态条件。
- `step_succeeded`、`step_failed`、`target_detected`、`target_not_detected` 前序结果分支。
- 0～2 次重试。
- `stop` 或 `continue` 失败策略。
- 暂停、恢复和取消。

动作白名单：

```text
safety_check
perception_check
arm / disarm
takeoff / land
move
return_home
hover
capture_image
```

模块化技能由 `SKILL.md`、`skill.yaml` 和 Workflow 执行器共同构成。`SKILL.md` 让模型理解技能用途；`skill.yaml` 声明参数、步骤和分支；通用加载器完成模板展开；执行器负责白名单校验、一次人工确认、结构化 ROS 调用和物理状态验证。当前包括正方形轨迹、V 字轨迹和人员条件巡检。

## 9. 坐标系和 TF

ROS 对外采用 ENU：

```text
X：东
Y：北
Z：上
单位：米、米每秒、弧度
```

TF：

```text
odom
└── base_link
    ├── camera_front_center_body
    │   └── camera_front_center_optical
    └── lidar
```

相机 optical frame：

```text
Z：前
X：右
Y：下
```

`/autonomy/goal`、Odometry 和注册点云必须使用一致世界 frame。不要把 PX4 NED 数值直接作为 ENU 发布。

## 18. 自主飞行关键参数

| Launch 参数 | 默认值 | 说明 |
|---|---:|---|

| `autonomy_min_depth_m` | 0.7 | 最小深度 m |
| `autonomy_max_depth_m` | 18.0 | 最大深度 m |
| `autonomy_map_radius_m` | 24.0 | 滚动地图半径 m |
| `autonomy_map_decay_sec` | 4.0 | 障碍保留时间 s |
| `autonomy_odom_timeout_sec` | 1.0 | 里程计超时 s |
| `autonomy_depth_timeout_sec` | 3.5 | 深度超时 s |

## 21. 常见故障排查

### Package not found

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

### 自定义消息 invalid

重新 source 工作空间，必要时重新构建 `aeromind_interfaces` 和依赖包。

### PX4 没有 ROS 数据

```bash
ps aux | grep micro-xrce-dds-agent
ros2 topic list | grep /fmu
ros2 topic echo /fmu/out/vehicle_status --qos-reliability best_effort
```

### 解锁后自动加锁

在 PX4 控制台执行：

```text
commander check
```

根据实际失败项处理 RC、GPS、电池、EKF 和安全开关。不要在真机上盲目关闭 failsafe。

### 相机有 Topic 但没有画面

```bash
ros2 topic hz /sensor/camera/rgb/front_center
ros2 topic echo /sensor/camera/rgb/front_center --once
ros2 topic echo /sensor/camera/rgb/camera_info --once
```

检查 `height * step == data size`，检查 encoding 是否与数据一致。

### ESDF 一直为空

```bash
ros2 topic hz /sensor/camera/depth/front_center
ros2 topic echo /sensor/camera/depth/camera_info --once
ros2 run tf2_ros tf2_echo odom camera_front_center_optical
ros2 topic echo /autonomy/status
```

缺少 CameraInfo 或 TF 时，Autonomy 默认拒绝融合。

### 无人机不移动

```bash
ros2 topic echo /autonomy/status
ros2 topic echo /autonomy/trajectory
ros2 topic echo /control/drone_state
```

重点检查：

- `state` 是否为 `SENSOR_WAIT`、`BLOCKED_HOLD` 或 `ARRIVED`。
- `planner_mode` 是否为 `safe_hover`。
- Control 是否处于起飞或降落互斥状态。
- `autonomy_trajectory_execution` 是否为 true。
- PX4 是否处于 OFFBOARD。

### Web 8080 打不开

```bash
ros2 node list | grep web_console
curl http://localhost:8080/api/status
ss -lntp | grep 8080
```

### Agent 8090 不可用

```bash
curl http://localhost:8090/health
ss -lntp | grep 8090
```

检查 API Key、Provider、数据库目录权限和 Python 依赖。

### 服务实际完成但界面显示超时

区分：

```text
服务响应超时
ROS Agent Mission 超时
物理状态验证超时
Web HTTP 超时
```

同时查看 `/agent/mission_status`、`/autonomy/status`、`/control/drone_state` 和 Gateway 日志。

## 22. 安全边界

1. 不允许大模型直接发布 PX4 uORB 输入。
2. 高风险控制必须经过人工确认。
3. 图像语义模型不能替代深度、LiDAR、EKF 和飞控 failsafe。
4. 真机不得直接使用 SITL 中关闭安全检查的参数。
5. 第一次测试应关闭轨迹执行，只观察状态。
6. 实飞应从系留、低高度、低速度、空旷场地开始。
7. RC 接管和急停必须独立于 Web、大模型和网络。
8. API Key、飞书密钥和 Agent Token 不得提交到仓库。

已完成：

- 多模型流式 Agent。
- Web/飞书跨端会话和确认。
- ROS 技能与 Workflow。

- 真实 VIO/SLAM 部署。
- 成熟 Voxblox/FIESTA/nvblox ESDF。
- EGO-Planner/Fast-Planner 等成熟局部规划。

- 完整复杂场景回归。

因此当前系统适合仿真演示、架构验证和模块研发，不应被描述为已经完成复杂未知环境真机自主飞行。

## 24. 推荐学习顺序

1. 用 ROS CLI 验证 DroneState、Odometry 和控制服务。
2. 理解 PX4 NED 与 ROS ENU 转换。
3. 查看 RGB、Depth、CameraInfo、PointCloud2 和 TF。
4. 发布 `/autonomy/goal` 并观察 Status/Trajectory。
5. 使用 Web 查看同一批 ROS 数据。
6. 调用 Legacy Agent 理解 Skill 和 MissionManager。
7. 使用 Agent Gateway 理解 MCP、确认、记忆和 Workflow。
8. 最后再进入 VIO/SLAM、ESDF 和真机安全。

本项目后续升级应以 [当前系统现状与升级交接说明](当前系统状态与升级交接说明.md) 为基线，先建立 ROS Bag 和可重复测试，再替换定位、建图和规划后端。
