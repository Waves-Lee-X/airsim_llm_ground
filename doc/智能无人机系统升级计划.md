# 基于大模型的具身智能无人机系统升级计划

> 目标：把当前项目从“自然语言无人机控制台”升级为“具备环境理解、任务状态机、失败恢复和自主飞行能力的具身智能无人机系统”。  
> 原则：大模型参与理解、推理、决策和报告；底层飞行安全仍由 PX4、规划器、控制器和安全监督层保障。  
> 执行方式：按阶段推进，每阶段都有可演示成果，不做一次性大重构。

---

## 0. 当前项目定位

当前系统已经具备以下基础能力：

- Web 地面站：状态、相机、点云、检测结果、任务链路、日志展示。
- ROS 2 模块化架构：Agent、Control、Perception、Autonomy、Bridge、Web、Interfaces。
- PX4 控制封装：解锁、起飞、降落、返航、Offboard、自主轨迹执行。
- LLM Agent：自然语言解析、技能选择、确认执行、规则兜底。
- 感知能力：RGB、Depth、LiDAR、YOLO 多目标检测、图片保存。
- 初级自主移动：自然语言相对移动目标 → `/autonomy/goal` → `/autonomy/trajectory` → `control_node` 执行。

当前主要不足：

- 复杂任务还缺少真正的异步任务状态机。
- 遇到树木等障碍物时，系统主要进入 `safe_hover`，不能主动绕行。
- 大模型主要负责语言解析，还没有真正参与图像/环境理解。
- YOLO 检测结果主要用于报告，没有深度融合到飞行策略。
- 自主规划还不是成熟的 SLAM/ESDF/重规划体系。

## 1. 总体目标架构

成熟版本应采用分层架构：

```text
Web 地面站
  ↓
LLM Agent 高层任务决策
  ↓
MissionManager 任务状态机
  ↓
VLM / Perception 场景理解
  ↓
World Model 语义世界模型
  ↓
RecoveryPlanner / Behavior Tree 失败恢复
  ↓
Autonomy Planner 局部规划与避障
  ↓
Control / PX4 飞控执行
  ↓
Safety Supervisor 安全监督
```

大模型参与：

- 任务理解
- 多步任务拆解
- 图像语义分析
- 风险解释
- 策略选择建议
- 失败原因总结
- 任务报告生成

大模型不直接参与：

- 电机控制
- 姿态控制
- 高频速度闭环
- 直接绕过安全检查发布飞控指令

## 2. 阶段 A：MissionManager 任务状态机

### 目标

把当前“解析后立即调用技能”的模式升级为“可等待、可验证、可恢复”的任务状态机。

示例任务：

```text
起飞，向前飞20米，并检测人
```

期望执行链：

```text
PARSE_TASK
→ SAFETY_CHECK
→ WAIT_CONFIRM
→ TAKEOFF
→ WAIT_TAKEOFF_DONE
→ MOVE_TO_GOAL
→ WAIT_GOAL_REACHED_OR_BLOCKED
→ DETECT_TARGET
→ GENERATE_REPORT
→ DONE
```

### 涉及模块

- `aeromind_agent`
- `aeromind_interfaces`
- `aeromind_web`
- `aeromind_autonomy`

### 主要实现

1. 新增任务状态结构：

```text
MissionTask
MissionStep
MissionStatus
```

2. Agent 内部增加 MissionManager：

```text
create_mission(task)
confirm_mission(token)
tick()
execute_current_step()
advance_or_fail()
```

3. 使用定时器驱动状态推进：

```text
0.5s tick
读取 drone_state / odom / autonomy_status / detections
判断当前步骤是否完成
```

4. 复杂任务不再一次性执行完，而是进入任务队列。

5. Web 显示：

- 当前任务阶段
- 当前步骤
- 已完成步骤
- 正在等待的条件
- 失败原因

### 当前完成情况

- [x] Agent 内部 MissionManager：支持创建、推进、超时和失败状态。
- [x] 复合任务链路：起飞、等待高度、发布自主目标、等待到达/阻塞、目标检测、任务报告。
- [x] `/agent/mission_status` 实时状态话题：Agent 周期发布任务快照。
- [x] Web 网关订阅任务状态，并通过 `/api/status` / WebSocket 下发给浏览器。
- [x] Web 任务态势面板实时显示复合任务步骤、当前阶段和失败原因。
- [ ] 任务取消、暂停、恢复接口。
- [ ] 多任务队列和任务优先级。

### 验收标准

输入：

```text
起飞，向前飞20米，并检测人
```

系统表现：

- 先返回确认请求。
- 用户确认后调用起飞。
- 到达目标高度后自动发布 `/autonomy/goal`。
- 等待 `goal_reached` 或 `blocked`。
- 到达后执行目标检测。
- 最后生成任务报告。

### 风险

- 需要处理服务异步返回和状态订阅之间的时序。
- 需要避免多个任务同时抢控制权。
- 需要任务取消和超时机制。

## 3. 阶段 B：RecoveryPlanner 失败恢复与基础绕行

### 目标

当自主飞行遇到阻塞时，不只是悬停，而是尝试有限的恢复策略。

当前问题：

```text
前方遇到树木
→ direct_goal 不安全
→ safe_hover
→ 任务阻塞
```

升级后：

```text
前方阻塞
→ 尝试右绕
→ 尝试左绕
→ 尝试上升
→ 仍失败则安全悬停并报告
```

### 涉及模块

- `aeromind_agent`
- `aeromind_autonomy`
- `aeromind_web`

### 主要实现

1. 新增 RecoveryPlanner：

输入：

```text
当前 odom
当前 goal
autonomy_status
depth summary
pointcloud summary
```

输出：

```text
新的 /autonomy/goal
或 safe_hover
```

2. 先做规则版策略：

```text
blocked_count == 1 → 右绕 5m
blocked_count == 2 → 左绕 5m
blocked_count == 3 → 上升 3m
blocked_count >= 4 → 悬停并报告失败
```

3. 后续接入 VLM 后，让 VLM 提供绕行建议：

```text
左侧树木密集，右侧开阔，建议右绕
```

### 当前完成情况

- [x] `aeromind_autonomy` 增加基础 RecoveryPlanner 逻辑。
- [x] 阻塞超时后不再立即清空目标，而是依次尝试右绕、左绕、上升恢复目标。
- [x] 到达恢复目标后自动恢复原始目标，继续执行任务。
- [x] 恢复策略用尽后才进入 `BLOCKED_HOLD` 并安全悬停。
- [x] `/autonomy/status` 支持 `RECOVERY` 状态，Web 可实时显示恢复阶段。
- [ ] 根据真实点云左右可通行空间选择恢复方向，而不是固定顺序。
- [ ] 恢复目标安全性预检查，避免把恢复点放到障碍物内部。
- [x] 与 VLM/语义目标结合：订阅 `/perception/image_analysis`，根据“右绕/左绕/上升”等语义建议调整恢复策略优先级。
- [ ] 基于语义目标类型进一步调整速度、距离和安全半径。

### 验收标准

输入：

```text
向前飞20米
```

如果遇到阻塞：

- Web 显示 `blocked`。
- Agent 自动进入恢复策略。
- 依次尝试右绕、左绕、上升。
- 失败后生成明确报告，而不是无解释停住。

## 4. 阶段 C：VLM 图像语义分析

### 目标

让大模型真正参与图像和环境解析，而不是只解析自然语言。

新增能力：

```text
当前画面里有什么？
前方是不是有树？
有没有人？
哪里更安全？
是否建议继续飞？
```

### 涉及模块

- `aeromind_perception`
- `aeromind_agent`
- `aeromind_web`

### 主要实现

1. 新增服务：

```text
/perception/analyze_image
```

2. 输入：

```text
RGB 图像
用户任务
YOLO detections
深度摘要
飞行状态
```

3. 输出：

```json
{
  "scene": "前方有树木和道路",
  "objects": [
    {"name": "tree", "position": "front", "risk": "high"},
    {"name": "person", "position": "left", "risk": "medium"}
  ],
  "suggestion": "建议右绕后继续前进",
  "confidence": 0.78
}
```

4. 第一版可接云端 VLM：

- GPT-4o / GPT-4.1 vision
- Qwen-VL API
- Gemini vision

5. 后续本地化：

- Qwen2.5-VL
- InternVL
- MiniCPM-V

### 当前完成情况

- [x] 新增 `AnalyzeImage.srv`，作为图像语义分析的 ROS 服务接口。
- [x] `perception_node` 提供 `/perception/analyze_image` 服务。
- [x] 默认规则模式：融合 RGB 状态和 `/perception/detections`，输出场景、目标、风险等级和建议。
- [x] 可选 VLM 模式：支持 OpenAI-compatible Vision API，发送当前 RGB 图像和检测摘要。
- [x] `SemanticImageSkill` 已加入 Agent 技能库。
- [x] Agent 支持自然语言调用：例如“分析当前画面中有什么”“描述前方图像”。
- [x] Web 技能库显示“图像语义分析”能力。
- [x] Launch 文件支持 `vlm_enabled`、`vlm_api_url`、`vlm_model`、`vlm_api_key` 参数。
- [x] 将 VLM/规则语义建议接入 RecoveryPlanner，影响绕行方向优先级。
- [x] 增加 `/perception/image_analysis` 缓存 topic，供 Agent、Web 和 Autonomy 复用。
- [x] Perception 支持自动低频图像语义分析，可按参数选择规则模式或 VLM 模式。
- [x] TargetSearchSkill 接入 `/perception/analyze_image`，YOLO 未命中时使用语义分析兜底搜索。

### 启动示例

规则/YOLO 摘要模式无需配置 VLM：

```bash

```

接入 OpenAI-compatible Vision API：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  yolo_enabled:=true \
  vlm_enabled:=true \
  vlm_api_url:=https://api.openai.com/v1 \
  vlm_model:=gpt-4o-mini \
  vlm_api_key:=你的API_KEY
```

输入：

```text
分析前方环境，判断是否可以继续前进
```

系统输出：

- 场景描述
- 目标列表
- 风险判断

## 7. 阶段 F：安全监督层

### 目标

保证大模型和自主规划不会越权控制无人机。

### 实现内容

- 最大速度限制
- 最大高度限制
- 最小高度保护
- 地理围栏
- 禁飞区
- 急停优先级
- 遥控器/人工接管
- 大模型输出动作白名单
- 控制指令审计日志

### 验收标准

任何任务执行前都能明确回答：

```text
这个动作是否安全？
是否需要人工确认？
是否触发限制？
如果失败，原因是什么？
```

## 8. 推荐实施顺序

建议严格按以下顺序推进：

```text
1. MissionManager 任务状态机
2. RecoveryPlanner 阻塞恢复
3. VLMAnalyzeSkill 图像语义分析
4. MissionReport 增强与日志落盘
5. 安全监督层增强
6. 接入 EGO-Planner / Fast-Planner
```

原因：

- 先做状态机，系统才有“任务执行主线”。
- 再做恢复策略，演示时遇到障碍不会只是停住。
- 再接 VLM，大模型才能真的参与环境理解。
- 最后换成熟规划器，避免一开始陷入底层算法大坑。
