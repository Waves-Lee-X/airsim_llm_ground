## 1. PPT 总体叙事

本项目面向无人机巡检、搜索、应急勘察、教学科研和智能机器人平台验证等场景，构建了一套“自然语言任务理解 + Web 地面站 + ROS 2 模块化架构 + PX4 飞控执行 + 感知与自主避障”的无人机智能控制系统。

系统的核心目标不是只做一个网页控制面板，而是形成一条完整闭环：

```text
用户自然语言任务
  → 大模型解析任务意图
  → Agent 选择对应技能
  → 安全检查与人工确认
  → 调用 ROS 2 服务 / Topic
  → PX4 飞控执行
  → 传感器数据回传
  → Web 控制台实时展示状态、图像、点云、检测结果和任务进度
```

面向甲方时建议强调三点：

1. **可视化**：浏览器端地面站可以实时查看飞行状态、相机、深度点云、目标检测、任务执行链路。
2. **智能化**：用户可以用自然语言描述任务，系统通过大模型解析为结构化指令，并由 Agent 调用受控工具执行。
3. **工程化**：底层基于 ROS 2 + PX4，模块之间通过标准 topic/service 解耦，便于团队并行开发和未来迁移真机。

### 第 2 页：项目背景与需求

**标题**：传统无人机控制方式存在的问题

**核心内容**：

- 传统无人机控制依赖遥控器或专业地面站，操作门槛较高。
- 多传感器数据分散：飞行状态、相机、深度、点云、检测结果往往分散在不同工具中。
- 任务执行链路不透明：用户难以知道系统是否完成了解析、安全检查、服务调用和执行验证。
- 二次开发困难：不同成员开发控制、感知、规划、前端时容易接口混乱。
- 未来真机迁移需要更清晰的模块边界和安全控制链路。

**建议视觉元素**：

左侧：传统链路：遥控器 / 命令行 / RViz 分散  
右侧：本项目链路：统一 Web 地面站 + 自然语言 Agent + ROS 2

### 第 4 页：系统总体架构

**标题**：系统总体架构：从自然语言到飞控执行

**建议画图**：

```text
用户 / 甲方操作员
        ↓
Web 地面站
        ↓ HTTP / WebSocket
ROS 网关
        ↓
LLM Agent ── 技能库 ── 安全检查 / 人工确认
        ↓
ROS 2 Topic / Service
        ↓
Control / Perception / Planning / Autonomy
        ↓
PX4 飞控 + AirSim / Gazebo / 真机
```

**讲解重点**：

- Web 前端与 ROS 解耦，Web 可以作为本地地面站运行。
- ROS 网关负责把浏览器请求转成 ROS 2 topic/service。
- Agent 负责自然语言解析和工具调用编排。
- PX4 负责最终飞控执行，保证底层飞行控制遵循成熟飞控架构。
- 感知、控制、规划、自主避障都是独立模块，便于替换和升级。

### 第 7 页：自然语言任务链路

**标题**：自然语言控制：从一句话到受控执行

**示例任务**：

```text
检查状态，如果安全就起飞到 10 米
```

**系统内部处理链路**：

1. 用户在 Web 控制台输入自然语言。
2. Agent 调用 DeepSeek / 本地模型进行意图解析。
3. 生成结构化任务：

```json
{
  "intent": "takeoff",
  "skill": "TakeoffSkill",
  "args": {"altitude": 10.0},
  "risk_level": "high",
  "need_confirm": true
}
```

4. Agent 执行飞控状态、安全条件、服务状态检查。
5. Web 控制台显示“等待用户确认”。
6. 用户点击确认执行。
7. Agent 调用 `/control/takeoff`。
8. Web 控制台展示执行进度和最终结果。

**讲解重点**：

大模型不直接控制无人机。大模型只负责“理解任务”和“选择技能”；真正执行由 Agent 的白名单工具完成，并且高风险任务需要人工确认。

### 第 9 页：安全执行机制

**标题**：安全机制：大模型参与决策，但不直接接管飞控

**安全设计**：

- **白名单工具调用**：Agent 只能调用已注册技能，不能随意发布飞控指令。
- **风险等级**：状态查询属于低风险；起飞、移动、返航、急停属于中高风险。
- **人工确认**：高风险任务先解析、检查，再等待用户确认。
- **起飞前检查**：检查飞控状态、EKF、定位、服务可用性、目标高度范围。
- **执行进度反馈**：Web 显示每一步是否完成，避免“命令发出但用户不知道结果”。
- **取消链路**：用户可取消自主任务，系统发布悬停零速度。
- **PX4 原生能力优先**：起飞、降落、返航等关键动作优先使用 PX4 成熟能力封装。

**建议视觉元素**：

用流程图展示：

```text
自然语言 → 解析 → 安全检查 → 等待确认 → 执行 ROS 服务 → 状态验证
```

### 第 11 页：目标搜索能力

**标题**：目标搜索：自然语言目标与视觉检测结果对齐

**当前实现**：

  - `检测person`
  - `检测前方有人吗`

- Agent 会将中文目标映射到 YOLO 类别：

- 系统过滤空类别和低置信度 detection，避免误判。

### 第 12 页：自主避障与路径执行框架

**标题**：底层自主避障：从控制命令走向自主飞行

**当前框架**：

系统已建立自主避障基础链路：

```text
深度 / 里程计 / 目标点
  → 局部地图与障碍物分析
  → 重规划策略选择
  → 平滑轨迹生成
  → /autonomy/trajectory
  → control_node 执行
```

**当前已实现的保护逻辑**：

- 自主目标发布：自然语言移动任务可生成 `/autonomy/goal`。
- 轨迹执行：控制节点订阅 `/autonomy/trajectory` 并执行。
- 速度限制：避免轨迹执行速度过大。
- 加速度平滑：减少无人机突然摇摆。
- 高度保护：避免持续前飞时掉高度。
- 任务结束逻辑：到达目标后进入悬停，不无限重复执行轨迹。
- 阻塞策略：障碍物过近时进入安全悬停。
- 取消任务：Web 或自然语言可取消自主任务。

**后续升级方向**：

最终目标是从当前基础版升级为：

```text
VIO / SLAM + ESDF 地图 + Kinodynamic Replanning + Minimum Snap Trajectory
```

### 第 13 页：仿真与真机迁移思路

**标题**：从仿真到真机：架构已预留迁移路径

**当前支持仿真模式**：

| 模式 | 特点 | 适用场景 |
|---|---|---|
| PX4 + SIH | 最轻量，无外部仿真器 | 飞控接口测试 |
| PX4 + Gazebo | 有 3D 仿真画面 | 基础飞行验证 |
| PX4 + AirSim | RGB、深度、LiDAR 传感器丰富 | 视觉感知与点云演示 |

**真机迁移思路**：

- PX4 飞控保持不变。
- ROS 2 节点可部署到机载计算机或伴随计算机。
- Web 地面站运行在地面电脑，通过网络访问 ROS 网关。
- 相机、深度相机、LiDAR 替换为真机传感器 topic。
- 控制接口仍走 `/control/*` 和 `/autonomy/*`，减少上层改动。

**讲解重点**：

前端和 ROS 已解耦。Web 地面站不是只能在仿真机上运行，后续可以作为真实无人机地面站使用。

### 第 18 页：当前限制与工程边界

**标题**：当前限制与下一阶段重点

**当前限制**：

- YOLO 使用通用 COCO 模型，只能识别人、车、公交车、自行车等常见类别。
- “红色目标”“特定型号车辆”“穿蓝衣服的人”等复杂语义目标，需要视觉语言模型或定制检测模型。
- 当前自主避障是基础工程链路，不是完整成熟的未知环境实时自主飞行系统。
- 当前定位主要依赖仿真里程计，真机需要接入 VIO / SLAM。
- 当前 Web 控制台主要用于演示和联调，后续还需要权限、日志落盘、任务回放、用户管理等工程功能。
- 真机飞行需要增加冗余安全策略，包括遥控器接管、地理围栏、失控保护、急停硬件链路。

**讲解方式建议**：

不要把限制讲成缺点，而是讲成“当前已经完成基础闭环，下一阶段进入工程增强和真机适配”。

## 3. 可直接放进 PPT 的一句话介绍

本项目构建了一套面向无人机任务执行的智能地面站系统，用户可以通过自然语言描述任务，系统自动完成任务解析、安全检查、人工确认、ROS 工具调用和 PX4 飞控执行，并在 Web 控制台实时展示飞行状态、相机画面、深度点云、目标检测和任务执行链路。

## 4. 可直接放进 PPT 的系统亮点

1. **自然语言任务控制**：支持“检测人”“起飞到10米”“生成任务报告”等自然语言输入。
2. **大模型 Agent 调度**：通过 DeepSeek / OpenAI-compatible 接口解析任务，并映射到系统技能。
3. **安全可控执行**：高风险动作需要人工确认，真实执行通过白名单 ROS 工具完成。
4. **Web 地面站**：统一展示飞行状态、相机、点云、检测、任务进度和日志。
5. **视觉感知**：支持 RGB、深度、LiDAR、YOLO 多目标检测。
6. **目标搜索**：中文目标可映射到视觉检测类别，例如“人”映射到 `person`。
7. **自主避障基础链路**：具备局部目标、轨迹生成、状态反馈和取消任务机制。
8. **可迁移架构**：前端、ROS 网关、飞控控制、感知规划解耦，便于未来真机部署。
