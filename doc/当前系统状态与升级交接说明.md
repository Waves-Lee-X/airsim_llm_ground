# 当前系统现状与升级交接说明

> 基线日期：2026-07-14  
> 当前决定：暂停新增升级，保留现有实现作为下一阶段开发基线。  
> 适用范围：ROS 2 Humble、PX4/AirSim、Web/飞书 Agent、多传感器感知和自主飞行模块。

---

## 1. 文档目的

本文档回答四个问题：

1. 当前系统已经真实实现了什么。
2. 哪些功能只是基础版或接口已经准备好。
3. 哪些能力尚未安装、联调或验证。
4. 后续恢复升级时应该从哪里开始。

本项目当前不是成熟真机自主无人机产品。它已经形成完整的软件架构和可运行基础链路，但真实 VIO/SLAM、成熟 ESDF/局部规划器、复杂环境回归和真机安全认证仍未完成。

## 2. 当前总体架构

```text
Web 地面站 / 飞书
        │ HTTP + WebSocket / 飞书长连接
        ▼
Agent Gateway
  ├── Claude Agent SDK Runtime
  ├── DeepSeek/Qwen OpenAI-compatible Runtime
  ├── SQLite 会话、事件、记忆和确认记录
  ├── Drone MCP 只读工具
  └── Confirmation Center + Workflow
        │ ROS /agent/execute_task
        ▼
ROS Agent / MissionManager
  ├── 技能选择与安全检查
  ├── Mission 状态机
  └── ROS 服务和自主目标发布
        │
        ├── Perception：RGB、Depth、LiDAR、YOLO、VLM
        ├── Autonomy：滚动体素、重规划、Minimum-Snap
        └── Control：PX4 原生命令和 Offboard 轨迹执行
                │
                ▼
              PX4
```

设计原则：大模型负责理解、查询、拆解、编排和解释；确定性 ROS/PX4 模块负责安全检查、轨迹、控制闭环和物理完成验证。

## 3. 已完成且代码真实存在的能力

### 3.1 多模型 Agent 与多端对话

- Claude Agent SDK 流式多轮会话。
- DeepSeek、Qwen 等 OpenAI-compatible Runtime。
- WebSocket 增量回复、工具调用和错误事件。
- SQLite 保存会话、消息、事件、Provider、模型和 Claude session ID。
- Web 与飞书显式身份绑定、统一时间线和跨端任务状态。
- 有界滚动记忆和可治理的长期语义记忆。
- 飞书私聊文本、确认卡片、图片下载和 VLM 分析。
- Web 断线重连后恢复历史、待确认任务和近期 Mission。

核心目录：

```text
src/aeromind_agent_gateway/
src/aeromind_agent/
src/aeromind_web/
```

### 3.2 受控无人机工具和人工确认

- 模型可以读取飞控状态、里程计、感知摘要、检测结果和自主状态。
- 模型不能使用 Bash、任意文件写入或直接发布 PX4 控制消息。
- 解锁、加锁、起飞、降落、移动、悬停和 RTL 均创建持久化确认请求。
- 确认记录绑定用户和会话，支持过期、越权拒绝和幂等。
- 确认后复用 ROS Agent 的安全检查和 MissionManager。
- Gateway 区分“ROS 已受理”和“物理动作已经完成”。
- 起飞、降落、移动、RTL 等动作通过飞控、里程计和自主状态继续验证。

### 3.3 通用 Workflow 与模块化技能

- 单个 Workflow 最多 20 步。
- 支持前序依赖、执行条件、失败停止/继续和最多两次重试。
- 支持暂停、恢复和取消。
- 支持 `safety_check`、`perception_check` 和飞行白名单动作。
- 整套 Workflow 只产生一次高风险人工确认。
- 进程重启后，执行中的 Workflow 标记为 `interrupted`，不会自动续飞。
- 已实现 `flight.square` 正方形轨迹技能。
- 团队成员可通过 `AEROMIND_GATEWAY_SKILL_MODULES` 注册独立技能模块。
- Gateway `/api/skills`、模型 `list_skills` 与 Web 技能库共用目录。

核心文件：

```text
src/aeromind_agent_gateway/aeromind_agent_gateway/workflow.py
src/aeromind_agent_gateway/aeromind_agent_gateway/skill_registry.py
src/aeromind_agent_gateway/aeromind_agent_gateway/confirmation.py
src/aeromind_agent_gateway/aeromind_agent_gateway/ros_state.py
```

### 3.4 感知与任务报告

- AirSim RGB、Depth 和 LiDAR 桥接。
- RGB/Depth CameraInfo。
- YOLO 检测节点和 `/perception/detections`。
- 手动截图、任务目录归档、报告下载和 Web 缩略图。
- Qwen3-VL-Plus 等 OpenAI-compatible VLM 图像分析。
- VLM 自动低频分析和目标语义搜索基础链路。
- `PerceptionSkill`、`MissionReportSkill`、`HoverSkill`、`CaptureImageSkill`、`TargetSearchSkill` 等基础技能。

注意：目标检测效果取决于模型、类别、输入颜色、置信度和真实相机数据。当前不能把 YOLO/VLM 结果作为唯一飞行安全依据。

### 3.5 PX4 控制链路

- PX4 原生 arm、disarm、takeoff、land 和 RTL。
- Offboard 位置/速度 setpoint。
- `/autonomy/trajectory` 已接入 `control_node` 执行。
- 轨迹速度限幅、加速度平滑和最低高度保护。
- 起飞、降落与自主轨迹控制互斥。
- 到达、阻塞、悬停和取消的终止逻辑。

### 3.6 当前自主避障基础

当前已实现：

- 深度点转换到相机 optical frame，再通过 TF 转换到里程计世界坐标系。
- 使用 CameraInfo 内参，不再只依赖固定 FOV。
- 世界坐标滚动体素地图。
- 深度射线内部清障、障碍时间衰减和地图半径裁剪。
- 里程计位姿跳变后清空局部地图。
- 动力学受限角度扇区运动基元。
- 优先选择通过 clearance 校验的安全轨迹。
- 侧绕、爬升、恢复点和安全悬停策略。
- 七次单段 Minimum-Snap 轨迹。
- 里程计/深度超时后进入 `SENSOR_WAIT`，禁止盲飞。
- VIO/SLAM 里程计有限值、四元数和协方差质量门控。
- 可选接收世界坐标注册 `PointCloud2`。
- 发布 `/autonomy/esdf_obstacles` 供 RViz 检查实际障碍地图。

这部分是可运行基础，不是成熟 EGO-Planner/Fast-Planner/Voxblox/nvblox 的等价实现。

### 3.7 当前 TF 与坐标约定

PX4 和 AirSim Bridge 当前统一对外发布 ROS ENU 坐标：

```text
X：东
Y：北
Z：上
```

TF 树：

```text
odom
└── base_link
    ├── camera_front_center_body
    │   └── camera_front_center_optical
    └── lidar
```

- `odom -> base_link` 为动态里程计 TF。
- 相机和 LiDAR 外参为静态 TF。
- optical frame 遵循 ROS：Z 前、X 右、Y 下。
- 自主目标、注册点云和里程计必须使用一致的世界 frame。

## 5. 尚未完成的能力

### 5.1 真实 VIO/SLAM 未部署

当前未安装或运行：

- OpenVINS
- RTAB-Map
- ORB-SLAM3
- Isaac ROS Visual SLAM

当前 `/sensor/odometry` 主要来自 PX4/AirSim，而不是由相机和 IMU 计算得到的 VIO。

虽然 Autonomy 已提供以下接入口，但这不等于 VIO 已经完成：

```text
autonomy_odom_topic
autonomy_world_cloud_topic
```

### 5.2 传感器频率和标定未达到 VIO 条件

当前观察到相机约 0.6 Hz，无法支持可靠 VIO。后续通常需要：

- RGB/双目图像约 20～30 Hz。
- IMU 约 100～200 Hz。
- 相机和 IMU 硬件或软件时间同步。
- 相机内参、畸变、相机-IMU 外参和 IMU 噪声标定。
- ROS Bag 离线验证数据集。

### 5.3 成熟 ESDF 后端未接入

当前是自研滚动体素和在线 clearance 查询，未接入：

- Voxblox
- FIESTA
- nvblox

当前实现适合验证接口和基础避障逻辑，但不是高性能预计算 ESDF。

### 5.4 成熟局部规划器未接入

当前未接入：

- EGO-Planner
- Fast-Planner
- 完整 Kinodynamic A*
- 多段 Minimum-Snap/B-spline 全局优化

当前运动基元可以处理部分简单障碍，但不能保证通过复杂树林、凹形障碍、窄通道或动态人群。

### 5.5 真机安全能力未完成

尚未完整实现或验收：

- 三维地理围栏和禁飞区。
- 最大任务高度和任务区域硬限制。
- 独立于 Agent 的安全监督节点。
- RC/遥控器人工接管优先级。
- 急停全链路验证。
- 模型、网络、VIO、深度和 DDS 故障注入。
- 真机权限、证书、端口和部署隔离。
- 飞行日志自动回放和验收报告。

### 5.6 端到端任务尚未完成场景验收

尚未系统验证：

- 正方形 Workflow 完整飞行。
- 连续树木绕行。
- 窄通道穿越。
- 动态障碍物避让。
- VIO 丢失后悬停和恢复。
- Web/飞书断线期间任务安全状态。
- 长时间运行的内存、延迟和数据库增长。

## 6. 当前启动基线

每个新终端都必须加载 ROS 和工作空间：

```bash
cd ~/aeromind_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

启动 PX4/AirSim ROS 主系统：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py
```

启动 Web 与 Agent Gateway：

```bash
ros2 launch aeromind_bringup aeromind_web.launch.py \
  port:=8080 agent_port:=8090 \
  agent_provider:=claude agent_model:=sonnet
```

DeepSeek 示例：

```bash
export DEEPSEEK_API_KEY="你的密钥"
ros2 launch aeromind_bringup aeromind_web.launch.py \
  port:=8080 agent_port:=8090 \
  agent_provider:=deepseek agent_model:=deepseek-chat
```

启动 RViz 深度和 ESDF 障碍地图：

```bash
ros2 launch aeromind_bringup aeromind_vision.launch.py
```

地址：

```text
Web:           http://localhost:8080
Agent health:  http://localhost:8090/health
Agent WS:      ws://localhost:8090/ws/agent
```

SQLite 默认位置：

```text
~/.aeromind/agent_gateway.db
```

API Key、飞书密钥和 Agent Token 只通过环境变量设置，不应提交到仓库。

## 8. 当前重要参数

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `autonomy_velocity_limit` | 1.2 | 自主速度上限，m/s |
| `autonomy_accel_limit` | 0.8 | 自主加速度变化上限，m/s² |
| `autonomy_min_altitude` | 1.0 | 最低高度保护，m |
| `autonomy_map_radius_m` | 24.0 | 滚动地图半径，m |
| `autonomy_map_decay_sec` | 4.0 | 障碍体素保留时间，s |
| `autonomy_odom_timeout_sec` | 1.0 | 里程计超时阈值，s |
| `autonomy_depth_timeout_sec` | 3.5 | 深度/注册点云超时阈值，s |
| `autonomy_max_position_variance` | 2.0 | 位置协方差拒绝阈值 |
| `autonomy_max_orientation_variance` | 0.5 | 姿态协方差拒绝阈值 |
| `autonomy_odom_topic` | `/sensor/odometry` | 定位输入 |
| `autonomy_world_cloud_topic` | 空 | 世界坐标注册点云输入 |

真实飞行前不能只复制默认参数。速度、加速度、安全半径、地图衰减、最低高度和协方差阈值都需要根据机体、传感器和环境重新标定。

## 9. 已知风险和使用限制

1. 当前相机频率不足以支持可靠 VIO。
2. 当前 ESDF-style 地图不是成熟 ESDF 库。
3. 当前规划器没有全局拓扑搜索，复杂障碍可能进入 `BLOCKED_HOLD`。
4. VLM 和 YOLO 是语义辅助，不是飞行安全传感器。
5. Workflow 暂停会取消自主移动；PX4 原生起飞、降落和 RTL 仍由飞控完成安全状态转换。
6. Gateway 重启不会自动恢复未完成飞行任务。
7. AirSim、PX4、ROS 和 Web 使用不同进程，任一链路中断都必须观察状态，不应只根据服务返回判断成功。
8. 当前未完成真机网络安全、权限隔离和安全认证。

## 10. 后续恢复升级的推荐顺序

### 第一阶段：建立可重复数据集

1. 提升 AirSim RGB/Depth 和 IMU 发布频率。
2. 检查 CameraInfo、TF 和时间戳。
3. 录制相机、深度、IMU、PX4 Odometry 和 TF 的 ROS Bag。
4. 建立静止、直线、转弯、绕树和窄通道数据集。

### 第二阶段：部署真实定位器

1. 优先使用独立工作空间或容器安装 RTAB-Map/OpenVINS。
2. 先离线播放 ROS Bag，不立即控制无人机。
3. 对比 VIO 和 PX4/AirSim 真值轨迹。
4. 验证初始化、漂移、协方差、丢失和恢复。
5. 输出标准 `nav_msgs/Odometry` 和连续 TF。

接入现有 Autonomy：

```bash
ros2 launch aeromind_bringup aeromind_px4.launch.py \
  autonomy_trajectory_execution:=false \
  autonomy_odom_topic:=/vio/odometry \
  autonomy_world_cloud_topic:=/slam/registered_cloud
```

先关闭轨迹执行，仅观察 `/autonomy/status`、TF 和 `/autonomy/esdf_obstacles`。

### 第三阶段：成熟建图和局部规划

1. 根据计算平台选择 Voxblox/FIESTA/nvblox。
2. 建立统一 ESDF 查询适配层。
3. 接入 EGO-Planner/Fast-Planner 或多段轨迹优化。
4. 完成碰撞连续检查、动态障碍预测和重规划性能测试。

### 第四阶段：真机安全和验收

1. 独立 Safety Supervisor。
2. 地理围栏、禁飞区、速度/高度硬限制。
3. RC 接管、急停和 failsafe。
4. 网络、模型、传感器和定位故障注入。
5. 仿真通过后再进行系留、低高度和空旷场地测试。

## 12. 当前结论

项目目前已经具备“大模型任务理解和编排 + ROS 确定性执行 + PX4 控制 + 感知展示 + 基础三维局部避障”的完整软件骨架。

当前最有价值的成果是各层接口已经连接，并建立了确认、状态、物理验证、TF、世界坐标地图和安全悬停边界。当前最大的不足不是缺少更多界面按钮或更多自然语言规则，而是缺少高频同步传感器、真实 VIO/SLAM、成熟 ESDF/局部规划器，以及系统化仿真和真机验收。

后续升级应从数据集和真实定位器开始，不应直接跳到真机自主飞行。
