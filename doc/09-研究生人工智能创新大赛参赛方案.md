# 第八届中国研究生人工智能创新大赛参赛方案

> 编制日期：2026-07-16  
> 依据：大赛初赛作品提交规范与项目文档模板  
> 初赛截止：2026-09-01 23:59

## 1. 参赛判断

本项目适合以“多模态具身智能无人机任务系统”参加大赛。它已经具备可运行原型、真实 ROS 2/PX4 执行链、多模态感知、自然语言任务编排、安全确认和跨端交互，不只是概念方案。

当前具备参赛基础，但不能只以“功能展示”提交。大赛明确要求论证创新性、对比已有工作、体现 AI 推理效果和指标，并说明数据、算法、硬件及借鉴来源。因此，后续工作的中心应从继续堆功能转向：

1. 冻结一个稳定演示版本。
2. 建立可重复实验集和量化指标。
3. 证明大模型相对规则系统带来的任务能力提升。
4. 明确研究原型边界，不把尚未完成的真机能力写成成果。

## 2. 推荐项目定位

### 2.1 推荐名称

**智航灵枢：面向复杂任务的多模态具身智能无人机系统**

可选名称：

- 面向开放任务的多模态智能无人机指挥与自主执行系统
- 基于大模型与 ROS 2 的无人机具身智能任务平台
- 自然语言驱动的无人机感知、规划与安全执行系统

### 2.2 一句话定义

系统将开放自然语言转化为受约束、可确认、可执行、可验证的无人机任务，并融合飞控遥测、目标检测、视觉语言理解和空间感知完成任务级自主决策。

### 2.3 核心问题

传统无人机地面站要求操作员掌握飞行模式、坐标、航点和多个软件接口；普通大模型控制方案又容易出现指令幻觉、执行不可验证和高风险动作失控。本项目研究如何让大模型参与无人机任务理解、感知解释和流程规划，同时由确定性系统守住实时控制与安全边界。

## 3. 建议聚焦的三项创新

### 3.1 证据驱动的多模态任务 Agent

LLM 不仅解析一句命令，还可以按需读取飞控状态、里程计、深度、点云、YOLO 检测和 VLM 语义结果，将传感器事实、模型推断和操作建议组织为可追溯结论。

创新论证重点：

- 相比纯规则地面站，支持开放表达和复杂条件任务。
- 相比把图像直接交给模型，增加几何距离、飞控状态和数据新鲜度证据。
- 相比单轮工具调用，支持多步骤任务、状态反馈和任务报告。

### 3.2 大模型规划与确定性安全执行解耦

系统采用 Capability、Skill、Workflow 三层任务模型。大模型负责高层分解和组合，能力注册表负责参数约束，确认中心负责高风险授权，ROS 2/PX4 负责执行，遥测负责验证物理结果。

创新论证重点：

- 模型不能直接生成电机控制量或调用未注册动作。
- 高风险动作采用持久化、幂等、用户绑定的两阶段确认。
- “服务返回成功”不等于任务完成，必须等待高度、模式或位置证据。
- 明确命令通过确定性路由快速执行，复杂长尾任务由 LLM 规划。

### 3.3 面向无人机任务的闭环智能编排

大模型可将飞行、感知、拍照、视觉分析和报告组合为 Workflow，并根据条件分支选择后续动作。例如“发现人员则悬停拍照，否则继续巡检”。

创新论证重点：

- 从“语言控制一个动作”提升为“语言生成可执行任务图”。
- 支持步骤依赖、条件、重试、暂停、取消和失败原因。
- 任务产物与执行证据自动归档，可用于审计和经验积累。

> 自主避障、Minimum Snap 和 PX4 控制是重要工程基础，但不建议单独包装为大模型创新。它们是保证智能任务能够真实落地的确定性执行底座。

## 4. 必须完成的量化实验

### 4.1 自然语言任务推理数据集

建立至少 120 条中文任务：基础查询 30 条、明确飞行动作 30 条、多步骤组合任务 30 条、歧义/越界/缺失能力/恶意指令 30 条。每条标注正确意图、参数、工具、风险等级、是否确认和期望 Workflow。

| 指标 | 含义 | 建议目标 |
|---|---|---:|
| 意图准确率 | 是否选择正确能力/技能 | >= 95% |
| 参数准确率 | 高度、距离、方向、目标类别 | >= 90% |
| Workflow 步骤正确率 | 步骤、依赖和顺序是否正确 | >= 85% |
| 风险识别召回率 | 高风险任务是否进入确认 | 100% |
| 越界拦截率 | 非法参数和未注册能力是否被拒绝 | 100% |
| 平均规划延迟 | 输入到结构化计划生成 | 给出实测值 |

### 4.2 消融与对比实验

比较四种方案：

1. 仅规则解析器。
2. 仅 LLM 自由规划。
3. LLM + 能力 Schema。
4. 完整方案：混合路由 + Skills/Workflow + 确认 + 遥测验证。

比较任务覆盖率、计划正确率、危险动作拦截率、执行成功率和延迟。这是证明 Agent 架构价值的核心证据。

### 4.3 VLM/YOLO 推理实验

建立固定图像集或 Rosbag，包含人员、车辆、道路、建筑、植被、低照度和空场景。

- YOLO：Precision、Recall、mAP50、平均推理时延。
- VLM：目标/场景描述正确率、风险判断准确率、幻觉率、平均响应时延。
- 融合方案：相比仅 VLM，加入 YOLO、深度和点云后风险判断错误率是否降低。

VLM 评价应采用人工标注答案或明确评分规则，不能只展示几段“看起来合理”的文本。

### 4.4 系统闭环实验

固定 AirSim 场景，对状态检查后起飞、前进悬停拍照分析、人员条件巡检、安全降落以及模型/传感器/Web 断线降级等任务分别重复执行至少 20 次。

建议统计：端到端任务成功率、平均任务耗时、物理完成验证正确率、最小障碍距离、轨迹跟踪误差、异常响应时间和报告完整率。

## 5. 技术调研与对比方向

项目文档至少应对比以下类别，最终引用原始论文、官方文档或项目仓库：

- 传统无人机地面站：QGroundControl、Mission Planner。
- ROS/PX4 自主飞行框架：MAVROS/PX4 ROS 2、XTDrone 等。
- 无人机自主规划：Fast-Planner、EGO-Planner、FUEL 等。
- 具身 Agent/机器人 LLM：SayCan、Code as Policies、PaLM-E、RT-2 等。
- 视觉语言模型与开放词汇感知：Qwen-VL、Grounding DINO、SAM 类方案。

统一对比自然语言开放性、多模态证据、任务组合、安全确认、物理完成验证、跨端操作、仿真/真机迁移和可审计性。

## 6. 五分钟初赛视频结构

附件要求视频不超过 5 分钟、MP4、不超过 200 MB。现有约 7 分钟脚本需要压缩。

| 时间 | 内容 | 展示重点 |
|---|---|---|
| 0:00-0:25 | 问题与方案 | 地面站操作复杂、LLM 幻觉与安全风险 |
| 0:25-0:50 | 系统架构 | PX4/AirSim、ROS 2、Gateway、Web/飞书四层 |
| 0:50-1:25 | 多模态状态分析 | 工具调用、RGB/深度/点云证据、风险建议 |
| 1:25-2:15 | 安全起飞闭环 | 路由、确认、ROS 服务、PX4 与遥测验证 |
| 2:15-3:35 | 复杂组合任务 | 前进、悬停、拍照、VLM、Workflow |
| 3:35-4:15 | AI 效果与指标 | 准确率、拦截率、成功率和推理延迟 |
| 4:15-4:40 | 飞书与报告 | 白名单跨端操作、截图与报告 |
| 4:40-5:00 | 安全结束 | 优先展示稳定降落并总结价值 |

RTL 只有在 AirSim-PX4 链路稳定后才进入正式视频，否则使用原生降落收尾。视频中必须加入实验指标，不能只有 UI 操作。

## 10. 当前最高优先级

1. 不再新增大而不稳的功能，先冻结参赛演示链。
2. 把现有约 7 分钟视频剪成 5 分钟，并加入约 25 秒指标画面。
3. 建立 120 条自然语言任务集和四组 Agent 对比实验。
4. 建立固定视觉样本与 VLM/YOLO 评价规则。
5. 重复运行起飞、移动、拍照、分析、降落闭环，形成成功率统计。
6. 解决 AirSim-PX4 RTL 断链后再决定是否保留 RTL 演示。
7. 开始按附件 2 编写正式项目文档，而不是直接复制仓库 README。

## 11. 真实性表述边界

可以表述：

- 已实现 ROS 2/PX4 仿真闭环和真实工具调用。
- 已实现 LLM 任务规划、VLM 图像理解和确定性安全约束。
- 已实现多步骤 Workflow、人工确认和遥测完成验证。
- 架构支持迁移真机，正在进行安全和定位模块升级。

不能表述：

- 已完成复杂未知环境真机自主飞行。
- 大模型直接完成实时姿态控制或自主避障。
- 当前局部地图等同于成熟工业 ESDF 系统。
- 单次演示成功可以代表算法稳定性或普适性。

评审更容易认可边界清楚、指标真实、创新有证据的研究原型，而不是功能描述很多但无法复现实验的“完整产品”。
