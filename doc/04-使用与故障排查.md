# 使用与故障排查

本文面向日常操作和演示。开始前应按 [安装配置与启动](03-安装配置与启动.md) 启动 PX4、DDS Agent、ROS 主系统和 Web。

## 0. 起飞安全与任务互斥

安全起飞不再直接使用包含地面点的全方向最近障碍距离。Autonomy 会基于前视深度融合的 ESDF，在机体附近建立起飞柱状区域，过滤低于机体一定高度的地面点，并发布：

- `takeoff_clearance_valid`：净空证据是否新鲜可用。
- `takeoff_clearance_m`：起飞区域内最近有效障碍距离。
- `takeoff_clearance_source`：证据来源，当前为 `front_depth_esdf_ground_filtered`。

安全起飞 Workflow 必须使用这项证据。证据缺失或距离小于阈值都会停止任务。该检查只代表当前前视深度/ESDF 覆盖的起飞区域，不等同于真正的全向上视传感器；真机部署仍建议增加上视深度或全向 LiDAR。

Gateway 同时启用任务互斥：已有待确认或执行中的任务时，新的起飞、移动、返航和普通 Workflow 会被拒绝。降落或悬停属于安全抢占动作，会先取消正在执行的 Workflow，再创建新的确认请求。

## 1. 一分钟检查

```bash
source /opt/ros/humble/setup.bash
source ~/aeromind_ws/install/setup.bash

ros2 topic echo /control/drone_state --once
ros2 topic echo /sensor/odometry --once
ros2 topic hz /sensor/camera/rgb/front_center
ros2 topic echo /autonomy/status --once
ros2 service list | rg '/control|/perception'
```

检查目标：

- `DroneState` 持续更新，模式、解锁、GPS、EKF 字段合理。
- `/sensor/odometry` 不是停止的旧消息。
- 使用视觉功能时，RGB/Depth Topic 有稳定频率。
- `/control/takeoff`、`/control/land`、`/control/return_home` 已就绪。
- 自主飞行前，`AutonomyStatus` 不处于传感器超时状态。

## 2. Web 地面站

默认地址：

```text
ROS Web 网关：http://localhost:8080
Agent Gateway：http://localhost:8090
独立前端：http://localhost:5173
```

界面主要区域：

| 区域 | 用途 |
|---|---|
| 飞行状态 | 解锁、模式、高度、电压、GPS、EKF、速度 |
| 对话区 | 多轮任务、流式回复、人工确认 |
| 任务态势 | 当前 Workflow、Mission 状态、暂停/恢复/取消 |
| 感知区 | RGB、深度、Three.js 点云、检测结果、态势地图 |
| 能力库 | 基础能力与组合技能 |
| 日志 | WebSocket 状态、工具调用、错误和物理完成反馈 |

Web 页面关闭不会自动停止后端。浏览器强制刷新可使用 `Ctrl+Shift+R`；静态前端端口仍被占用时，先检查对应进程而不是重复启动。

## 3. ROS 基础控制

### 3.1 解锁与加锁

```bash
ros2 service call /control/arm aeromind_interfaces/srv/ArmDrone "{arm: true}"
ros2 service call /control/arm aeromind_interfaces/srv/ArmDrone "{arm: false}"
```

### 3.2 起飞、降落与返航

```bash
ros2 service call /control/takeoff aeromind_interfaces/srv/Takeoff "{altitude: 10.0}"
ros2 service call /control/land aeromind_interfaces/srv/Land "{}"
ros2 service call /control/return_home aeromind_interfaces/srv/ReturnHome "{}"
```

起飞和降落的 Service 返回表示控制节点已受理。物理完成应继续观察 `armed`、`mode`、高度和垂直速度。返航使用 PX4 原生 RTL，由 PX4 按 home 点和 RTL 参数执行。

### 3.3 单个自主目标

目标坐标单位是米，frame 默认为 `odom`：

```bash
ros2 topic pub --once /autonomy/goal geometry_msgs/msg/PoseStamped "{
  header: {frame_id: 'odom'},
  pose: {
    position: {x: 10.0, y: 0.0, z: 10.0},
    orientation: {w: 1.0}
  }
}"
```

这是世界坐标绝对目标，不是“机头前方 10 米”。自然语言相对方向需要根据当前航向换算后再发布。

取消：

```bash
ros2 topic pub --once /autonomy/cancel std_msgs/msg/Empty "{}"
```

### 3.4 多航点 Action

Action 名称：

```text
/autonomy/follow_waypoints
```

查看定义和状态：

```bash
ros2 interface show aeromind_interfaces/action/FollowWaypoints
ros2 action info /autonomy/follow_waypoints
```

通常通过 Agent Workflow 调用该 Action；手工测试前先阅读接口字段并确认 frame、起飞状态和航点高度。

## 4. 自然语言任务

推荐表达清楚目标、条件和结束行为：

```text
检查飞控和前方障碍，如果安全就起飞到 10 米。
向左飞 20 米，到达后悬停并拍照。
巡检前方区域，发现人就悬停拍照，否则继续前进 20 米。
飞一个宽 10 米、深 10 米的 V 字形，在顶点拍照，完成后返航。
```

高风险任务的正确流程：

```text
用户任务
→ Gateway 创建真实确认请求
→ Web 显示确认卡片
→ 用户确认
→ Workflow/ROS 执行
→ 遥测验证物理完成
→ 对话和任务态势更新
```

模型文本中自己编写的 `confirm-...` 不是有效确认。只有 Confirmation Center 持久化创建的请求才会出现在 Web，并能被“确认执行”消费。

## 5. 相机、检测和 VLM

### 5.1 检查 RGB

```bash
ros2 topic hz /sensor/camera/rgb/front_center
ros2 topic echo /sensor/camera/rgb/front_center --once
```

应满足 `step = width × 每像素字节数`，`data` 长度应约等于 `height × step`。不要把 JPEG 压缩字节伪装成 `rgb8/bgr8` 原始 Image，否则 RViz 和 republish 会报告尺寸错误。

### 5.2 保存图片

```bash
ros2 service call /perception/capture_image \
  aeromind_interfaces/srv/CaptureImage "{label: front_rgb}"
```

图片默认保存到 `missions/captures/` 或当前 Mission 的 `captures/`。PNG 是常用无损格式；旧 PPM 是早期无 OpenCV 编码兜底，不再是推荐输出。

### 5.3 分析图片

```bash
ros2 service call /perception/analyze_image \
  aeromind_interfaces/srv/AnalyzeImage \
  "{prompt: '仅根据当前图像列出可见物体、方位、障碍和不确定信息', use_vlm: true}"
```

VLM 是低频语义分析：节点将当前 RGB 编码后调用 OpenAI-compatible Vision API，再发布结构化分析结果。它可以通过更具体的 Prompt 分析物体、颜色、数量、道路、建筑、植被和风险，但距离只能是图像推测，精确距离必须来自深度或点云。

### 5.4 YOLO 关闭后仍有检测框

常见原因：

1. 前端保留了最后一次检测结果。
2. `/perception/detections` 仍有其他发布者。
3. Web 网关缓存没有设置过期时间。

检查：

```bash
ros2 topic info /perception/detections -v
```

关闭 YOLO 后应让前端按时间戳清除过期框，而不是继续展示历史 detection。

## 6. 点云与自主避障

Web 中点云工具条通常控制点大小、颜色方式、视角和采样量。它只影响显示，不修改规划器地图。

RViz 检查：

```bash
rviz2 -d ~/aeromind_ws/install/aeromind_bringup/share/aeromind_bringup/launch/depth_cloud.rviz
```

规划器实际使用的障碍数据：

```bash
ros2 topic echo /autonomy/status
ros2 topic hz /autonomy/esdf_obstacles
```

没有真实障碍却反复触发侧绕或 `safe_hover`，应检查：

- 深度最小/最大阈值是否把噪声当成障碍。
- CameraInfo 和 TF 是否正确。
- 旧体素是否正常衰减和清除。
- 无人机自身、地面或树叶稀疏点是否进入安全半径。
- 轨迹安全半径是否大于场景通道宽度。
- 里程计是否跳变，导致旧障碍留在错误世界位置。

## 7. 常见故障

### 7.1 Package not found 或消息类型 invalid

```bash
source /opt/ros/humble/setup.bash
source ~/aeromind_ws/install/setup.bash
ros2 pkg prefix aeromind_bringup
```

修改 `msg/srv/action` 后必须重新构建并重新 source。

### 7.2 PX4 没有 ROS 数据

检查 DDS Agent 是否显示客户端连接，并执行：

```bash
ros2 topic list | rg '^/fmu/'
ros2 topic hz /fmu/out/vehicle_odometry
```

若没有数据，检查 UDP 8888、PX4 uXRCE Client 和 ROS Domain 配置。

### 7.3 电池显示 0 或 EKF 异常

先区分 PX4 本身和 Bridge 映射：

```text
PX4 Console: listener battery_status
ROS: ros2 topic echo /fmu/out/battery_status --once
ROS: ros2 topic echo /control/drone_state --once
```

PX4 电压正常但 `DroneState` 为 0，说明桥接节点订阅字段、QoS 或单位映射存在问题，不应由 LLM 推断为真实没电。EKF 同理，应使用 PX4 estimator/status 的明确字段，而不是用 GPS fix 或是否有里程计简单替代。

### 7.4 无人机不能起飞

检查顺序：

1. `/control/takeoff` 服务是否存在。
2. PX4 是否收到 arm/mode/setpoint。
3. `DroneState` 是否变为 `armed=true` 和 `OFFBOARD/AUTO_TAKEOFF`。
4. 起飞 setpoint 是否持续发送，而不是只发一次。
5. 自主轨迹悬停逻辑是否错误覆盖起飞控制。
6. PX4 Console 的 preflight/commander 拒绝原因。

`SENSOR_WAIT` 应阻止自主移动，但不应无条件覆盖控制节点内部正在进行的安全起飞序列。

### 7.5 `SENSOR_WAIT` 或里程计超时

```bash
ros2 topic hz /sensor/odometry
ros2 topic hz /sensor/camera/depth/front_center
ros2 topic echo /autonomy/status --once
```

确认时间戳持续前进、Topic 名与 Launch 参数一致、协方差没有超过门控阈值。

### 7.6 服务实际完成但界面显示超时

服务调用和物理任务的时间尺度不同。正确实现应在 ROS 请求受理后立即返回“已下发”，再通过 WebSocket/Mission 状态异步确认完成。不要用一个短 HTTP 超时等待起飞、降落或截图落盘的全部过程。

### 7.7 Workflow 卡在某一步

同时检查：

```bash
ros2 topic echo /autonomy/status
ros2 action info /autonomy/follow_waypoints
```

常见原因包括完成事件丢失、Action 结果未转发、截图 Service 响应超时、目标被新的任务覆盖或前端只更新了日志但没有更新步骤状态。

### 7.8 VLM 401

```bash
test -n "$AEROMIND_VLM_API_KEY" && echo loaded
printf '%s\n' "$AEROMIND_VLM_API_URL"
printf '%s\n' "$AEROMIND_VLM_MODEL"
```

确认 API URL、Key、模型和区域属于同一平台。VLM 失败应降级为规则/检测摘要，但回调异常不能让 Agent 节点退出。

### 7.9 端口占用

```bash
ss -ltnp | rg ':8080|:8090|:5173'
```

停止旧进程或换端口。关闭浏览器标签页不会停止 Python HTTP Server、ROS 网关或 Agent Gateway。

## 8. 安全停止

正常结束优先使用降落或 RTL，确认落地加锁后再停止 ROS/PX4。自主任务异常时先取消并悬停：

```bash
ros2 topic pub --once /autonomy/cancel std_msgs/msg/Empty "{}"
```

真机紧急策略必须由独立安全监督和遥控器/飞控 failsafe 保证，不能依赖 Web、LLM 或云端网络。
