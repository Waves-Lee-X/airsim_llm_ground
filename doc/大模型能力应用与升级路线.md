# 大模型能力应用与升级路线

> 适用场景：客户汇报、项目答辩、团队技术说明和后续研发规划。
> 项目定位：自然语言驱动、视觉语义增强、具备安全确认和自主执行能力的智能无人机任务系统。

---

## 1. 核心结论

本项目不是简单地把大模型接入聊天窗口，也不是让大模型直接控制电机。系统采用分层设计：

```text
大模型负责：理解、规划、语义分析、工具选择、解释和报告
确定性系统负责：校验、确认、任务状态机、定位、避障、轨迹和控制
PX4 负责：状态估计、姿态控制、执行器控制和飞行保护
```

项目当前已经形成以下闭环：

```text
自然语言任务
  -> LLM 或确定性路由解析
  -> Skill / Tool / Workflow
  -> 风险校验与人工确认
  -> ROS 2 感知、规划和控制
  -> PX4 执行
  -> 遥测验证
  -> 任务报告与多轮对话
```

因此，本项目体现的是“大模型驱动任务智能”，而不是“大模型替代飞控”。

## 2. 系统中的模型分工

### 2.1 语言模型 LLM

当前可通过 OpenAI-compatible 接口使用 DeepSeek 等模型，主要承担：

- 理解自由形式的中文任务。
- 从自然语言中提取目标、距离、高度、方向和约束。
- 将复杂任务拆成多个可执行步骤。
- 根据上下文理解“继续”“拍下来”“回去”等省略表达。
- 选择合适的 Skill 和 ROS Tool。
- 解释当前飞行状态、失败原因和风险。
- 汇总任务过程并生成自然语言报告。

### 2.2 视觉语言模型 VLM

当前已经接入 Qwen3-VL-Plus，主要承担：

- 开放类别场景理解。
- 识别 YOLO 类别集合之外的物体和环境语义。
- 描述物体数量、颜色、相对方位和大致远近。
- 分析道路、地形、建筑、植被、人员和车辆。
- 判断可通行区域、潜在风险、光照和画面质量。
- 明确指出视觉不确定信息。
- 为目标搜索、巡检和任务报告提供语义证据。

### 2.3 YOLO 与传统感知

YOLO、深度图和点云不属于大模型，但它们为大模型提供可靠的实时数据基础：

- YOLO：实时检测已知类别，输出边界框和置信度。
- 深度相机：提供像素级距离。
- LiDAR/点云：提供环境几何结构。
- VLM：解释“画面里是什么、意味着什么”。

合理组合是：YOLO 负责快速定位，深度和点云负责几何测量，VLM 负责开放语义理解。

## 3. 大模型在当前项目中的真实调用链

### 3.1 自然语言控制链

```text
Web / 飞书输入任务
  -> Agent Gateway
  -> 确定性白名单路由或 LLM Runtime
  -> 生成结构化 action / workflow
  -> Confirmation Center
  -> ROS Agent
  -> Control / Autonomy / Perception
  -> PX4
```

明确的高风险控制命令，例如起飞、降落、RTL、正方形和 V 字轨迹，可以由确定性路由直接识别。这类任务不调用语言模型解析，以降低延迟和误判概率。

开放表达、复杂条件、多轮上下文和无法被规则覆盖的任务才进入语言模型。两者共同构成混合 Agent 架构。

### 3.2 VLM 图像分析链

```text
用户：详细分析当前画面
  -> Agent 选择 SemanticImageSkill
  -> 调用 /perception/analyze_image
  -> perception_node 获取最新 RGB 图像
  -> 图像转换为 PNG 和 Base64
  -> 请求 Qwen3-VL-Plus /chat/completions
  -> VLM 返回结构化 JSON
  -> 发布 /perception/image_analysis
  -> Agent 汇总并显示到 Web
```

当前结构化结果主要包括：

```json
{
  "message": "图像语义分析完成",
  "scene": "场景描述",
  "risk_level": "low | medium | high",
  "suggestion": "任务建议",
  "objects": []
}
```

当结果的 `source=vlm` 时，表示视觉模型调用成功；`source=rule+detection+vlm_failed` 表示 VLM 失败后使用了规则和检测摘要。

## 4. 当前已经体现的大模型能力

### 4.1 自由自然语言交互

用户不需要掌握 ROS 2 服务、Topic 名称和消息格式，可以使用任务语言：

```text
检查状态，如果安全就起飞到10米
向左飞20米并检测画面中的人
详细分析当前画面，不要引用历史任务
```

大模型负责把人的表达转换成系统能够理解的结构化意图。

### 4.2 多轮对话与上下文

系统支持 WebSocket 流式对话、会话历史和任务记录。例如：

```text
用户：检查前方有没有人
系统：发现一名人员
用户：拍下来并生成报告
```

第二条命令可以结合上一轮语义理解，不必重新描述目标。

### 4.3 Skill 与 Tool Use

大模型可以选择和调用：

- 飞控状态读取。
- 起飞、降落、RTL 和悬停。
- 自主飞行目标发布。
- RGB、深度、点云和检测摘要读取。
- 拍照归档。
- VLM 图像分析。
- 目标搜索。
- Mission 报告生成。

模型只选择受控工具，不能直接发布任意 PX4 消息，也不能绕过确认中心。

### 4.4 复杂任务拆解

系统已经具备 Workflow 基础，可以把组合任务拆成依赖步骤，例如：

```text
飞一个宽10米、深10米的V字形并在顶点拍照
```

对应执行计划：

```text
必要时起飞
  -> 飞向 V 字顶点
  -> 等待飞控确认到达
  -> 拍照
  -> 飞向 V 字右端
  -> 等待任务完成
```

### 4.5 开放视觉语义分析

当前 VLM 已能对夜间城市画面给出：

- 城市街道场景描述。
- 建筑、树木、道路、标志杆等物体清单。
- 数量、颜色、方位和大致距离。
- 可通行区域和潜在障碍。
- 光照条件和画面质量。
- 无法确认的内容。
- 高风险评级与悬停/返航建议。

这类能力超出了固定类别检测器的范围，是当前项目中最直观的大模型应用证据之一。

### 4.6 多源数据解释

Agent 可以读取飞控、里程计、感知和任务状态，并将原始数据解释为面向人的结论：

```text
无人机已解锁，处于 OFFBOARD 模式，高度约10米；
前方视觉能见度低，最近障碍距离不足；
建议暂停当前移动并使用深度或点云继续确认。
```

### 4.7 任务报告与可追溯性

系统能够保存截图、Mission 记录、确认记录和执行状态，并生成报告。报告可以说明：

- 用户下达了什么任务。
- 系统选择了什么 Skill。
- 实际调用了哪些工具。
- 飞控是否完成物理动作。
- 感知发现了什么。
- 失败或中止的原因。
- 下一步建议。

## 5. 大模型与确定性系统的边界

### 5.1 大模型应该参与

- 高层任务理解。
- 开放场景语义分析。
- 多步任务规划。
- 条件分支和策略选择。
- 失败原因归纳。
- 非结构化信息整理。
- 人机交互和报告生成。

### 5.2 大模型不应该直接负责

- 电机转速。
- 姿态角速度闭环。
- 高频位置和速度控制。
- 毫秒级避障反应。
- 绕过安全检查执行飞行动作。
- 在没有传感器证据时声称动作已经完成。

底层控制必须继续由 PX4、轨迹跟踪器和安全监督模块完成。大模型输出需要经过 Schema、参数范围、白名单、人工确认和状态验证。

## 6. 当前能力的不足

### 6.1 VLM 目前只分析单帧 RGB

当前 VLM 看不到连续视频，也没有直接获得深度图、点云和精确位姿。因此它可以描述“大致远近”，但不能把这一描述当作可靠测距。

### 6.2 视觉事实和历史推断可能混合

上层 LLM 有时会结合 Mission 历史补充推断。后续应在界面和数据结构中明确区分：

```text
视觉直接证据
传感器测量值
任务历史
模型推断
```

### 6.3 LLM 任务规划仍受已注册能力约束

模型不能凭空创造底层飞行能力。所有任务最终必须映射到已有 Tool、Skill 和 Workflow Action。

### 6.4 尚未形成持续闭环语义决策

当前多数 VLM 分析属于按需调用。真正成熟的系统需要在任务过程中持续执行“观察、判断、行动、验证、再规划”。

### 6.5 模型延迟和网络依赖

云端 VLM 单次调用可能需要数秒到数十秒，只适合任务级决策，不能承担实时避障。真机还需考虑断网、限流、费用和数据安全。

## 7. 后续可继续应用大模型的方向

### 7.1 P0：闭环语义巡检

目标任务：

```text
巡检前方区域，发现人就悬停拍照并报告位置；
没有发现就继续前进20米；前方不安全则停止。
```

需要实现：

- VLM/YOLO 结果成为 Workflow 条件。
- 每个动作完成后重新读取状态。
- 条件变化时允许重新规划。
- 全流程只执行已注册的安全 Action。

这是最能证明大模型参与任务决策的升级。

### 7.2 P0：主动视觉感知

当画面过暗、模糊或目标不确定时，Agent 不直接给出结论，而是主动执行：

```text
证据不足
  -> 调整偏航或观察位置
  -> 再拍一张
  -> 比较多帧结果
  -> 输出最终判断
```

这能体现具身系统通过行动改善感知，而不是被动看图。

### 7.3 P0：RGB、深度和点云融合

将 VLM/YOLO 的图像目标与深度像素、相机内参和里程计融合，得到三维目标：

```json
{
  "target": "person",
  "confidence": 0.86,
  "distance_m": 8.2,
  "relative_position": {"forward": 8.0, "right": -1.4, "up": -0.5},
  "world_position": {"x": 16.3, "y": 4.7, "z": 0.0}
}
```

VLM 负责语义，几何模块负责距离和坐标。

### 7.4 P1：任务级动态重规划

需要支持：

- 目标消失后回到最后观测位置搜索。
- 通道阻塞后选择替代观察点。
- 电池不足时提前返航。
- 视觉风险升高时暂停任务。
- 连续失败后请求人工接管。

大模型选择任务策略，底层规划器负责生成安全轨迹。

### 7.5 P1：三维语义地图

在世界坐标地图中保存：

```text
区域 A：发现人员
区域 B：存在车辆
区域 C：通道狭窄
区域 D：视觉光照不足
```

随后支持：

```text
回到刚才发现人员的位置
重新检查红色车辆是否还在
避开上次发现的狭窄区域
```

### 7.6 P1：证据化任务报告

自动将以下信息关联到同一 Mission：

- 航迹。
- 时间和位置。
- 原始截图与缩略图。
- YOLO 边界框。
- VLM 场景描述。
- 深度和最近障碍距离。
- 人工确认记录。
- 成功、失败和重试原因。

报告应明确标记事实来源，便于巡检、科研和客户验收。

### 7.7 P2：长期记忆与经验复用

系统可以积累任务级经验：

- 哪些区域经常出现人员。
- 哪些路线容易阻塞。
- 哪类提示词更容易产生可靠识别。
- 哪些任务参数更适合当前机型。

长期记忆只用于建议和高层规划，不能绕过实时传感器检查。

### 7.8 P2：多无人机协同

大模型可以根据任务范围、载荷、剩余电量和当前位置分配：

- 搜索区域。
- 巡检顺序。
- 中继通信。
- 目标跟踪与交接。

每架无人机仍应拥有独立的本地安全控制和失联保护。

### 7.9 P2：本地模型和边云协同

真机可以采用：

```text
机载小模型：低延迟目标检测、基础场景分类和异常检测
地面站模型：任务规划、多轮对话和报告
云端大模型：复杂 VLM 推理和跨任务知识分析
```

断网时必须自动降级到本地规则、传统感知和安全返航能力。

## 8. 推荐的演示任务

建议使用以下一句话作为完整演示：

```text
起飞到10米，巡检前方区域。搜索人员和车辆；
发现人员就保持安全距离、调整视角拍照并记录位置；
前方存在障碍则自主绕行；完成后返航并生成任务报告。
```

该任务可以同时展示：

1. 自然语言任务理解。
2. LLM 任务拆解。
3. Skill 与 Tool 选择。
4. 人工确认和安全网关。
5. YOLO 实时目标检测。
6. VLM 开放场景理解。
7. 深度和点云环境测量。
8. 自主规划与避障。
9. 条件分支和任务重规划。
10. 截图归档与任务报告。

## 9. 如何证明大模型确实产生了价值

不能只展示聊天内容，应同时记录可量化指标：

| 指标 | 说明 |
|---|---|
| 自然语言任务成功率 | 不同表达能否完成同一任务 |
| 未见指令泛化率 | 没有写死模板的表达能否正确规划 |
| Workflow 合法率 | 模型计划通过 Schema 和白名单校验的比例 |
| 目标搜索成功率 | VLM/YOLO 是否找到指定语义目标 |
| 任务重规划成功率 | 环境变化后能否完成替代策略 |
| 人工操作次数 | 与传统手动控制相比减少多少步骤 |
| 任务完成时间 | Agent 是否提高任务效率 |
| 错误拒绝率 | 危险或不确定任务是否被正确阻止 |
| 报告完整度 | 是否包含时间、位置、图像和判断依据 |

建议进行对照演示：

```text
规则系统：只能接受固定格式命令
LLM 系统：接受自由表达并拆解复杂任务
LLM + VLM：根据视觉语义和任务结果动态改变后续动作
```

## 10. 推荐研发顺序

### 第一阶段：形成真正的语义任务闭环

1. 扩展 VLM 结构化输出 Schema。
2. 分离视觉证据、传感器事实、历史和模型推断。
3. 将 VLM/YOLO 结果接入 Workflow 条件。
4. 完成人员巡检闭环演示。

### 第二阶段：获得三维语义能力

1. 标定 RGB、Depth 和 LiDAR。
2. 将二维目标投影为三维坐标。
3. 建立短期语义目标地图。
4. 支持按语义目标导航和复查。

### 第三阶段：动态任务智能

1. 增加主动观察动作。
2. 增加目标丢失和通道阻塞恢复策略。
3. 增加任务级重规划和人工接管策略。
4. 建立可量化的仿真回归场景。

### 第四阶段：真机工程化

1. 部署真实 VIO/SLAM 和成熟局部规划器。
2. 建立机载计算与地面站边界。
3. 增加断网降级、遥控接管和地理围栏。
4. 完成仿真、半实物和真机分级测试。

## 11. 对外表述建议

推荐使用：

> 本项目构建了一个大模型驱动的智能无人机任务系统。语言模型负责理解自然语言、拆解任务、选择技能和解释结果；视觉语言模型负责开放场景语义分析；ROS 2、传统感知、规划器和 PX4 负责确定性的实时执行。系统通过工具白名单、人工确认、任务状态机和飞控遥测验证，将大模型的灵活推理能力与无人机的安全控制能力结合起来。

不建议使用：

> 大模型直接控制无人机飞行和实时避障。

后者不符合当前实现，也不符合真机安全控制原则。

---

## 12. 总结

当前项目已经实现了大模型在无人机领域的三个关键应用入口：

1. 语言入口：自然语言理解、多轮对话和复杂任务拆解。
2. 视觉入口：Qwen3-VL 场景理解、目标语义和风险分析。
3. 行动入口：通过受控 Skill、Workflow 和 ROS Tool 驱动真实任务执行。

下一阶段的关键不是增加更多聊天功能，而是把 VLM 结果、深度几何、任务条件和动态重规划连接成持续闭环。完成“观察、判断、行动、验证、再规划”后，系统才能从自然语言控制台进一步升级为真正具备任务智能的具身无人机系统。
