# 无人机身份文档与地空分层智能体实施计划

> 目标：在现有 AeroMind/APM Lite M1 基础上，形成“无人机身份文档 + 地面大模型调度 + 机载小模型具身协同 + 确定性安全执行”的可验证闭环。
>
> 本计划先定义系统边界和实施顺序，作为后续编码、测试和申报书技术路线的共同依据。本计划不改变现有飞控协议、评分器、历史验收记录或真机授权范围。

## 1. 总体判断

这条路线可以实现，但不能把两个模型都放进飞控控制环。推荐采用分层闭环：

```text
人提出任务
  -> 地面大模型：任务理解、集群分解、能力匹配、全局调度
  -> 结构化任务契约：MissionGraph + TaskAssignment
  -> 机载小模型：本机感知、局部判断、技能选择、异常解释
  -> 确定性安全层：权限、边界、电量、通信、健康和新鲜度检查
  -> 现有技能执行器/飞控控制器
  -> 遥测、局部计划和证据回传
  -> 地面大模型更新全局计划
```

地面大模型和机载小模型都只能产生“受约束的计划或技能请求”，不能直接输出电机、姿态或绕过现有门禁的控制指令。20--50 Hz 的稳定控制继续由现有飞控和确定性控制器完成。

## 2. 核心产物：无人机身份文档

### 2.1 身份文档与孪生状态分离

身份文档是相对稳定、可签名和可审计的“无人机数字护照”；`TwinState` 是持续变化的实时状态。两者通过 `vehicle_id` 关联，但不能互相替代。

| 层 | 主要内容 | 变化频率 | 可信要求 |
|---|---|---:|---|
| Identity | 编号、序列号、平台类型、厂商、固件、注册时间 | 低 | 签名、版本、撤销 |
| Capability | 传感器、载荷、技能、航时、速度、任务限制 | 低 | 能力来源和校准哈希 |
| Embodiment | 机载模型、技能库、自治等级、资源预算、降级策略 | 中 | 模型版本和技能版本 |
| Authorization | 白名单、最大权限、需确认动作、有效期 | 中 | 策略签名、门禁校验 |
| TwinState | 位置、速度、电量、链路、健康、任务阶段、来源 | 高 | 时间戳、来源、置信度、新鲜度 |

### 2.2 建议的数据结构

新增 `VehicleIdentityDocument`，内部组合以下对象：

```text
IdentityMetadata
  vehicle_id / serial_number / platform_type / vendor / firmware

CapabilityProfile
  sensors / payloads / skills / max_speed / endurance / limits

EmbodiedAgentProfile
  model_id / model_version / input_modalities / skill_ids
  autonomy_level / decision_rate_hz / compute_budget / fallback_policy

AuthorizationProfile
  allowed_commands / confirmation_policy / geofence / expires_at

Attestation
  document_version / document_hash / signing_key_id / signature_algorithm
  signature / revoked
```

其中 `TwinState` 继续复用现有契约，保存当前动态状态；身份文档只声明“能做什么”和“允许做什么”，不声明“此刻已经完成了什么”。

### 2.3 身份文档的生命周期

```text
制造/注册
  -> 能力录入与校准
  -> 地面站签名发布
  -> 无人机端启动时校验
  -> 任务前能力/授权匹配
  -> 运行中只更新 TwinState
  -> 固件、模型或能力变化时生成新版本
  -> 丢失、异常或过期时撤销
```

## 3. 地面大模型：全局调度层

### 3.1 职责

地面大模型负责：

1. 将自然语言需求转换为结构化任务目标和约束；
2. 查询身份文档和最新 `TwinState`；
3. 将任务拆分为多机 `MissionGraph`；
4. 按能力、电量、位置、通信和权限生成 `TaskAssignment`；
5. 接收机载端反馈并触发重规划；
6. 解释选机依据、失败原因和任务边界。

### 3.2 输出边界

地面模型只允许输出：

- 任务节点和依赖关系；
- 无人机分配结果；
- 目标区域、航点或技能参数；
- 失败处理和替代方案；
- 需要人工确认的动作清单。

地面模型不得输出：

- 电机、姿态、PWM 或原始飞控控制量；
- 未注册的无人机能力；
- 超出身份文档限制的参数；
- 绕过确认、地理围栏、电量或健康检查的动作。

### 3.3 调度闭环

```text
任务文本
  -> 任务解析
  -> 能力匹配
  -> 任务图生成
  -> 安全约束验证
  -> 人工确认（需要时）
  -> 任务下发
  -> 反馈收集
  -> 完成验证 / 失败重规划
```

## 4. 机载小模型：具身智能层

### 4.1 定位

机载小模型不是“缩小版地面大模型”，而是一个受本机状态和技能库约束的局部智能体。它必须知道：

- 自己是哪一架无人机；
- 自己有哪些传感器和载荷；
- 当前能量、链路和健康状况；
- 当前被分配的局部任务；
- 哪些技能可用、哪些动作必须拒绝；
- 何时应该悬停、返航或请求地面重规划。

### 4.2 机载模型输入与输出

输入：

```text
VehicleIdentityDocument（静态能力和授权）
TwinState（动态状态）
TaskEnvelope（地面分配的局部任务）
LocalObservation（视觉、位置、链路和故障摘要）
```

输出：

```text
LocalPlan
  intent / skill_id / parameters / confidence / reason

ActionProposal
  action / target / expiry / required_confirmation / evidence_ids
```

输出必须经过机载确定性安全层和现有白名单后，才能进入技能执行器。机载模型决策建议控制在 0.5--2 Hz；飞控控制器仍保持原有实时频率。

### 4.3 机载端的最小自治等级

| 等级 | 能力 | 典型行为 |
|---|---|---|
| A0 | 仅执行 | 按地面给定航点执行 |
| A1 | 状态判断 | 电量不足时拒绝继续并请求处理 |
| A2 | 局部调整 | 在限定区域内选择搜索顺序或观察点 |
| A3 | 局部容错 | 短时失联时悬停、返航或按预案继续 |
| A4 | 自主协商 | 暂不纳入 M2，需先完成多机安全验证 |

M2 先实现 A1--A2，A3 只允许在明确的、可验证的失联预案内实现。

## 5. 通信与契约

建议在现有协议之外增加以下结构化消息，不改变原有飞控指令格式：

| 消息 | 方向 | 用途 |
|---|---|---|
| `VehicleIdentityDocument` | 地面 -> 机载 / 注册库 | 身份、能力、模型和授权 |
| `TaskEnvelope` | 地面 -> 机载 | 局部任务、约束、有效期和确认要求 |
| `LocalObservation` | 机载 -> 地面 | 传感器摘要、目标、环境和本机判断依据 |
| `ActionProposal` | 机载 -> 安全层 | 受约束的技能请求，不是原始飞控指令 |
| `ExecutionFeedback` | 机载 -> 地面 | 接收、执行、完成、失败和证据引用 |
| `ReplanRequest` | 机载 -> 地面 | 能力不足、状态异常或任务不可完成 |

每条消息都应带：`mission_id`、`vehicle_id`、`task_id`、`schema_version`、时间戳、有效期、来源和证据引用。

## 6. 分阶段实施计划

### P0：身份文档最小版

新增：

- `common/identity/vehicle_identity.py`；
- `common/contracts/identity.py`；
- `schemas/vehicle-identity-v1.schema.json`；
- 身份文档签名、哈希和撤销字段；
- `VehicleRegistry` 的文档导入、导出和版本校验。

验收：

- 同一 `vehicle_id` 在 demo、SITL、real 模式下身份一致；
- 能力不在文档中的任务被拒绝；
- 修改文档内容后签名校验失败；
- 过期或撤销的文档不能进入任务分配。

### P1：机载具身智能最小闭环

新增：

- `onboard/embodied_agent.py`；
- `onboard/local_planner.py`；
- `LocalObservation`、`LocalPlan`、`ActionProposal` 契约；
- 规则/小模型双路推理；
- 机载安全门和技能白名单。

验收：

- 小模型只能选择已注册技能；
- 电量、链路、健康或权限不满足时自动拒绝或降级；
- 失联时执行确定性预案，不依赖模型继续输出；
- 不产生原始电机或绕过门禁的指令。

### P2：地面大模型调度闭环

新增：

- `ground/browser/mission_orchestrator.py`；
- 多机任务分解和能力匹配；
- 大模型输出 Schema 校验；
- 任务下发、反馈回收和重规划接口；
- 调度解释和证据记录。

验收：

- 自然语言任务能生成可验证的多机任务图；
- 选机依据可解释；
- 注入故障后可生成替代方案；
- 原有单机评测结果不下降。

### P3：地空协同仿真验证

内容：

- 地面大模型生成集群计划；
- 机载小模型执行局部判断；
- L0/L1 广筛与 L2 SITL 复验；
- 记录计划、局部判断、遥测和最终结果的完整证据链。

验收：

- 任务完成率、重规划成功率、拒绝正确率和通信恢复率可统计；
- 相同身份文档、任务和随机种子可回放；
- 明确区分仿真、台架和真机结果。

### P4：受限实体验证

只在完成仿真和无桨台架验证后进行，先验证：

- 身份文档加载；
- 能力和权限校验；
- 状态回传；
- 失联和低电量预案；
- 人工接管和停止链路。

不以大模型输出作为真机放行依据，不把仿真结果写成真机验收结论。

## 7. 关键风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 大模型生成越权任务 | Schema、能力匹配、白名单、安全门和人工确认四重校验 |
| 小模型输出不稳定 | 规则基线、技能白名单、置信度阈值和确定性降级 |
| 机载算力不足 | 小模型只做低频局部判断，实时控制由飞控完成 |
| 通信中断 | 本机预案独立运行，过期状态不能进入新任务判断 |
| 身份伪造或能力篡改 | 文档签名、版本哈希、撤销列表和启动校验 |
| 仿真与真机混淆 | 所有状态和证据强制携带 `source`、`fidelity` 和适用边界 |

## 8. 推荐的研究表述

工程名称可以表述为：

> 面向异构无人集群的地空分层多智能体协同架构：以可验证无人机身份文档为基础，由地面大模型完成全局任务调度，由机载小模型完成受约束的具身决策，并通过确定性安全层实现闭环执行与证据追溯。

这个表述中，身份文档是基础设施，地面大模型是全局调度方法，机载小模型是具身智能方法，安全门和证据链是系统可信性保障。
