# 翼策·平行域四实例环境说明

本文档描述阶段 0 到阶段 4 的可复现边界。它只编排 SITL、Gazebo classic、AirSim 和地面桥，
不修改 PX4 或 ArduPilot 飞控核心，也不把四路 MAVLink 通过 router 合并。

## 实现选择

APM 实机替身采用 **ArduPilot 原生 SITL**（`arducopter --model +`），没有接入
`ardupilot_gazebo`。当前工作区未安装或构建该插件；原生 SITL 能保持独立的 14550
MAVLink 端点并满足阶段 0 的 ARM/TAKEOFF ACK 验收。运行器默认 `SITL_SPEEDUP=10`，
用于让原生估计器在无 GUI 的 tmux 启动中稳定收敛；可通过环境变量降速。它不提供 Gazebo 的刚体/碰撞世界，
因此不能被描述为 Gazebo-ArduPilot 外场，也不能替代阶段 2 的物理侧碰撞验证。

## 端口、机号和 dialect

| 实例 | 角色 | 物理/孪生 | 进程 | vehicle_id / MAV_SYS_ID | 地面桥 MAVLink UDP | 其他仿真端口 | dialect |
|---|---|---|---|---:|---:|---|---|
| `px4-real` | real | Gazebo classic | PX4 SITL | 1 / 1 | `14540` | Gazebo TCP `4560`; SDK `14540`; QGC 辅助 `14640` | `common` + PX4 extensions |
| `px4-virtual` | virtual | UE AirSim | PX4 SITL | 1 / 1 | `14541` | AirSim TCP `4561`; PX4 local sockets `14581/18571`; QGC 辅助 `14641` | `common` + PX4 extensions |
| `apm-real` | real | native SITL | ArduCopter SITL | 2 / 2 | `14550` | SITL instance `20` | `ardupilotmega` + common |
| `apm-virtual` | virtual | UE AirSim | ArduCopter SITL | 2 / 2 | `14551` | AirSim sensor/control `9003/9002`; SITL instance `0`; `SITL_SPEEDUP=10` | `ardupilotmega` + common |

桥端点必须使用 `udpin:0.0.0.0:<port>`，并由只读 `bridge.yaml` 或控制
`bridge-control.yaml` 分别绑定；任何端点重复都应被配置校验拒绝。PX4 Gazebo 的默认 QGC fan-out 是
14550，本编排在运行目录生成 SDF 时改成 14640，防止它把 PX4 数据写进 APM 的
14550；PX4 的独立 onboard 输出仍然只发往 14540。四个 MAVLink socket 彼此不转发。

阶段 0 关注的 PX4 message 集合为 `HEARTBEAT`、`SYS_STATUS`、`GPS_RAW_INT`、
`GLOBAL_POSITION_INT`、`LOCAL_POSITION_NED`、`ATTITUDE_QUATERNION`、
`MISSION_*` 和 `COMMAND_ACK`。APM 使用同一 common 基础集合并增加
`EKF_STATUS_REPORT`、`EXTENDED_SYS_STATE`、`STATUSTEXT` 等 `ardupilotmega`
消息。核心只看统一遥测模型；dialect 和模式/命令编号留在各自 adapter。

## GeoReference 和坐标方向

四个世界使用同一份已锁定的 SITL 专用标定：

- origin：latitude `47.641468`、longitude `-122.140165`、altitude `122.0 m AMSL`；
- ENU 基准：`+X=East`、`+Y=North`、`+Z=Up`；当前场地 map 在该基准上按
  `map_x_heading_from_true_north=0°` 旋转，因此实际 map 轴为
  `+X=North`、`+Y=West`、`+Z=Up`；所有证据都标记为 `frame=map`，不能把 map 数值
  直接当成未旋转的 ENU；
- Gazebo：ENU；Gazebo 模型的 `z=0.83` 是模型出生高度，不是地理原点海拔；
- AirSim：NED，`+X=North`、`+Y=East`、`+Z=Down`；
- vehicle home：PX4 `(0,0,0)`，APM `(0,3,0)`（map 米）；
- 配置源：`configs/parallel_domain/sitl-georeference.yaml` 和本目录 `worlds.yaml`；
- 标定 ID：`parallel-sitl-locked-v1`，其 `surveyed` 仅表示已对上述确定性 SITL
  启动参数完成锁定和往返验证。

`run_px4_gazebo.sh` 会显式设置 `PX4_HOME_LAT/LON/ALT` 为上述原点。不能省略：
Gazebo classic 否则会使用 PX4 默认苏黎世原点，使转换后的 map 坐标达到 ECEF 量级。
需要覆盖原点时，三个环境变量必须一起覆盖，并同步更新 GeoReference。

这不是真实场地测绘。进入真实场地前必须换用新的外场标定 ID，重新测量
origin、朝向、海拔 datum 和每架机 home；不得把这份 SITL `surveyed` 状态或
仿真结果声明为真机外场证据。`demo-georeference.yaml` 仍保留为 draft 预览，
不能用于 live 验收。

## 启动顺序

在 WSL Ubuntu 22.04：

```bash
cd ~/aeromind_ws/apm_lite
deploy/parallel_domain/start_all.sh --line all --world all
```

脚本首先生成 `~/.aeromind/parallel-domain/airsim/{px4,apm}.settings.json`，再按
`PX4 Gazebo -> APM 原生 SITL -> PX4 AirSim SITL -> APM AirSim SITL` 顺序建立四个
独立 tmux session。`AIRSIM_HOST` 默认取 `/etc/resolv.conf` 的 Windows 网关，必要时
显式设置，例如 `AIRSIM_HOST=172.24.80.1 ...`。AirSim UE 不在 WSL 中自动猜测启动：
`start_all.ps1` 会把两份 settings 分别复制到
`%LOCALAPPDATA%\Aeromind\parallel-domain\airsim\px4|apm\settings.json`，以两个独立
`-settings=<绝对路径>` 启动 UE，并校验 RPC 分别监听 `41451/41452`。它在启动前后
比较标准 `Documents\AirSim\settings.json` 的 SHA-256，绝不写入或共享该文件；两个
世界的 UE 日志和进程 manifest 也分别落在各自 profile。不要手动去掉 `-settings`，
否则 AirSim 1.8.1 会退回单一 Documents 配置并造成端口和车辆配置互相污染。

只起一条线或一侧：

```bash
deploy/parallel_domain/start_all.sh --line px4 --world real
deploy/parallel_domain/start_all.sh --line apm --world virtual
deploy/parallel_domain/start_all.sh --dry-run
deploy/parallel_domain/stop_all.sh
```

启动地面桥前，先在四个 session 日志中确认模拟器连接，然后执行只读观察桥：

```bash
deploy/sim/start-parallel-domain.sh configs/parallel_domain/bridge.yaml
```

默认 `bridge.yaml` 设置 `observation_only: true`，桥只订阅四路 MAVLink，不处理任务或
审批 spool。real 端只用新的 `GLOBAL_POSITION_INT` 形成 observed；PX4 virtual 只用
`LOCAL_POSITION_NED`，APM virtual 只用 GPS fix >= 3 的有效
`GLOBAL_POSITION_INT` 形成 predicted，禁止把 APM 的 local/global 两个原点混进同一证据；
心跳/GPS/姿态消息不会复用最后位置产生轨迹点。
APM 的 `SITL_SPEEDUP=10` 只影响 APM 线内 sim time，跨 PX4/APM 比较必须使用 UTC
wall time。适配器会持续消费全部 MAVLink 报文以更新最新缓存，但按
`telemetry_sample_interval_s=0.1` 的 wall-time 边界生成最多 10 Hz 的轨迹证据，
防止 10 倍速 APM 报文积压后被误认为实时位置。

live 状态和可回放轨迹位于：

```text
.runtime/parallel-domain/twin/<line>/state-set.json
.runtime/parallel-domain/twin/<line>/real-status.json
.runtime/parallel-domain/replay/<line>/observed.jsonl
```

需要启用“虚控实” live 控制时，必须显式启动隔离的控制配置；它与默认只读桥不能
同时绑定同一端口：

```bash
deploy/sim/start-parallel-control.sh configs/parallel_domain/bridge-control.yaml
```

控制配置只接受任务级动作。链路为 `AirSim predicted -> 白名单/参数门禁 -> 人工确认
(TTL、任务摘要、预测证据摘要) -> PX4 OFFBOARD 或 ArduPilot GUIDED -> real observed`。
适配器实现 `rtl` 映射，但默认 live 白名单只授权 `takeoff/waypoint/land`；RTL 任务会在
virtual dispatch 前以 `capability_whitelist=false` 拒绝。批准凭据一次性消费，重复审批
或重复下发会进入重放审计，不能扩大到其他任务或其他 evidence hash。
控制桥不透传孪生姿态或电机量，real 飞控仍运行自己的稳定和 failsafe 闭环。
`bridge-control.yaml` 的 `force_arm_for_sitl: true` 是仅针对本地 SITL 替身的显式
预检例外（magic `21196`）；默认只读 `bridge.yaml` 和未配置该字段的端点永远发送
普通 ARM，不会强制解锁。该配置不得复制到真机配置。

启动与控制面完全隔离的只读 observed 监视页：

```bash
deploy/sim/start-parallel-observer.sh configs/parallel_domain/bridge.yaml
```

默认地址为 `http://127.0.0.1:8091`。页面每 500 ms 读取一次
`/api/observed`，同时画 PX4/APM 的 map ENU 轨迹、最新位置、序号和
fresh/stale 状态。HTTP 服务不实现任何写入或控制路由，POST 固定返回 405。
`PD_OBSERVER_PORT` 可覆盖端口，`PD_OBSERVER_MAX_POINTS` 可调整每线显示点数。

`real-status.json` 的状态为 `waiting/fresh/stale/recovering`。心跳丢失、GPS fix 丢失、
链路异常或超过 3 秒没有新 real 位置都会停止镜像；默认连续两条健康样本后恢复。
stale/recovering 期间最后 observed 位置保持不变，不以旧值续命。

桥正在运行且两条 real 线均有轨迹时，可以对持久化的 live 结果执行只读验收：

```bash
PYTHONPATH=src python3 tools/accept_parallel_domain.py \
  --live-state-directory .runtime/parallel-domain \
  --output .runtime/parallel-domain/live-acceptance.json
```

该门禁同时运行确定性故障注入用例，并检查现场日志的状态、序列、三时间域、
map 坐标尺度、标定哈希和 PX4/APM 的 sim/wall 速度比。

两条线均完成一次 `predicted -> approval -> real dispatch -> observed -> comparison`，并
完成越权、TTL 和重放注入后，执行阶段四只读验收：

```bash
PYTHONPATH=src python3 tools/accept_parallel_domain.py \
  --live-control-state-directory .runtime/parallel-domain-control \
  --output .runtime/parallel-domain-control/live-control-acceptance.json
```

它会交叉核对 audit 事件顺序、approval/evidence hash、PX4 OFFBOARD 与 APM GUIDED
执行语义、`source=airsim/real_telemetry`、map 标定、`alignment_clock=wall_time` 和误差
阈值。TTL 负向复现时可在验收窗口把 `approval_ttl_s` 临时设为模型最小值 30 秒，生成
approval request 后等待 30 秒再提交正确摘要；完成后必须恢复 600 秒并重启控制桥。
越权样例为 `configs/parallel_domain/missions/apm-denied-rtl.json`。

APM 原生 SITL 的 `apm-native-sitl.parm` 固定 ArduCopter 4.7 的
`MAV1_EXT_STAT=2`、`MAV1_POSITION=10`、`MAV1_EXTRA1=10`（旧版本名称为
`SR0_*`）。这只配置 SERIAL0 的只读遥测发布率，不包含 ARM、模式或任务命令；
删除这些参数会导致仅有 heartbeat、没有 observed 位置。

## 阶段五：双线 live 异常复验

阶段五使用专用 `configs/parallel_domain/bridge-live-faults.yaml`。它仍然只允许
`takeoff/waypoint/land`，但把人工确认 TTL 收紧到 30 秒，并显式打开 SITL 故障入口；
生产控制配置 `bridge-control.yaml` 的 TTL 仍为 600 秒，不能为了演示修改生产门禁。

四实例和 UE 世界已经运行时，一键执行双线三类异常，并自动恢复正常控制桥：

```bash
deploy/sim/accept-parallel-domain-live-faults.sh
```

脚本只停止并重启地面桥的 `pd-control`/`pd-live-faults` tmux session，不停止
`pd-px4-real`、`pd-px4-virtual`、`pd-apm-real` 或 `pd-apm-virtual`。报告和逐事件流落在：

```text
.runtime/parallel-domain-live-faults/live-fault-acceptance.json
.runtime/parallel-domain-live-faults/live-fault-acceptance-events.jsonl
.runtime/parallel-domain-live-faults/audit/events.jsonl
```

为避免上次未完成任务被 bridge restart 恢复并污染新一轮，脚本启动前会把已有专用目录
完整移动到 `.runtime/parallel-domain-live-faults-history/<UTC>-<pid>/`；历史拒绝和失败
日志不会删除，固定的 `parallel-domain-live-faults` 目录始终表示本次运行。

每条线都会依次复验：

1. `RTL` 不在白名单，virtual rehearsal 在真实下发前产生
   `rehearsal_rejected`，原因含 `capability_whitelist` 和命令名；样例分别是
   `missions/px4-denied-rtl.json` 与 `missions/apm-denied-rtl.json`。
2. 合法任务生成 approval request，等待严格 TTL 后提交正确摘要，产生带
   `approval_ttl_expired` 的 `approval_rejected`，且不存在 `real_mission_dispatched`。
3. 对 recovery 任务先写 `request-dispatch`，验证没有人工确认时的
   `real_dispatch_rejected(operator_confirmation_missing)`；再写 operator approval，
   最后写 `inject-fault --confirm-sitl`。桥在下一条 real 位置遥测的健康门禁处一次性注入
   heartbeat/GPS loss，触发 `safety_hold -> recovery_land`，恢复后继续写
   `source=observed` 并完成任务。

拒绝、故障和安全动作事件都带 `reason`、UTC `wall_time`、`vehicle_id`、`line_id` 和
`command`，可以从 `audit/events.jsonl` 追溯到 mission/fault/approval。故障注入明确标记
`injection_layer=live_telemetry_health_gate`，它是可复现的 SITL 健康门禁测试，不冒充
物理 RF/UDP 断链；真实断链仍由 adapter 的静默超时、关闭 socket、重连和 stale 门禁处理。

安全动作的飞控差异只在适配器内：

| 线 | `safety_hold` | `recovery_land` |
|---|---|---|
| PX4 | `SET_MODE:AUTO.LOITER`（按 PX4 广播别名回退到 `LOITER`） | `SET_MODE:AUTO.LAND`（按广播别名回退到 `LAND`） |
| APM | `SET_MODE:LOITER` | `SET_MODE:LAND` + `MAV_CMD_NAV_LAND` |

PX4 重连窗口若还没有可用的动态 `mode_mapping()`，PX4 适配器会用该模式的固定
主/子模式参数发送 `MAV_CMD_DO_SET_MODE`。该最后回退仍然只切换飞行模式，不发送姿态、
角速度、推力或执行器控制量。

任何 stale 或 recovering 状态都不追加 observed、不移动最后位置，也不以最后一条旧遥测
续命；恢复要求配置的连续健康样本数。阶段五脚本结束时会重新启动 600 秒 TTL 的
`bridge-control.yaml`，如需查看负向日志不要删除专用 runtime。

## 验收

只读心跳和系统号检查（不会发送飞行命令）：

```bash
PYTHONPATH=src python3 tools/verify_sitl.py \
  --config configs/parallel_domain/bridge.yaml
```

仅启动 real 侧时，可在桥绑定端口前检查 observed 必需的 GPS、全局位置和
姿态报文：

```bash
PYTHONPATH=src python3 tools/probe_parallel_domain.py \
  --config configs/parallel_domain/bridge.yaml \
  --role real --require-observed-telemetry --timeout-s 20
```

ARM/TAKEOFF ACK 是显式 opt-in，且仅允许 SITL：

```bash
PYTHONPATH=src python3 tools/verify_sitl.py \
  --config configs/parallel_domain/bridge.yaml \
  --exercise --confirm-sitl --takeoff-altitude-m 5
```

如果原生 APM SITL 的 AHRS 尚未形成高度估计，可在确认只连接仿真进程后增加
`--force-arm`（MAVLink 标准的 SITL force-arm magic `21196`）；该选项绝不能用于
真机或由 Agent 自动调用。

验收工具在地面桥绑定端口前运行；桥已启动时应先停止桥或使用专门的 MAVLink
分流设备。没有 AirSim UE 时，四实例 live gate 不应标记为通过；可运行只读的离线
故障注入验收：
`deploy/sim/accept-parallel-domain.sh`。

## 常见报错

| 现象 | 处理 |
|---|---|
| PowerShell 提示脚本未数字签名 | 使用进程级策略运行：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\parallel_domain\start_all.ps1 -DryRun`；不要修改 LocalMachine 策略。 |
| `PX4 binary not found` | `cd $PX4_ROOT && make px4_sitl_default`，或设置 `PX4_BUILD`。 |
| Gazebo `An instance ... is not running` | 关闭残留 `gzserver/gzclient`，删除 runtime 后重启；不要同时启动两个 PX4 Gazebo world。 |
| AirSim TCP 4561 无连接 | 先启动 PX4 AirSim session，再确认 UE 使用 PX4 settings、WSL IP 和 `TcpPort=4561`，放行 Windows 防火墙。 |
| ArduCopter AirSim 无传感器 | 检查 `AIRSIM_HOST`、WSL IPv4、AirSim `UdpIp` 和 `9002/9003`，确认 UE 已进入 Play。 |
| 14550 收到 PX4 数据 | 说明使用了未生成的默认 Gazebo SDF；删除 runtime 重新生成，确认 QGC 辅助端口为 14640。 |
| `Address already in use` | `tmux ls`、`ss -lunpt` 检查残留进程；四路端点和 PX4 本地 socket 必须各自独占。 |
| ARM/TAKEOFF ACK 被拒绝 | 先看 `COMMAND_ACK.result` 和 `STATUSTEXT`；GPS/EKF/模式未就绪时拒绝是正常安全行为，不要绕过门禁。 |
| 找不到 `mavproxy.py` | 本环境未安装 MAVProxy；使用 QGC/MAVSDK 或安装 ground extras 后再做独立端口连接。 |
| `real-status.json` 为 `stale` | 查看 `reason`、链路错误及 heartbeat/GPS age；恢复后需连续两条健康位置样本。不要用旧 `real.json` 当实时位置。 |
| observed sequence 跳过源报文号 | `source_sequence` 包含被门禁拒绝的候选，回放 `sequence` 只对已接受 observed 连续；这是预期行为。 |

停止时使用 `stop_all.sh`，再停止 UE；不要用杀掉整个 `px4`/`arducopter` 进程名的
方式，以免误伤其他项目的 SITL。

## 阶段六：live 证据包与标定冻结

live 证据包把同一任务的 `planned`、AirSim 遥测生成的 `predicted` 和 real 端遥测
生成的 `observed` 放在同一个 map 坐标、同一个任务 ID 下。`manifest.json` 锁定
line、vehicle_id、软件树 SHA-256、Git commit、随机种子、UTC 时间范围、标定 ID/SHA-256、
三份 evidence hash、三组误差报告 hash 和包内容 hash；`observed-replay.jsonl` 是原始
observed 日志的逐条对账来源。包的 `content_sha256` 覆盖 manifest 中所有 artifact
hash，不能只校验压缩文件名。

先用确定性 SITL 真值完成 draft 到 surveyed 的冻结。默认触发条件是至少 6 个样本、
至少 3 个独立控制点、同时存在 outbound/return、存在明确真值来源，并且实测水平/垂直
RMSE、3D 最大值和 P95 通过阈值。命令入口是 `tools/calibrate_parallel_domain.py`
的 `freeze` 和 `verify`；receipt 会交叉绑定 draft SHA、冻结 SHA、dataset hash 和
测量报告 hash。冻结后才允许 `preview_only=false` 和 `acceptance_passed=true`，真实
场地必须使用新的 calibration_id，不能把 SITL fixture 当成外场测量。

对于正在运行的 Gazebo real 替身，`capture-gazebo` 每个样本同时读取独立的
`gz model -m <model> -p` 根位姿（Gazebo ENU）和最近 observed GPS-derived map，按
wall time 配对后写入 dataset。飞到一个已知控制点后运行一次；到下一个点或返航后用
`--append` 追加。配对偏差、真值来源和真实误差分布原样落盘，控制点不足时不得冻结。

```bash
PYTHONPATH=src python3 tools/calibrate_parallel_domain.py capture-gazebo \
  --georeference .runtime/parallel-domain-calibration/georeference.yaml \
  --replay .runtime/parallel-domain-control/replay/px4/observed.jsonl \
  --line px4 --vehicle-id 1 --model px4_real_1 \
  --control-point CP-live-0 --pass-id outbound-1 --direction outbound \
  --sample-count 2 --output .runtime/parallel-domain-calibration/live.json \
```
