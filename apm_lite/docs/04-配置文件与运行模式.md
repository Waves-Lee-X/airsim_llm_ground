# 04 配置文件与运行模式

## 1. 配置分层

Lite 不把所有参数写进一个文件。不同生命周期的数据分开管理：

| 配置 | 示例位置 | 管理对象 |
|---|---|---|
| 机队配置 | `configs/real/fleet.uav3.yaml` | 机号、FCU、P9、频率、标定 ID |
| 仿真机队 | `configs/sim/fleet.m1.yaml` | SITL UDP 和单机验收参数 |
| AirSim 配置 | Windows `Documents/AirSim/settings.json` | AirSim 车辆、端口和相机 |
| 场地标定 | `configs/calibration/venue.yaml` | WGS84/map/NED/AirSim 对应关系 |
| 机载密钥/开关 | `/etc/aeromind-apm-lite/uav3.env` | 每机密钥和命令白名单 |
| 地面密钥 | `%USERPROFILE%\.aeromind\uav3.env` | 对应飞机共享密钥 |
| 模型配置 | `%USERPROFILE%\.aeromind\vlm.env` | VLM/LLM URL、Key、模型和超时 |
| systemd 单元 | `deploy/systemd/aeromind-apm-lite@.service` | 机载启动、隔离和重启策略 |

真实密钥只能放在机器本地环境文件，不得写入 YAML、Git、截图或日志。

## 2. 运行模式

地面站通过 `--mode` 选择三种模式：

### 2.1 DEMO

```bash
cd ~/aeromind_ws/apm_lite
PYTHONPATH=src python3 -m aeromind_apm_lite.ground.browser.app \
  --mode demo --host 127.0.0.1 --port 8010 --disable-camera
```

DEMO 使用内存飞行状态，不连接 SITL、P9 或 FCU，适合检查 Web、API 和 Mission
Agent。页面上的模拟完成证据不能作为飞控或实机验收。

### 2.2 SITL

```bash
PYTHONPATH=src python3 -m aeromind_apm_lite.ground.browser.app \
  --mode sitl --host 127.0.0.1 --port 8000 \
  --fcu-endpoint udpin:0.0.0.0:14550
```

SITL 模式在地面进程内创建 `OnboardAgent + ApmLink`，连接 ArduCopter UDP。UE、
AirSim 和 SITL 必须由操作者先启动，Lite 不管理它们的生命周期。

### 2.3 REAL_SERIAL

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\windows\start-ground-uav3.ps1
```

真实模式的地面站只拥有 `COM3` P9 串口，FCU 串口由树莓派独占。真实模式必须提供
`--secret-env` 和 `--frame-calibration-id`。

## 3. 机队 YAML

UAV3 当前关键配置：

```yaml
schema_version: "1.0"
mode: real
vehicles:
  - vehicle_id: 3
    name: real-uav3
    frame_calibration_id: uav3-local-ned-bench-v1
    credential_env: AEROMIND_UAV3_TOKEN
    fcu:
      transport: serial
      endpoint: /dev/ttyAMA0
      baudrate: 921600
      source_system: 203
      source_component: 191
      target_system: 3
      target_component: 1
    ground_link:
      transport: serial
      endpoint: /dev/ttyAMA1
      baudrate: 57600
```

字段解释：

| 字段 | 说明 |
|---|---|
| `vehicle_id` | Lite 机号，同时用于协议隔离和目标 MAVLink system ID |
| `frame_calibration_id` | 所有坐标消息必须匹配的版本标识 |
| `credential_env` | 密钥所在环境变量名，不是密钥值 |
| `source_system/component` | 树莓派伴随计算机发 MAVLink 时的来源 ID |
| `target_system/component` | 目标 ArduCopter ID |
| `setpoint_rate_hz` | 连续设定点发送频率，当前 20 Hz |
| `trajectory_timeout_ms` | 轨迹新鲜度门限 |
| `companion_heartbeat_hz` | 给 FCU 的伴随计算机心跳频率 |
| `completion_hold_s` | 物理完成条件连续满足时间 |

修改 `vehicle_id` 时必须同时核对 ArduPilot `SYSID_THISMAV`、地面密钥文件、systemd
实例号和 P9 两端配置，不能只改一处。

## 4. 机载环境文件

默认只读配置：

```text
AEROMIND_UAV3_TOKEN=base64:<至少32字节随机值>
```

无桨 ARM/DISARM 台架才允许增加：

```text
AEROMIND_COMMAND_OUTPUT_ENABLE=--enable-command-output
AEROMIND_ALLOW_ARM=--allow-command=arm
AEROMIND_ALLOW_DISARM=--allow-command=disarm
```

总开关关闭时，白名单即使存在也无效；总开关打开但白名单为空时，所有命令仍被
拒绝。当前不得增加 TAKEOFF/HOLD/LAND/RTL。

## 5. 地面模型配置

`%USERPROFILE%\.aeromind\vlm.env` 示例：

```text
AEROMIND_VLM_API_URL=https://your-openai-compatible-endpoint/v1
AEROMIND_VLM_API_KEY=<local-secret>
AEROMIND_VLM_MODEL=qwen3-vl-plus
AEROMIND_LLM_MODEL=qwen3-vl-plus
AEROMIND_VLM_TIMEOUT_SEC=30
```

启动脚本只接受上述白名单变量。模型密钥不会传给浏览器、P9 或树莓派。

## 6. AirSim settings.json

WSL NAT 地址可能在重启后变化，必须重新生成：

```bash
cd ~/aeromind_ws/apm_lite
PYTHONPATH=src python3 -m \
  aeromind_apm_lite.ground.simulation.manual_settings \
  --output /mnt/c/Users/<Windows用户名>/Documents/AirSim/settings.json
```

生成器会输出匹配的 `sitl_command`。不要从旧日志复制 WSL IP，也不要让生成器自动
启动 UE/SITL；进程由操作者分终端管理。

## 7. GeoReference 配置

`configs/calibration/venue.example.yaml` 是空场地草稿。关键字段包括真实场地原点、
map X 真北航向、AirSim 原点、四机 Home 和高度基准。没有室外实测时保持
`status: draft`，不得改为 `surveyed`。

## 8. 配置哈希

Lite 对机队配置和 GeoReference 生成 SHA-256。心跳携带机载配置哈希，轨迹证据
携带软件、场地、任务、飞控和场景版本。哈希用于回答“这次结果到底使用了哪套
参数”，不能用文件名代替。

## 9. 修改配置的推荐流程

1. 复制示例或当前配置，明确修改目的。
2. 保持 `schema_version` 不变，避免新增未知字段。
3. 运行配置和测试校验。
4. 只读启动，确认 FCU/P9/相机状态。
5. 记录配置哈希。
6. 仿真回归后再申请实机授权。
7. 实机配置变更必须保留旧文件和回滚方法。
