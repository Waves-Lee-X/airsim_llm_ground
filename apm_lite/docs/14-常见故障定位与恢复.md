# 14 常见故障定位与恢复

## 1. 排障原则

先定位哪一层失败，再决定是否重启。不要一看到“离线”就同时重启飞控、树莓派、
P9、地面站和路由器，否则会丢失根因证据。

推荐顺序：

```text
供电/接线
  -> 串口是否存在和被谁占用
  -> 树莓派 FCU 状态
  -> P9 传输统计
  -> 地面 API
  -> Web
  -> 相机/模型
```

所有实机命令排障都必须拆桨、固定机体并保留 RC 接管。

## 2. 快速状态采集

### 2.1 树莓派

```bash
hostname
hostname -I
date -Is
free -h
df -h /
sudo systemctl status aeromind-apm-lite@3.service --no-pager
sudo systemctl status ed_rtsp.service --no-pager
sudo journalctl -u aeromind-apm-lite@3.service -n 100 --no-pager
sudo fuser -v /dev/ttyAMA0 /dev/ttyAMA1
```

### 2.2 Windows

```powershell
Get-CimInstance Win32_SerialPort |
  Select-Object DeviceID,Name
Get-NetTCPConnection -LocalPort 8000 -State Listen
Invoke-RestMethod http://127.0.0.1:8000/api/status |
  ConvertTo-Json -Depth 10
```

混合模式分别采集，不能只看默认 UAV1：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/status?vehicle_id=1" |
  ConvertTo-Json -Depth 10
Invoke-RestMethod "http://127.0.0.1:8000/api/status?vehicle_id=3" |
  ConvertTo-Json -Depth 10
```

## 3. 地面站打不开

| 检查 | 命令/判断 |
|---|---|
| 8000 是否监听 | `Get-NetTCPConnection -LocalPort 8000 -State Listen` |
| Python 是否启动失败 | 查看启动 PowerShell 窗口最后错误 |
| 虚拟环境是否存在 | `%USERPROFILE%\.aeromind\venv\Scripts\python.exe` |
| 地面密钥是否存在 | `%USERPROFILE%\.aeromind\uav3.env` |
| 端口被其他进程占用 | 核对 PID，或用 `-WebPort 8010` |

不要不核对 PID 就批量结束所有 Python 进程。

## 3.1 混合模式只有一端在线

- 只有实机：检查 SITL `--serial0` 是否为
  `udpclient:<Windows主机地址>:14550`，而不是 WSL `127.0.0.1`；
- 只有仿真：检查 COM3、P9 上电、机载服务和 UAV3 密钥；
- 两端都离线：检查混合地面站启动窗口和 8000/14550 端口；
- 页面切换后仍像上一架：强制刷新浏览器并确认加载 `app.js?v=20260730.8`；
- UAV1 和 UAV3 配成同一机号：启动会直接拒绝，必须保持唯一机号。

实机串口失败不会自动把 UAV1 标为离线；SITL 失败也不能让 UAV3 继承仿真状态。

## 4. P9 在线但 Agent/FCU 间歇离线

重点读取 `/api/status`：

```text
received_frames
duplicate_frames
crc_errors
discarded_bytes
retries
invalid_payloads
session_reset_requests
```

判断方法：

- `crc_errors` 持续增长：波特率不一致、供电/接地、P9 空中链路或串口噪声；
- `discarded_bytes` 增长：其他进程/协议写入同一串口，或两端版本不一致；
- `retries`/`duplicate_frames` 同时增长：反向 ACK 丢失或链路拥塞；
- 帧不增长但 COM3 已打开：检查 P9 配对、机载 `/dev/ttyAMA1` 和 Agent 服务；
- 地面重启后短暂 `session_reset_requests`：正常重握手；持续增长则查时钟和版本。

UAV3 稳定基线是遥测 1 Hz、大帧压缩、周期状态不重传。不要先提高遥测频率。

## 5. FCU 一会在线一会离线

先区分 FCU-UART 和 P9：

1. 树莓派日志是否持续看到 FCU 遥测；
2. `/dev/ttyAMA0` 是否被其他进程占用；
3. ArduPilot TELEM2 波特率是否为 921600；
4. TX/RX 是否交叉、是否共地；
5. 树莓派供电是否压降或热降频；
6. 若树莓派稳定而地面闪烁，回到 P9 统计排查。

检查低压/降频：

```bash
vcgencmd get_throttled
vcgencmd measure_temp
```

## 6. Web 显示“网关超时”

“网关超时”表示地面站没有在期限内收齐结果，不等同于飞控明确拒绝。检查：

- P9 心跳是否仍新鲜；
- 命令是否有应用 `accepted/running` ACK；
- 是否收到对应 MAVLink `COMMAND_ACK`；
- 遥测是否达到物理完成条件；
- P9 是否在返回证据时产生 CRC/重试。

如果飞机状态未知，不要重复发送同一命令。先通过遥测和现场观察确认实际 ARM 状态。

## 7. ARM 被拒绝

按层查看：

| 层 | 常见原因 |
|---|---|
| Web | API/Agent/FCU 离线，控件锁定 |
| 地面门禁 | `arm` 不在心跳白名单 |
| 机载门禁 | 总开关关闭、白名单为空、TTL/认证失败 |
| ArduPilot | pre-arm、RC、EKF、传感器、电池、安全开关等 |
| 物理证据 | ACK 接受但 `armed` 遥测未变 |

保留 `STATUSTEXT` 和 `COMMAND_ACK`。不得关闭 `ARMING_CHECK` 或强制解锁来让演示
“通过”。室内没有 GPS 不一定阻止所有手动模式 ARM，但会阻止需要 GPS 的 GUIDED
导航；必须以实际 pre-arm 文本为准。

## 8. 没有 GPS/位置

室内 GPS Fix 不足是正常现象。`LOCAL_NED`、Home 和 GPS 健康可能为空，因此
TAKEOFF/GOTO/RTL 自动导航门禁会阻断。处理方式：

- 室内只做不依赖位置的只读和无桨台架检查；
- 不伪造 GPS，不关闭 EKF/GPS 预检；
- 到室外等待 3D Fix、HDOP、Home 和 EKF 稳定；
- 先完成静态记录，再进入低空任务。

## 9. 视频离线或延迟高

### 9.1 树莓派

```bash
ls -l /dev/video4
sudo systemctl status ed_rtsp.service --no-pager
sudo journalctl -u ed_rtsp.service -n 100 --no-pager
```

### 9.2 Windows

```powershell
Test-NetConnection 192.168.1.110 -Port 15544
Invoke-RestMethod http://127.0.0.1:8000/api/camera/status |
  ConvertTo-Json -Depth 6
```

设备号变化时先用 `v4l2-ctl --list-devices` 确认，不要猜 `/dev/videoN`。延迟逐渐增长
通常是旧帧积压；固定高延迟则检查编码、WiFi 和 JPEG 请求频率。

## 10. VLM 或 Mission Agent 不可用

检查 `%USERPROFILE%\.aeromind\vlm.env` 是否包含允许的五个变量，然后完全重启地面
进程。读取：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/semantic/status |
  ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:8000/api/agent/status |
  ConvertTo-Json -Depth 5
```

HTTP `409` 通常表示另一个视觉/Agent 请求正在执行；`503` 表示模型或相机未配置；
`502` 表示上游模型返回或网络错误。模型不可用不能影响飞控只读状态和人工控制门禁。

## 11. AirSim 能解锁但不起飞

检查顺序：

1. UE 已进入 Play，AirSim 与 SITL 已交换传感器；
2. `settings.json` 是当前 WSL 重启后生成；
3. 出生点没有碰撞或埋入地面；
4. SITL 收到 GPS/EKF，模式可以进入 GUIDED；
5. 地面站连接的是正确 14550；
6. 查看 ArduCopter 控制台 `STATUSTEXT`；
7. 检查 TAKEOFF 的应用、ACK 和物理证据分别停在哪层。

不要只看 Web 最终“失败”文字，应定位三层证据。

## 12. systemd `203/EXEC`

通常是 shell 脚本没有执行位、CRLF 换行或路径不存在：

```bash
ls -l /opt/aeromind-apm-lite/deploy/raspberry-pi/preflight-onboard.sh
file /opt/aeromind-apm-lite/deploy/raspberry-pi/preflight-onboard.sh
sudo systemctl cat aeromind-apm-lite@3.service
```

安装脚本应以 `0755` 安装预检文件。不要直接从聊天软件复制脚本文本覆盖运行文件。

## 13. 恢复顺序

确认故障层后，只重启对应组件：

```text
视频故障       -> ed_rtsp.service
机载 Agent 故障 -> aeromind-apm-lite@3.service
地面 API 故障   -> Windows 地面站进程
SITL 故障       -> 地面站、SITL、UE 按逆序停止后重新启动
供电/接线故障   -> 断电检查，不在线热插拔飞控 UART
```

恢复后先做 60 秒只读观察，统计值稳定后才能继续下一层测试。
