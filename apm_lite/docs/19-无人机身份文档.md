# 无人机身份文档

## 1. 定位

`VehicleIdentityDocument` 是无人机的版本化数字身份文档，描述相对稳定的身份、能力、
机载具身智能配置和授权边界。实时位置、电量、链路和健康信息仍由 `TwinState` 表达。

身份文档只参与能力发现、任务匹配和授权判断，不发送飞控指令。

## 2. 文档组成

| 对象 | 内容 |
|---|---|
| `IdentityMetadata` | 机号、序列号、平台类型、厂商、固件和文档版本 |
| `CapabilityProfile` | 传感器、载荷、能力、速度、续航、坐标系和工作限制 |
| `EmbodiedAgentProfile` | 机载模型、输入模态、技能、自治等级、决策频率和降级策略 |
| `AuthorizationProfile` | 允许命令、需确认命令、标定、最大高度、最大距离和围栏 |
| `IdentityAttestation` | 签名密钥 ID、算法、文档哈希、签名、有效期和撤销状态 |

机载 `skill_ids` 必须属于身份文档声明的能力集合。`confirmation_required` 必须属于
允许命令集合。身份和能力档案中的 `vehicle_id`、`platform_type` 必须一致。

## 3. 签名和校验

当前版本复用 Lite 已有的每机共享密钥体系，使用 HMAC-SHA256。密钥不得写入身份文档、
配置样例、日志或 Git。

签名覆盖：

- 身份、能力、具身模型和授权信息；
- 签名算法、密钥 ID、签发和到期时间；
- 撤销状态和撤销原因。

`document_hash` 和 `signature` 本身不进入待签名内容。任何受保护字段被修改后，
`verify_integrity()` 或 `verify_signature()` 都会失败。

`verify()` 还会检查到期时间和撤销状态，因此只用于判断文档当前能否使用；已撤销文档仍可
通过签名验证并留在注册表中审计，但不会参加能力查询。

## 4. 注册表行为

`VehicleRegistry.register_document()` 会：

1. 校验文档内容哈希；
2. 在提供验证密钥时校验签名；
3. 从文档生成兼容的 `VehicleProfile`；
4. 保存完整身份文档；
5. 保持原有 `TwinState` 更新和查询接口。

注册表 JSON 同时保存 `profiles`、`states` 和 `documents`。旧版不含 `documents` 的注册表
仍可加载。加载带身份文档的注册表时应提供验证密钥。

## 5. 使用示例

```python
document = VehicleIdentityDocument.create(
    document_id="uav-3-identity-v1",
    identity=identity,
    capabilities=capabilities,
    embodied_agent=embodied_agent,
    authorization=authorization,
    key_id="ground-identity-key-v1",
    secret=secret,
    issued_at_utc=issued_at,
)

registry = VehicleRegistry()
registry.register_document(document, verification_secret=secret)

eligible = registry.query(
    required_capabilities={"search"},
    minimum_energy=0.4,
)
```

## 6. 当前边界

- 当前签名算法是与现有通信认证一致的 HMAC-SHA256，不是公钥证书体系；
- 当前只完成身份文档和注册表，尚未实现机载小模型推理；
- 自治等级只是身份和授权声明，不会自动扩展飞控白名单；
- 模型和技能版本已进入身份文档，但模型文件本体仍需后续纳入制品校验；
- 真机使用前仍须完成密钥分发、轮换和撤销流程的台架验证。
