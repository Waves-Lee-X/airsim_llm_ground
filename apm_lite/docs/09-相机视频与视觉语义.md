# 09 相机视频与视觉语义

## 1. 当前硬件和能力

UAV3 已确认相机是 Intel RealSense D435i，硬件包含 RGB、Depth、左右 IR 和 IMU。
当前 Lite 只接入 Linux V4L2 暴露的 RGB 节点 `/dev/video4`：

```text
424 x 240
15 FPS
H.264 约 800 kbit/s
```

Depth、IR、IMU、深度尺度、相机安装外参和 USB 3 带宽尚未接入。当前系统不能据此
宣称具备未知障碍自主避障。

## 2. “D435 驱动”具体指什么

如果只读取 RGB，Linux V4L2 节点和 FFmpeg 已经够用。如果要读取同步 RGB-D、深度
尺度、双 IR 和 IMU，需要 Intel RealSense `librealsense` 及对应 Python/C++ 接口。
驱动接入不等于避障完成；还需要：

- 标定相机内参和机体外参；
- 处理深度无效值、量程、反光和室外红外干扰；
- 定义数据新鲜度和安全区域；
- 将深度结果接入限速/HOLD 否决层；
- 做断流、遮挡和 CPU/USB 压力测试。

## 3. 实机 RGB 推流链

```text
/dev/video4
  -> FFmpeg V4L2 采集
  -> libx264 ultrafast + zerolatency
  -> RTSP TCP
  -> EasyDarwin :15544/cam
  -> Windows OpenCV VideoCapture
  -> 最新帧缓存
  -> /api/camera/frame
  -> 浏览器和 VLM
```

树莓派入口为 `deploy/raspberry-pi/ed_rtsp.py`，由 `ed_rtsp.service` 管理。当前 FFmpeg
关键低延迟参数：

```text
-rtbufsize 2M
-fflags nobuffer
-preset ultrafast
-tune zerolatency
-bf 0
-g 15
-sc_threshold 0
-flush_packets 1
```

脚本监视 EasyDarwin 和 FFmpeg，采集设备暂时不存在时等待，FFmpeg 异常退出后
2 秒重启。

## 4. OpenCV 在当前系统中的作用

OpenCV 不是飞控，也不是大模型。当前地面站用它完成：

1. 打开 RTSP 流；
2. 持续解码 H.264；
3. 丢弃积压，只保存最新帧；
4. 将最新像素矩阵编码为 JPEG；
5. 同一帧同时提供给 Web 和 VLM。

后续还计划使用 OpenCV HSV/Lab 颜色检测，与 VLM 的箱体颜色结论交叉验证。颜色
算法只提供感知证据，不能直接生成飞控命令。

## 5. 为什么视频会延迟

端到端延迟由多段累加：

```text
相机曝光
+ V4L2 缓冲
+ H.264 编码和 GOP
+ RTSP 服务器
+ WiFi 网络
+ OpenCV 解码缓冲
+ JPEG 编码
+ 浏览器刷新
```

常见原因和处理：

| 原因 | 现象 | 当前处理 |
|---|---|---|
| 播放器按顺序消费旧帧 | 越看越慢 | 后端持续读取并只保存最新帧 |
| B 帧/GOP 太长 | 启动慢、拖尾 | `-bf 0`，GOP 15，zerolatency |
| 分辨率/码率太高 | 树莓派或 WiFi 拥塞 | 当前 424x240、800k |
| Web 并发请求重叠 | 延迟和 CPU 上升 | 前端串行请求，上一帧完成后再取下一帧 |
| RTSP 断开 | 画面冻结 | 帧龄门禁和自动重连 |

真正的延迟验收需要给采集端帧加入可见时间戳，再统计 P50/P95。只看“主观流畅”
不能给出可靠延迟结论。

## 6. AirSim 相机

仿真默认 `front_center` Scene RGB：1280x720、90 度视场。Lite 通过 AirSim RPC
读取压缩 Scene 图像，使用单线程执行器隔离阻塞调用并缓存最新帧。它不模拟 D435
Depth，除非后续明确配置并实现对应桥接。

实机与仿真相机要近似对应，至少需要测量并统一：

- 分辨率和宽高比；
- 水平/垂直视场角；
- 相机相对机体的前后、左右、上下位置；
- roll/pitch/yaw 安装角；
- 图像裁剪和畸变模型。

## 7. VLM 视觉分析

视觉请求流程：

```text
操作员点击“识别当前帧”
  -> 获取最新且未过期 JPEG
  -> Base64 放入 OpenAI 兼容请求
  -> VLM 返回 JSON
  -> 代码提取/规范化字段
  -> Web 同时显示结构化结果和模型原文
```

当前结构化结果包含：

- 场景和可见对象；
- 箱体标签/编号、颜色、颜色所在面；
- `found`、置信度和视觉证据；
- 风险等级、建议和任务关联。

非法 JSON 会降级为可见文本并带 `format_warning`。视觉接口始终返回
`flight_command_generated=false`。

## 8. 视觉结果如何进入 Mission Agent

Mission Agent 每轮会读取最近一次结构化视觉结果，但模型仍只能建议六种原子动作。
“发现红色箱体”不会自动形成 GOTO、搜索或降落命令。未来寻物闭环必须增加多帧
证据、世界模型、目标重分配和独立任务 Schema。

## 9. 实机视频调试

树莓派检查设备和服务：

```bash
ls -l /dev/video*
v4l2-ctl --list-devices
v4l2-ctl --device /dev/video4 --list-formats-ext
sudo systemctl status ed_rtsp.service --no-pager
sudo journalctl -u ed_rtsp.service -n 100 --no-pager
```

Windows 检查 RTSP 地址和地面桥：

```powershell
Test-NetConnection 192.168.1.110 -Port 15544
Invoke-RestMethod http://127.0.0.1:8000/api/camera/status |
  ConvertTo-Json -Depth 5
```

相机状态重点查看：`stream_available`、`frame_sequence`、`frame_age_s`、
`source_fps` 和 `last_error`。

## 10. 视觉语义调试

1. 先确认 Web 画面是新鲜帧。
2. 检查 `/api/semantic/status` 的模型和 `vision_available`。
3. 使用画面中确实存在、容易核对的目标。
4. 对照结构化结果和模型原文。
5. 不清楚时让模型返回 `null`，不要逼迫猜测。
6. 保存原图、提示词、模型名、时间和原始返回后再评估准确率。

当前尚未实现长期视觉证据存档和多帧一致性，这是下一阶段 M4 的主要工作。

继续阅读：[10 Mission Agent 设计与调试](10-Mission-Agent设计与调试.md)。

## 11. 确定性颜色交叉验证与视觉证据（M4）

自 2026-07-31 起，视觉链路增加三层确定性保护，VLM 仍不拥有飞行权限：

### 11.1 OpenCV 颜色检测（ColorDetector）

- 对当前相机帧解码后转为 HSV，按内置调色板（红、绿、蓝、黄、橙、紫、粉、白、黑、灰）做掩码和轮廓分析。
- 输出最大色块的颜色、覆盖率、边框、置信度和时间戳；画面中无有效色块时返回空。
- 纯色/无信息画面（覆盖率超过 95%）会被忽略，避免把背景误报为目标色。
- 未安装 OpenCV 时返回“检测不可用”，不影响 VLM 与飞行链路。

### 11.2 交叉验证（cross_validate_color）

- 每次“识别当前帧”后自动把 VLM 声称的颜色与 OpenCV 检测结果比对：
  - `agreed`：VLM 颜色与 OpenCV 一致；
  - `disagreed`：两者不一致（VLM 需要复核）；
  - `vlm_color_missing`：VLM 未给出可归一化颜色；
  - `unavailable`：OpenCV 不可用或无有效色块。
- 支持中英文颜色归一化（红色/red/红/蓝/blue 等）。

### 11.3 多帧共识（VisionConsensusTracker）

- 保留最近 5 次分析，按颜色/编号/面/标签投票；同一颜色达到 3 票（窗口 5）才标记 `confirmed`。
- Web 显示“观察中 2/5”或“已确认 · red (3/5)”。

### 11.4 视觉证据持久化（VisionEvidenceStore）

- 每次识别自动存档到 `~/.aeromind/visual-evidence/{evidence_id}.json`，帧快照保存为 `{evidence_id}.frame`。
- 记录包含：帧 SHA-256、VLM 模型/原文/结构化结果、OpenCV 交叉验证、多帧共识、无人机编号与时间。
- 证据按 UUID 不可变：同 ID 只能写入相同哈希，帧字节必须与 SHA-256 一致。
- API：
  - `POST /api/vision/crosscheck`：仅做 OpenCV 交叉验证，不调用模型；
  - `GET /api/vision/evidence`：证据摘要列表；
  - `GET /api/vision/evidence/{id}`：证据详情；
  - `GET /api/vision/evidence/{id}/frame`：帧快照。
- 相关 Schema 见 `schemas/protocol-v1.schema.json` 的 `vision_analysis_evidence` 与 `color_detection`。
