# 02 总体架构与数据流

## 1. 系统定位

AeroMind-APM Lite 是一套面向 ArduPilot、树莓派 4B、P9 Radio 和 Web 地面站的
非 ROS 飞行与虚实交互系统。它不依赖 ROS 2、MAVROS、PX4 Offboard 或
`px4_msgs`。旧 AeroMind ROS/PX4 工程继续作为算法原型，Lite 单独承担真机适配、
安全门禁和轻量部署。

系统当前完成了单机 AirSim/ArduCopter SITL、UAV3 实机基础链路、RGB 视频、VLM
识别、Mission Agent、场地坐标转换和轨迹证据。四机编队、未知障碍自主绕行、箱体
五面搜索和视觉精确降落仍属于后续阶段。

## 2. 组件和职责

| 组件 | 运行位置 | 核心职责 | 明确不负责 |
|---|---|---|---|
| Web 前端 | Windows 浏览器 | 状态显示、人工操作、视频、语义结果、证据展示 | 不直接访问串口，不保存飞控密钥 |
| FastAPI 地面站 | Windows Python | P9 会话、命令门禁、Web API、视频桥、VLM/LLM、证据 | 不直接拥有实机 FCU 串口 |
| `SerialGroundServer` | Windows 地面站进程 | 独占地面 P9 串口，按机号复用会话 | 不传视频 |
| `OnboardAgent` | 树莓派 | P9 认证、白名单、命令调度、遥测和 ACK | 不运行 Web、ROS 或大模型 |
| `ApmLink` | 树莓派；SITL 模式下位于地面进程内 | MAVLink 收发、命令匹配、物理完成判断 | 不接受未经 Agent 门禁的网络命令 |
| ArduCopter | CUAV V5+ 或 SITL | 姿态、位置估计、飞控模式、电机控制和 failsafe | 不理解 Lite JSON 协议 |
| 相机推流服务 | 树莓派 | D435i RGB 采集和 RTSP 推流 | 不承载飞行控制 |
| AirSim/UE | Windows | 虚拟场景、传感器和可视化 | 不作为真机安全控制器 |

源码入口对应关系：

```text
src/aeromind_apm_lite/common/          协议、配置、坐标和证据模型
src/aeromind_apm_lite/ground/          地面会话、串口服务器和仿真工具
src/aeromind_apm_lite/ground/browser/  FastAPI、Web 网关、相机、语义和 Agent
src/aeromind_apm_lite/onboard/         树莓派 Agent、MAVLink 和导航状态机
web/                                   无框架 HTML/CSS/JavaScript 地面站
configs/                               仿真、实机和场地配置
deploy/                                Windows、树莓派和 systemd 部署入口
```

## 3. 三条物理数据链

### 3.1 控制和遥测链

```text
浏览器
  <-> HTTP/WebSocket
Windows FastAPI 地面站
  <-> COM3 @ 57600
地面 P9 Radio
  <-> P9 无线透明串口
机载 P9 Radio
  <-> /dev/ttyAMA1 @ 57600
树莓派 OnboardAgent
  <-> /dev/ttyAMA0 @ 921600 MAVLink
CUAV V5+ / ArduCopter
```

P9 只提供字节透明传输。Lite 自己在字节流上增加帧头、CRC32、ACK/重传、重复抑制、
会话、HMAC、TTL、机号隔离和业务 Schema。

### 3.2 视频和模型链

```text
D435i RGB
  -> FFmpeg H.264
  -> EasyDarwin RTSP
  -> WiFi/IP
  -> Windows OpenCV 最新帧缓存
  -> Web JPEG / VLM 请求
```

视频不经过 P9。OpenCV 在当前版本中负责解码 RTSP、保留最新帧和 JPEG 编码，避免
浏览器或 VLM 读取积压的旧视频帧。Depth、IR 和 IMU 尚未进入控制安全层。

### 3.3 虚拟环境链

```text
UE 4.27 + AirSim 1.8.1
  <-> AirSim UDP 9002/9003
ArduCopter SITL
  -> MAVLink UDP 14550
Lite SITL 地面站
  -> AirSim RPC 41451 读取 RGB
```

AirSim RPC 只用于图像和虚拟状态，不承担飞控命令。飞行动作仍经过
`OnboardAgent -> ApmLink -> MAVLink -> ArduCopter`。

## 4. 三种运行模式

| 模式 | FCU | Agent 链路 | 命令性质 | 使用场景 |
|---|---|---|---|---|
| `demo` | 内存模拟 | 进程内 | 不产生 MAVLink | UI、API、Agent 演示 |
| `sitl` | ArduCopter SITL UDP | 进程内 WebSocket | 真实 MAVLink，作用于仿真 | AirSim 联调和自动验收 |
| `real_serial` | 树莓派连接真实 V5+ | P9 串口 | 真实 MAVLink，受双层白名单限制 | 无桨台架和后续外场 |

三个模式复用 Web API、业务消息和证据模型，但不能混淆验收结论。DEMO 成功只证明
界面和软件流程；SITL 成功不自动授权真机；真机命令必须单独通过外场与安全评审。

## 5. 一条命令如何执行

以 Web 中的 ARM 为例：

```text
1. 操作员点击“解锁”并二次确认
2. FastAPI 检查运行模式、机号、连接状态和当前白名单
3. GroundServer 生成带 session/sequence/TTL 的 VehicleCommand
4. 使用每机密钥做 HMAC-SHA256 签名
5. P9 串口层可靠发送并等待传输 ACK
6. OnboardAgent 校验签名、会话、序号、TTL、机号和标定 ID
7. OnboardAgent 再检查总开关和命令白名单
8. ApmLink 发送 MAVLink COMMAND_LONG
9. 记录 COMMAND_ACK
10. 继续等待新鲜遥测确认 armed=true
11. MissionAck 返回地面站，Web 显示三层证据
```

三层证据分别是：

| 层级 | 回答的问题 |
|---|---|
| 应用接收 | Agent 是否接受了这条合法、未过期的命令 |
| MAVLink ACK | ArduCopter 是否对对应 `MAV_CMD` 返回结果 |
| 物理完成 | 新鲜 FCU 遥测是否达到目标状态并保持规定时间 |

`COMMAND_ACK=ACCEPTED` 不能单独算完成。例如 ARM 必须最终看到 `armed=true`，LAND
必须看到落地状态和高度/速度条件满足。

## 6. “以虚控实”和“以实应虚”

Lite 中这两个概念不是把 AirSim 遥控器直接接到真机，而是共享任务、坐标和证据：

### 6.1 以虚控实

```text
同一任务参数
  -> AirSim/SITL 先执行
  -> 生成 predicted 轨迹和安全结果
  -> 通过场地标定转换真实目标
  -> 人工确认和真机安全门禁
  -> 真机执行
```

当前软件已完成单机任务状态机、坐标转换和证据格式，但真机 GOTO 尚未授权。

### 6.2 以实应虚

```text
真机 GPS/状态/视觉结果
  -> 转换到场地 map 坐标
  -> 更新 AirSim 镜像实体或语义世界
  -> 显示 observed 轨迹
  -> 与 planned/predicted 比较
```

当前已经支持 GPS CSV 离线回放和误差报告；真机轨迹实时驱动 AirSim 镜像仍待外场
联调。

## 7. 安全边界

- 当前 UAV3 实机仅允许 ARM/DISARM，且只能无桨台架测试。
- GOTO、TAKEOFF、HOLD、LAND、RTL 的代码存在，不等于实机已授权。
- P9 断开、心跳过期、FCU 离线或白名单为空时，Web 必须锁定写操作。
- VLM/LLM 只生成语义结果或工具草案，不能绕过确定性门禁。
- RGB 在线不代表具备深度避障；没有 Depth 安全层时只能演示已知地图规划。
- `draft` 场地标定只允许仿真预览，不能作为真机坐标依据。
