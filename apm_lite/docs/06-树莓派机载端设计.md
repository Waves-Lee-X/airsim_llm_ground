# 06 树莓派机载端设计

## 1. 机载端为什么要有新程序

旧 `swarmXian_group_fix.py` 同时占用 FCU 和 P9 串口，并使用旧消息处理方式。新 Web
地面站采用 Lite v1 的认证、会话、TTL、白名单和三层证据，因此树莓派必须运行
对应的 `aeromind_apm_lite.onboard.runtime`。新旧程序不能同时占用 UART。

树莓派不运行 ROS、MAVROS、AirSim、Web、OpenCV 地面桥或大模型。它只运行轻量
飞行代理和独立视频推流服务。

## 2. 进程结构

```text
systemd: aeromind-apm-lite@3.service
  -> preflight-onboard.sh
  -> python -m aeromind_apm_lite.onboard.runtime
       -> PymavlinkTransport(/dev/ttyAMA0)
       -> ApmLink
       -> ReliableSerialLink(/dev/ttyAMA1)
       -> OnboardAgent

systemd: ed_rtsp.service
  -> ed_rtsp.py
       -> EasyDarwin
       -> FFmpeg(/dev/video4)
```

两个服务相互独立：飞行代理退出不应由视频服务接管 UART；视频退出也不应让飞行
代理失去 FCU/P9 状态。

## 3. 启动顺序

`run_onboard()` 的实际顺序：

1. 读取机队 YAML 并选择 `vehicle_id`。
2. 从指定环境变量加载至少 32 字节共享密钥。
3. 打开 `/dev/ttyAMA0`，等待 V5+ HEARTBEAT 和固件身份。
4. 创建 `ApmLink`，启动 MAVLink 接收和伴随计算机心跳。
5. 打开 `/dev/ttyAMA1`，创建 Lite P9 可靠帧链。
6. 与地面站执行双向挑战认证。
7. 每秒发送 Heartbeat，当前每秒发送一次 Telemetry。
8. 接收命令并执行签名、会话、TTL、机号、总开关和白名单检查。
9. 将命令交给 `ApmLink`，持续返回 ACK 和物理完成证据。

FCU 还没就绪时不会假装 Agent 正常；P9 暂时断开时 Agent 会按 1 秒间隔重连。

## 4. 文件和安装位置

开发机需要上传的最小项目内容：

```text
src/aeromind_apm_lite/
configs/
deploy/raspberry-pi/
deploy/systemd/aeromind-apm-lite@.service
pyproject.toml
setup.py
setup.cfg
```

安装后：

```text
/opt/aeromind-apm-lite/                 程序和虚拟环境
/etc/aeromind-apm-lite/fleet.yaml       当前机队配置
/etc/aeromind-apm-lite/uav3.env         本机密钥和命令开关
/etc/systemd/system/aeromind-apm-lite@.service
```

不需要上传 `web/`、测试、AirSim 配置、Windows 启动脚本或模型密钥。

## 5. systemd 预检

服务启动前执行 `preflight-onboard.sh`：

- `/dev/ttyAMA0` 和 `/dev/ttyAMA1` 必须存在；
- 服务用户必须可读写两路 UART；
- 旧 `swarmXian*.py` 进程不能存在；
- `/etc/aeromind-apm-lite/fleet.yaml` 必须可读。

服务使用专用 `aeromind` 用户和 `dialout` 组，并启用只读系统目录、无提权、私有
临时目录等 systemd 隔离。两个 shell 文件必须是 LF 换行并具有执行权限，否则会
出现 `203/EXEC`。

## 6. MAVLink 层

`PymavlinkTransport` 负责串口字节和 MAVLink 消息；`ApmLink` 负责更高层语义：

- 等待 HEARTBEAT，确认 autopilot 和固件；
- 维护 ARM、模式、LOCAL_NED、GPS、Home、EKF、电池等遥测快照；
- 将 Lite 原子动作映射到 ArduPilot 命令；
- 匹配 `COMMAND_ACK`，处理 ACK 没有事务 ID 的限制；
- 对需要连续设定点的动作按 20 Hz 发送；
- 用新鲜遥测判断物理完成；
- 超时、拒绝或链路停止时生成明确失败证据。

不要让 MAVProxy、旧脚本或第二个 pymavlink 进程同时打开 `/dev/ttyAMA0`。

## 7. 命令安全门禁

机载端默认：

```text
command_output_enabled=false
allowed_commands=[]
```

只有同时传入 `--enable-command-output` 和一个或多个 `--allow-command` 才能到达
FCU。当前 systemd 仅允许：

```text
--allow-command=arm
--allow-command=disarm
```

Agent 对每条命令还会检查：

- HMAC 是否有效；
- 会话、机号和递增序号是否匹配；
- 消息是否超过 TTL；
- 坐标消息的标定 ID 是否一致；
- 命令是否在白名单；
- 同一命令是否已经处理。

拒绝结果通过 `MissionAck` 返回，不能靠 Web 页面文字代替。

## 8. 遥测和带宽

UAV3 当前 systemd 使用 `--telemetry-hz 1.0`，Heartbeat 也是 1 Hz。周期状态使用
“最新值覆盖”，不做串口重传；命令和证据可靠重传。该设置是 P9 57600 实测后的
稳定基线，不应在没有压力测试时直接恢复到 2 Hz 或更高。

Telemetry 包含：

- ARM 和模式；
- LOCAL_NED 位置与速度；
- 姿态和电池；
- FCU link、GPS Fix/HDOP、pre-arm、EKF；
- 坐标 frame 和 calibration ID。

## 9. 日常检查命令

```bash
hostname
hostname -I
sudo systemctl status aeromind-apm-lite@3.service --no-pager
sudo journalctl -u aeromind-apm-lite@3.service -n 100 --no-pager
sudo systemctl status ed_rtsp.service --no-pager
sudo fuser -v /dev/ttyAMA0 /dev/ttyAMA1
ps aux | grep -E 'aeromind|swarmXian|ed_rtsp' | grep -v grep
```

日志正常启动标志：

```text
FCU ready: vehicle=3 ...
P9 agent started: ... command_output=enabled allowlist=arm,disarm
```

串口占用者必须只有当前 Lite Python 进程。

## 10. 安全更新流程

1. 拆桨并固定机体。
2. 备份 `/etc/aeromind-apm-lite` 和当前安装包版本。
3. 先上传到用户目录，不直接覆盖运行目录。
4. 运行 Python 导入检查和 `preflight-onboard.sh`。
5. 使用安装脚本复制并保持权限。
6. 重启服务，先观察只读日志。
7. 地面站运行 60 秒只读闭环。
8. 只有现场确认后才执行白名单内 ARM/DISARM。

Mission Agent、Web 样式或地面 VLM 的修改通常不需要更新树莓派；协议、业务 Schema、
机载门禁或 MAVLink 实现变化时必须同步两端版本。

## 11. 资源边界

树莓派 4B 可以运行当前 Python Agent 和低码率视频推流，但不应同时运行 ROS 2、
MAVROS、SLAM、VLM 和多个视频编码器。后续接入 D435 Depth 时必须重新测量 CPU、
温度、USB 带宽、内存和 30 分钟稳定性。
